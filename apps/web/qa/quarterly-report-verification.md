# D09 immutable quarterly report UI

Date: 2026-10-19. Scope: frontend candidate on the isolated dot cloud worktree; API 0.60 contract coordinated with the report storage/API implementation. No WeCom changes, external publication, production action, or customer acceptance is claimed.

## Implemented

- Current `remote_test` padmin and `inspection_quarterly_reports:read` gate the route, menu, and reads. Creation additionally requires report write and source-collection read capabilities.
- User explicitly identifies and fully verifies one immutable source collection. POST binds the collection ID, expected source document and manifest SHA256, explicit year/quarter, label, `expected_version: 0`, and all six nullable configuration keys. No latest-source lookup, inferred quarter, platform timezone fallback, or approved-configuration claim.
- Separate metadata list/receipt and `FROZEN_INPUT_OUTPUT` detail. Detail verifies frozen document SHA256, report input fingerprint, source document/manifest, each source/template/worksheet fingerprint, candidate/selected bindings, row/item counts, findings and pending reasons. Detail drills into captured source content without current-head reads. History is rendered from saved output.
- Unknown writes retain one fixed body/idempotency key. Reads cannot resolve an unknown POST. A denied replay remains unknown. Concurrent retry, replacement writes and in-app navigation/context transitions are guarded. Scope changes abort and discard stale private reads. Dirty input and beforeunload guards are included.
- No edit, execution, publication, attachment grant, tenant-population denominator, or coverage-rate action is exposed. `REQUEST_DRAFT_NOT_APPROVED`, DRAFT and unresolved rules remain explicit.
