# MOP平台开发顺序与任务拆解

本文件把工作拆成可以领取、实施和检查的任务。任务负责人由项目组填写，不预填人员承诺；执行顺序不重新定义合同工期。合同的第1周启动、第4周开发完成、第8周上线及两个月开发上线要求继续保留，实际排程须结合已过时间、人员投入和客户材料到位情况维护。

## 一 开发状态和暂停边界

每项任务使用五个状态：`TODO` 未开始、`DOING` 开发中、`BLOCKED` 被明确问题阻塞、`VERIFYING` 待验证、`DONE` 已有完成证据。本套文档发布时所有生产开发任务均为 `TODO`，依赖未满足的任务标记 `BLOCKED`；文档写出不等于代码完成。

|可执行类别|现在允许完成的内容|不得提前完成的内容|
|---|---|---|
|独立设计与本地开发|页面和通用组件、接口定义、逻辑数据模型、权限检查接口、模拟适配器、纯计算测试夹具|把模拟调用记录成真实建单、送达、备份或远程执行。|
|带决策插槽的开发|参数结构、版本和审批记录、未配置状态、策略接口、待确认错误分支|填入未确认公式、默认阈值、保留期、生产连接地址。|
|有外部前置条件的开发|对接字段清单、调用时序、超时补偿、回读协议及验证计划|未经确认的数据库隔离物理方案、未获许可组件正式集成、真实堡垒机建连。|

“待确认”要阻塞具体策略发布或执行入口，不让一个未确定参数拖住整个页面开发。也不能仅隐藏入口便把合同内功能标记完成。

## 二 工程划分

以下是本版工程设计，可由开发组采用；它不是已存在的源码目录，也不宣称组件已通过客户评审。先沿用上一版Vue 3与TypeScript、Java与Spring Boot的技术方向做接口设计；精确版本、基础框架及第三方许可按05核验，物理数据库按04确认。

```text
mop-platform/
  apps/web/                 管理端和客户H5，共用API客户端
  server/api/               HTTP入口、身份、授权、参数校验
  server/domain/            租户、资产、事件、工单、报告领域规则
  server/worker/            任务租约、补偿、导出、报告生成
  server/adapters/          监控、CMDB、ITSM、消息、堡垒机
  server/persistence/       仓储接口；数据库确认后实现
  contracts/               OpenAPI、事件协议、配置定义
  fixtures/                无真实客户信息的测试数据
  tests/                   隔离、契约、状态、故障注入、验收
  deploy/                  环境样例、迁移、健康检查、恢复步骤
  docs/                    需求、开发、测试、运维、交付记录
```

首期采用模块化应用与单独Worker，共用明确的业务服务；不先拆成十套独立微服务。身份、审计、幂等、任务、附件和指标服务是共享底座。成熟组件用于通用能力，合同特有的客户确认、六层隔离、服务档位和报告口径由业务层实现。

## 三 第一批任务

### D00 固化资料和差异

依赖：已具备现有合同和原型。交付：07需求追踪、04确认清单、资料哈希。

1. 读取合同附件一全部128项，保留M编号、原文及可选标记，不以原型页数推定需求数。
2. 对照31个HTML和核心JS，把“有页面”“有演示交互”“有真实服务”分别记录。
3. 把原型中的固定月份、静态租户、假成功、演示审批人归入迁移任务；演示用户名不导入生产。
4. 将旧C01至C13与新Q编号对应，客户所有结论只在04记录，其他文档引用编号。
5. 本次文档核验通过后形成V0.1；之后输入变化生成新版本和影响条目，不覆盖证据。

完成条件：128个需求编号唯一，31个页面均有归属；没有未经来源支持的“已确认”“已完成”。

### D01 建立工程和本地运行入口

依赖：D00；生产依赖安装及版本需先完成05中的适用许可检查。

1. 在独立生产工程目录建工程，保留静态原型为参照。配置版本锁、格式检查、编码和换行规范。
2. 创建Web、API和Worker启动入口，暴露存活检查与就绪检查；数据库或关键依赖不可用时就绪检查失败。
3. 添加 `local_fixture`、`integration`、`production` 环境，开发样例配置不含真实秘密。生产环境禁止启用fixture适配器。
4. 建统一API客户端，支持请求追踪、会话到期、统一错误提示和异步任务轮询。
5. CI先执行编译、静态检查、契约校验和领域测试；物理库方案未定前不生成伪装为通用SQL的迁移文件。
6. 写出开发启动、停止、清理测试数据、定位日志的命令；每条命令由第二个环境复现后登记。

完成条件：干净环境可按说明启动本地空壳，fixture与生产环境有硬隔离，接口错误结构一致。此时不标记业务功能完成。

### D02 提取可复用页面组件

依赖：D01；可与D03并行。对应原型：shell.js、app.css、enterprise.css及31页。

1. 提取页头、导航、权限菜单、面包屑、租户上下文、列表筛选、分页、确认弹窗、附件、时间线和状态标签。
2. 在成熟表格与表单组件上封装薄层，不自建排序、分页、校验、日期选择、上传和图表引擎。
3. 统一五种数据状态：加载中、正常、空数据、失败、规则待确认；额外标出最后采样时间和数据过期。
4. 将角色、当前租户和权限从服务端会话读取；客户不出现租户切换，导航不渲染未授权项。
5. 把原型 `DATA` / `localStorage` 读取迁移到开发fixture客户端；生产页面只调用API。
6. 本版建议先用1440宽桌面和390宽移动视口检查主流程，并按合同要求覆盖Edge、Chrome、Firefox及360浏览器；表格可横向滚动，关键动作在移动端可达。

完成条件：同一列表能用fixture展示成功、未知、为空和报错四类数据；切换页面或刷新不丢筛选，绝不保留跨租户缓存。

### D03 建立身份与租户上下文

依赖：D01。本地接口与领域规则可先开发，身份源实际接入及附加岗位权限等待04。

1. 定义User、Membership、Role、Capability、TenantContext，角色码沿用viewer、tadmin、msp、padmin。
2. 请求依次执行会话验证、成员关系查询、租户范围校验、动作权限和对象范围校验；未知对象与无权对象统一404。
3. 平台“全部租户”只返回服务端确认的授权集合；聚合接口单独实现，不让普通仓储接受 `tenant=all`。
4. 创建 `TenantRepository` 接口，所有租户对象查改方法要求tenant_id和id；系统级表显式标记，不自动放行。
5. 将权限版本放入缓存键、任务消息和会话；撤权后下次请求及后台任务执行前重新检查。
6. 设计A/B双租户数据和跨租户ID调用用例。数据库层隔离策略未定时先验证服务端行为，数据库验收保持未执行。

完成条件：API层越权被拒绝、拒绝有审计；客户端改租户ID不能扩权。数据库隔离未通过前不能对外放行生产数据。

### D04 实现配置和确认机制

依赖：D03。配置字段以04和 `contracts/config-baseline.json` 为依据。

1. 将配置分为合同固定、客户待确认、技术建议、环境输入四类，保存来源、作用域、单位、版本和生效时间。
2. 为待确认项保存 `value=null`、`decision_status=pending`；禁止把空值解释成0、false或系统默认。
3. 建草稿、待审核、已批准、已生效、已失效状态。一般配置审核权限与客户书面确认记录分别保存，不以管理员点保存代替客户确认。
4. 实现“读取有效配置”服务，按作用域匹配；任何关键项缺失返回 `CONFIG_PENDING`，并附受影响Q编号。
5. 规则发布前检查依赖、类型、范围和生效日期，生成差异；更新后的规则只应用于新对象，存量工单采用创建时快照。
6. 提供配置列表、待确认筛选、结论附件引用和审计历史。无结论时只允许保存草稿，不允许正式发布相关策略。

完成条件：未确认阈值无法发布，缺补偿口径无法出应付金额，修改新档位不改变已有工单截止时间。

## 四 业务链路任务

以下顺序细节与逐页步骤共同执行，不能仅凭下表结束任务。

|任务|先后步骤|依赖和可先做边界|交付及退出条件|
|---|---|---|---|
|D05 租户与资产|租户创建事务 → operation → 配额预留 → 资产草稿 → 导入预览 → 五步接入 → 首值回读|D03/D04；数据库与监控接入未定时实现仓储及适配器接口|单条与500行导入共用校验；逐行回执；对象均有租户和来源版本。|
|D06 监控事件底座|适配器收事件 → 耐久inbox → 去重 → 关联资产 → 归并 → 降噪原因 → outbox → 断点补偿|D05；阈值/恢复条件只定义策略接口，未定值不能执行|重复、乱序、恢复先到、断网补扫不生成重复工单；未知数据不写正常。|
|D07 工单闭环|报障 → 本地受理 → ITSM建单意图 → 回读 → 接单/转派 → 工时 → 提交解决 → 客户确认/拒绝/重开|D03/D04/D06；ITSM权威源和映射未定时只开发内部动作接口及fixture|工程师不能代确认；转派不改SLA；超时不冒充外部成功。|
|D08 SLA与指标|区间并集工具 → 日历版本 → 档位快照 → 响应/恢复时钟 → 未知/维护处理 → 指标明细|D07；“次日”、未知区间、补偿口径阻塞对应计算策略发布|边界用例逐条对账；统计可下钻；0分母返回null。|
|D09 通知与门户|身份绑定 → H5报障上传 → 工单查看 → 客户确认 → 统一发送计划 → 通道适配 → 回执与重试|D07；通道账号/矩阵/外部身份依赖04|accepted与delivered分开；重复点击仅一次业务动作；客户端不能指定确认人。|
|D10 备份与变更|计划 → 凭据引用 → 授权SSH读取 → 规范化 → 加密版本 → diff → 变更单匹配 → 失败计数|D05/D07；设备指令、保留策略、真实凭据待确认|同设备并发互斥；重试与整次运行分别计数，建单触发按Q22结论；客户不能下载正文。|
|D11 远程会话|契约和授权模型 → 路线确认 → 能力验证 → 审批 → 单次票据 → 录屏建连 → 结束回填|合同要求路线确认后排期；确认前仅梳理接口和验证方案|真实读写双人审批、录屏故障停止写会话、并发原子控制通过专项。|
|D12 报告与经营|指标快照 → 报告模板 → 版本审核 → H5/PDF同源 → 发布 → 通道通知 → 首次阅读|D08/D09；评分、成本、年度复盘范围待确认项保持空|改源数据不改变旧报告；月费/成本无输入不造毛利；最多3条下月建议等合同版式落实。|
|D13 运营与治理|模板版本 → 灰度与回退 → Proxy健康 → 容量输入 → 平台监控 → 审计检索|D05/D06；产品和环境真实能力验证在集成环境执行|估算有输入和公式；容量实测记录分开；模板跨租户回归。|
|D14 联调与交付|真实适配器 → 业务回归 → 隔离安全 → 性能 → 灾备 → 资料 → 上线演练|本期功能及适用Q结论到位；按06逐步执行|所有结果有版本/环境/证据；无阻断缺陷；客户确认上线窗口。|

## 五 单个接口怎样开发

以“工单转派”为固定工作模板，其余业务动作按相同工程步骤执行，各模块的特有规则另见02。

1. **核对来源**：读取M5转派要求、02工单章节和04权限问题，明确谁能转派、目标工程师范围、SLA不重置。
2. **写契约**：在OpenAPI补全 `POST /tickets/{id}/transfer`，输入assignee_id、reason_code、reason_detail、retain_previous_as_collaborator、expected_version；原因码来自已确认字典，保留是否协办选项。要求Idempotency-Key；禁止tenant_id、actor_id、sla_due_at等可伪造字段。
3. **写领域命令**：从TenantContext取主体；查询本租户工单和目标成员；校验状态、资格和版本。目标权限未确定时动作关闭，不能先赋全权限。
4. **写持久化事务**：保存原截止时间；CAS更新负责人、version；追加动作、审计和outbox。若任一环节失败，整笔业务事务回滚。
5. **写异步适配**：外部系统为权威源时返回202；Worker按关联ID调用、回读、落实际结果。超时保持待核实，绝不在浏览器直接改为已转派。
6. **接页面**：加载允许的目标人员；提交中禁止重复点；成功后重新取详情和时间线；409提示刷新，不用旧表单覆盖新数据。
7. **写测试**：正常转派、无权转派、目标跨租户、重复请求、同键异内容、并发抢派、外部超时各一例；逐个比较转派前后的响应和恢复截止时间。
8. **存证并更新**：记录接口响应、数据库变更、审计、外部回读及截图；07填实现提交号与用例结果，完成条件全满足后转DONE。

## 六 客户结论到位后怎样继续

1. 客户在04某Q项填写结论、确认人、日期和书面证据；开发负责人检查是否回答全部子问题。
2. 将该Q项关联的参数从null补为确定值，保留原版本；若客户结论改变合同边界，先补相应变更依据。
3. 更新受影响的接口、规则、数据库迁移和用例；列出已有对象是否需迁移及迁移方式，不默改历史快照。
4. 在测试环境验证方案，记录版本和结果；通过后把该Q项从“待确认”改为“已确认待实现/已落实”，两个状态不能合并。
5. 只解除相应任务阻塞；例如ITSM已确认不代表通知通道和远程堡垒机也已确认。
