# 模块开发步骤与页面交互

版本：V0.1，2026-09-30。用途：将合同与现有静态原型转换为可以领取、实现、联调和验收的开发任务。本文件为开发设计，不表示后端已经实现或客户已经批准待定事项。

依据：`tmp/contract_full.txt` 中附件一 M1—M10 共128项；`tmp/project_docs/formal/design_content.md` 的 D01—D28；`zabbix-msp-prototype/` 现存31个HTML、10个核心JS及3份原型说明。合同正文及附件是范围依据，原型是交互依据；冲突处按已明确合同修正，有歧义处进入确认汇总。

## 1. 使用方法与实施约束

本文件的任务顺序是依赖顺序。先做公共底座，再按 M2→M3→M4→M5→M8→M6/M7→M9/M10 接通业务链；M1页面可同步开发，但真实指标必须使用统一指标服务。不要等全部确认事项解决后才开工。

每项任务采用三个完成层次：①数据结构、校验、契约和模拟适配器可执行；②真实系统联调有回执与失败证据；③满足合同验收。只有第三层可以记为合同功能完成。涉及客户未确认规则的接口保留字段与策略入口，规则值设为 `null`，配置登记使用 `decision_status=pending`；页面显示“待客户确认”，依赖该值的发布、计费、执行或结论动作返回 `CONFIG_PENDING`。工单等对象自己的工作流状态与配置登记状态分别存储。

本次统一技术约定：Vue 3 + TypeScript 前端与 Java/Spring Boot 后端为沿用旧设计的候选；数据库产品、监控/堡垒机产品及版本以确认记录和组件基线为准。以下API均以 `/api/v1` 为前缀，是本次拟定接口，不是已存在服务。首批接口的字段以 [核心OpenAPI契约](contracts/core-api.openapi.json) 为准；本文件列出的其余模块路径为后续接口草案，实施时先补OpenAPI与角色DTO再编码。

|通用事项|开发时落实的方法|
|---|---|
|API信封|同步200：`{data,trace_id}`；异步202：`{data:{operation_id,status},trace_id}`；错误：`{error:{code,message,details},trace_id}`。列表在data内返回items及分页信息。|
|异步动作|提交业务意图、operation和outbox后返回202；前端轮询 `GET /api/v1/operations/{id}`。只有回读目标系统成功才显示已生效；不可点击后立即显示成功。|
|幂等与并发|创建、导入、发送、执行等意图写操作携带 `Idempotency-Key`；更新与状态动作携带 `expected_version`。相同键不同载荷、旧版本更新返回409并保留用户输入。|
|租户与角色|服务端从会话和成员关系推导允许范围；对象按tenant_id+id联合验证。“全部租户”是已授权集合。URL、localStorage、标签和前端角色选择器不提供授权。|
|时间与字段|服务端时间为准；UTC存储，按合同固定 `Asia/Shanghai` 展示。sampled_at表示样本时间，generated_at表示结果生成时间；未知值用null，不替换为0、100%或正常。|
|复用|表格、筛选、分页、表单、抽屉、上传、日期、提示统一封装；图表、监控模板、SSH、diff、报告渲染和审批对接优先使用获准成熟组件。保留可替换适配层，不另造监控引擎、终端协议栈或富文本编辑器。|
|异常页面|所有页面均具备加载、空数据、无权限、请求失败、数据过期五态；错误显示可读原因与trace_id。切租户取消旧请求，迟到响应不可覆盖新租户数据。|
|文件与导出|上传先验证类型、内容、大小及对象归属；导出通过受权任务，下载地址15分钟有效。下载时重新校验当前账号授权，撤权后旧链接不可继续取数。|
|权限呈现|菜单与按钮在请求数据前过滤；后端独立鉴权。客户DTO不包含内部字段，不能只依靠CSS隐藏。|

每个模块提交物统一包含：迁移脚本/逻辑模型、OpenAPI增量、业务服务及适配器、前端页与共享组件、真实数据联调记录、针对关键分支的用例、合同ID到证据的对应。模拟数据只在显式开发/测试模式加载，不进入生产构建或验收统计。

## 3. M1 首页、工作台与全局导航

来源：`dashboard.html`、`index.html`、`shell.js`、`charts.js`；合同 M1-1—11，联动 M5-12、M10-12；旧设计 D04—D06、D15。可先开发固定布局、租户联动、查询契约与统一指标调用。

1. [ ] **M1-D01 固定页面结构。** 将Dashboard与MyTasks拆为独立路由；Dashboard依次保留6KPI、趋势、服务健康、故障时间线、最近事件、待处理工单、Top5；不做拖拽、显隐保存或个性化布局。抽出TenantSelector、TimeRange、Freshness、StateBadge、MetricCard、DataTable。
2. [ ] **M1-D02 聚合读取。** 后端提供 `GET /api/v1/dashboard?from=&to=`，调用资产、事件、工单、指标、通知的读服务，返回每卡value、unit、sample_count、drilldown、sampled_at、generated_at。原始与归并趋势返回相同时间桶；不从页面DOM反算数据。
3. [ ] **M1-D03 指标边界。** 在线率把未知单列；当前问题剔除抑制事件后分5级；本月窗口从当月1日到当前；待办含超SLA数；MTTA按近24小时；通知送达只计delivered，低于95%标黄。服务可用率聚合调用统一指标服务，不平均百分数冒充合同口径。
4. [ ] **M1-D04 下钻与搜索。** 每卡携带同一授权租户集合、时间、严重级/状态跳转。`GET /api/v1/search?q=` 按资产/事件/工单分组，服务端先限定范围再搜索。通知铃铛从 `GET /api/v1/notifications/inbox` 取得，不枚举其他租户。
5. [ ] **M1-D05 刷新。** 监控页默认30秒轮询；页面卸载/切租户取消请求；连续失败保留最后数据并标“数据过期”。手动刷新更新请求时间，样本仍旧时显示真实样本年龄。按钮重复点不启动多个定时器。
6. [ ] **M1-D06 待办聚合。** `GET /api/v1/tasks?status=` 汇总本人待处理工单、授权审批和服务经理待办，返回task_type、target_id、due_at、owner_id、tenant_id；办理跳转原业务详情，不在待办页另维护一份状态。该辅助入口范围随页面入口确认记录，不削减合同总览。
7. [ ] **M1-D07 验证。** 对照同一固定数据集逐卡与明细核对；断采1分钟内未知+1正常-1；零样本显示未知/—；验证30秒自动刷新、切租户无旧数据闪现、四角色版式与按钮权限、深链越权统一拒绝。

字段与状态：筛选from<to，范围与取点数使用全局配置；KPI允许null，单位与统计版本必返；loading→ready/empty/stale/error为呈现状态，不修改业务状态。权限：按当前成员关系读取，客户只收客户字段；工作台只收自己的或被授权处理的任务。

冻结点：Q05未知区间及汇总口径、Q06采样与失联检测、Q24入口与客户文案；客户结论留空，相关达标结论与正式发布等待确认，其余结构、数据质量标记和下钻可先完成。

## 4. M2 租户、身份、联系人与审计

来源：`login.html`、`tenants.html`、`members.html`、`audit.html`、`shell.js`；合同 M2-1—14；旧设计 D03—D05、D17、D19、D23。可先完成逻辑模型、鉴权服务、权限校验、异步租户创建和审计接口；数据库实际隔离机制待路线确定。

1. [ ] **M2-D01 建立身份对象。** 建user、identity_binding、tenant、membership、role_permission、resource_grant、auth_version模型。将登录身份与业务角色分离；OIDC subject+issuer唯一绑定，平台本地密码使用安全框架的自适应哈希，客户端不持有可随意改动的角色权威值。
2. [ ] **M2-D02 实现登录与上下文。** `POST /api/v1/auth/login`、OIDC服务端回调、`GET /api/v1/session`、`POST /api/v1/session/tenant-context`、退出接口；复核成员启用状态/授权版本。客户无“全部租户”；MSP只枚举指派集合；非法对象ID统一404，未登录401，动作无权403。
3. [ ] **M2-D03 异步建租户。** `POST /api/v1/tenants` 校验名称全局唯一、管理员邮箱、套餐档位、隔离模式、配额、保留策略、身份源、ITSM配置。隔离三模式为shared共享监控实例、dedicated独享监控实例、independent独立部署；独立部署包括控制层和监控层置于客户环境，不能用独享监控池冒充。实际必需配置未完成返回CONFIG_PENDING且不准备资源；可保留未提交表单。配置齐备后事务写PROVISIONING与operation；Worker按步骤创建主机组、受限身份、配额、邀请并回读；完成才ACTIVE，失败标明step/error并允许只重试未完成步骤。
4. [ ] **M2-D04 配额与档位。** `PATCH /api/v1/tenants/{id}/quotas` 原子校验使用量；主机/Item/NVPS/Worker并发可改，曲线点数/每页上限只读。`POST /api/v1/tenants/{id}/tier-changes` 追加原档/新档、生效时间、原因与审批人；契约设备数、月费、周期独立字段，现有工单快照不可重算。
5. [ ] **M2-D05 成员管理。** `GET/POST /api/v1/members` 及撤权/MFA重置/重邀动作；邀请校验授权角色范围，非平台管理员不得邀请MSP或平台管理员。撤权递增授权版本，失效受影响会话/缓存，异步任务执行前也重新检查；不能只从成员列表删一行。
6. [ ] **M2-D06 联系人维护。** 在租户详情新增联系人Tab和导入入口；`GET/POST /api/v1/tenants/{id}/contacts` 与更新/停用。字段为姓名、角色集合、手机、邮箱、企微userid、偏好、启用状态；邮箱/手机格式服务端校验。删除、停用或取消最后一名启用决策人均需同事务检查并阻断，避免并发操作删除全部决策人。

11. [ ] **M2-D11 验证。** 对hostid、itemid、eventid、下载、缓存、伪造任务tenant、受限监控账号执行7类双租户用例；名称重复/配额并发/撤权下一请求/最后决策人/邀请越级/审计追加与篡改检测各留证。仅有前端按钮隐藏不能通过。

状态：租户PROVISIONING→ACTIVE，失败另记PROVISION_FAILED；退役/停用与operation分开。成员INVITED→ACTIVE→REVOKED，重邀不恢复过期授权。档位变更PENDING→EFFECTIVE，生效历史不可修改。字段约束：月费定点非负，配额非负整数，Worker默认2；不把原型默认配额当客户的正式配额。

## 5. M3 资产台账、五步接入与依赖

1. [ ] **M3-D01 建资产事实。** asset保存名称、类型、IP/域名、品牌/型号/序列号、站点/位置/负责人/业务、采购/维保/超期日期、采集方式、备注、来源；另表保存监控映射、凭据引用、模板版本、依赖与同步操作。资产可用性不与配置同步状态共用字段。

6. [ ] **M3-D06 接入第2步。** 校验Proxy/站点/资源池绑定；选择采集方式与credential_ref；提交网络检查operation，返回目标端口、TLS/认证、可达结果和检测时间。无Proxy/凭据失败显示原因并阻断推进，不能用setTimeout模拟通过。

8. [ ] **M3-D08 导入预检。** 用标准15列模板：设备名称、设备类型、IP或域名、品牌、型号、序列号、站点、位置、负责人、所属业务、采购日期、维保到期日、超期服役日期、采集方式、备注；备注必填。上传/映射→预览校验→确认导入三个交互步骤，完成后展示结果面板。`POST /api/v1/assets/imports` 传file_id、column_mapping、dry_run=true，支持.xlsx/.csv、≤500行；返回预检operation及preview_hash。
9. [ ] **M3-D09 导入执行。** 预检返回每行原值、规范值、错误/警告、修正建议；名称/IP/类型/必填错误阻止该行，非法日期或非本租户负责人置空并警告，品牌无映射只提供可用性并提示。再次 `POST /api/v1/assets/imports` 传dry_run=false及preview_hash；哈希绑定文件、列映射、租户与配额预留版本，正式提交重新校验数据库冲突与配额，变化要求重新预检，按tenant+名称+IP防重。返回成功/失败统计与错误回执.xlsx，500行≤60秒；审计保存文件hash。
10. [ ] **M3-D10 依赖与维保。** `POST /api/v1/assets/{id}/dependencies` 保存上游/下游、类型、抑制范围；禁止自指、跨租户和有向环。维保/超期每日扫描生成提醒；到期日期为空显示未配置，不自动认定过期。依赖图是抑制数据源，独立于美化拓扑的节点坐标。
11. [ ] **M3-D11 退役、迁池与导出。** 停用/退役异步停止采集与告警，回读后改变生命周期，保留历史事件/报表映射。迁池保留asset_id、新旧binding生效区间与旧池只读历史；导出通过 `POST /api/v1/exports` 继承当前筛选/时间，字段白名单不含凭据。
12. [ ] **M3-D12 验证。** 50行含3类错误数据全部正确定位；500行性能与重复导入；两并发导入不穿透配额；首值失败不进入服务；监控调用超时先回读再重试；依赖A→B→C后C→A拒绝；退役后历史仍可下钻；客户不能获取配置正文/凭据。

字段与状态：asset.availability=正常/有问题/未知/维护中/已停用；sync_state=已生效/同步中/同步失败/待接入/配置漂移；生命周期与这两者独立。日期无效按导入警告规则，不把空日期写成1970年。模板/凭据/Proxy均为受权对象ID，非可随便填的名称。

权限：msp/padmin管理授权资产；tadmin的资料维护范围由权限矩阵决定；客户读专用DTO。异常：CMDB离线保留同步异常与最后版本；首值超时留草稿；部分导入失败返回逐行结果；IP变更需重新验证与审计。

冻结点：Q20首批设备与OID、Q19 CMDB接口与主数据责任、Q06采样与失联检测、Q31导入导出；表结构、校验、模拟接入与导入先做，未经证实的厂商指标显示“不支持/待映射”，不伪造采样。

[ ] **M5-D02 建单模型与接口。** `POST /api/v1/tickets` 接source、incident_id/asset_id、可选title、description、priority、category、impact_scope、contact_name、contact_phone、urgency、attachment_ids；impact_scope为company/partial_area/individual，分别表示全公司/部分区域/个人，不把部分区域改成部门。联系人绑定关系由服务端另行核验，客户未填title可按类别与设备生成。业务事件到工单的绑定唯一；手工登记与客户报障进入同一服务但保留不同来源。附件失败不取消已经受理的工单，允许补传。
3. [ ] **M5-D03 自动建单规则。** 在告警策略新增“建单规则”面板，配置级别、rule_code/标签/维护排除、5分钟聚合、30分钟工单去重窗口、标题/描述模板、优先级、资产/队列/负责人映射和退避。默认灾难/严重自动建单并绕过等待；其他级别仅已配置时建单。重试最多5次，间隔完整配置待Q07，失败进隔离队列可人工补建；超时先按业务关联号查远端，避免重复建单。
4. [ ] **M5-D04 创建时冻结SLA。** 同事务保存tier_snapshot、calendar_version、priority、response_due_at、recovery_due_at及口径版本。参数来自配置表：P1基础30分钟/4小时、标准10分钟/2小时、进阶10分钟/1.5小时；P2分别60分钟/8小时、30分钟/4小时、20分钟/3小时；P3分别4小时/次日、2小时/次日、1小时/4小时。基础仅工作时间累计，标准/进阶7×24；Q08未确认的“次日”不擅设24小时。
5. [ ] **M5-D05 接单、转派、评论。** `POST /api/v1/tickets/{id}/accept` 首次响应只写一次；transfer验证新负责人授权，使用reason_code、reason_detail、retain_previous_as_collaborator记录转派原因及保留原负责人协办选项，保留SLA截止时间/创建时间；comments区分内部/客户可见、支持受控附件。受理、转派、升级、处置与工时写时间线及审计；客户DTO不含内部姓名与升级转派细节。
6. [ ] **M5-D06 解决与客户确认。** resolve要求处置说明≥20字，进入PENDING_CUSTOMER并记录recover_at、confirm_due_at；基础/标准48小时，进阶24小时。confirm仅报障人/决策人可调用，确认→CLOSED+customer_confirm，冻结客户账号、时间和工单快照hash；“未解决”说明必填，恢复处理中并reopen_count+1、通知值守。实际REOPENED枚举映射待Q07，不能混进监控状态。
7. [ ] **M5-D07 自动关闭与重开。** 服务端在确认到期前12小时发一次提醒；到期自动关闭，action=auto_close、close_mode=timeout_auto。关闭后72小时内 `POST /api/v1/tickets/{id}/reopen` 必填原因、可附附件；超过窗口给新建工单入口，原记录保留。重开沿用原截止与超时事实，累计≥2次通知服务经理；Q27待确认的MTTR展示不回写监控恢复时间。
8. [ ] **M5-D08 时钟Worker。** 每30秒扫描下一到期节点，按工单+周期+时钟+阈值唯一锁定动作；50%负责人、80%加值班长、100%执行确认后的升级链。暂停浏览器、重启Worker不影响计时；重复消费不能重复通知。工作日历使用版本化有效时间区间逐段累计，跨夜、节假日、月边界单测固定时钟。
9. [ ] **M5-D09 值班与交接。** `GET /api/v1/oncall/dashboard`、`GET/POST /api/v1/oncall/schedules`、`POST /api/v1/oncall/handovers`；按严重级与服务端due_at排序，30秒刷新。交接提交接班人/备注并在服务端冻结未确认、处理中、待复核三计数，不能把前端旧计数当事实。电话两次未接通触发升级与短信，使用provider回执而非HTTP成功推断。
10. [ ] **M5-D10 工时同期建设。** `POST/PATCH /api/v1/tickets/{id}/worklogs[/{worklog_id}]` 必有开始、结束、远程/现场/巡检/通勤、工单、执行人；结束不得早于开始、工单/执行人同范围。工程师只能改本人记录，服务经理可查看团队；修改追加历史。未填使用配置默认工时并标source=default，未确认默认值则阻止输出正式毛利，不静默记0。
11. [ ] **M5-D11 SLA报表。** `GET /api/v1/sla/services` 与 `/{id}/intervals` 使用统一指标服务；六KPI、11列、日趋势、故障/维护/未知区间和原事件下钻。区间先裁剪再求并集，维护排除要审批引用，跨月按边界拆分。零样本或未定未知口径不给达标结论。快照与导出引用同一metric_version。
12. [ ] **M5-D12 未达标和补偿。** P1—P3且未获准排除为适用集合；响应与恢复均≤截止才达标，逐单下钻四个时间点。Q26补偿公式未定时compensation_amount=null并注明待确认；已确认的10%/20%/30%比例可入配置但不直接变成应付金额。
13. [ ] **M5-D13 验证。** 覆盖告警→建单→受理→转派→工时→解决→客户确认，以及拒绝/超时/重开；客户确认<5秒，报障≤10秒按平台受理与外部完成分开取证。20个日历边界用例、修改档位后3张在途单截止不变、ITSM超时/旧回调/重复消息/双人同时操作409、重开与自动关单竞争、权限穿透均验证。

## 8. M6 配置备份、变更报备与恢复演练

来源：`backups.html`、`contract-pages.js`、`contract-model.js`；合同 M6-1—7、M4-17；旧设计 D12、D19、D23。可先实现计划/运行/版本/diff/报备/演练模型和页面；真实设备读取依赖SSH授权与厂商命令。

1. [ ] **M6-D01 计划配置。** `GET/POST /api/v1/backups/plans` 保存租户、目标设备、时区、计划、credential_ref、enabled、版本；默认每日02:00，单次失败重试2次且间隔10分钟。多个调度实例通过租约只生成一次run，按租户+设备加执行锁。
2. [ ] **M6-D02 执行入口。** `POST /api/v1/backups/runs` 返回operation；Worker再次验证设备授权、网络/凭据及SSH主机指纹，以厂商适配的只读命令取得running-config。命令/读超时给出分类错误；不能因为设备在资产列表中就允许任意SSH执行。
3. [ ] **M6-D03 保存与加密。** 保存原始加密对象、规范化副本hash、key_id、字节数、采集时间、设备/厂商/解析版本；AES-256按旧设计，具体密钥产品Q28确认。仅剔除已批准动态噪声行，不能把真实配置变化当时间戳噪声删除。
4. [ ] **M6-D04 差异比较。** `GET /api/v1/backups/versions`、`GET /api/v1/backups/diffs?before=&after=`；先校验两版本属于同设备同租户，使用成熟文本diff组件显示增删，敏感行脱敏。相邻规范化内容相同不造新差异；每6小时差异检测与备份读取复用采集/存储链路。
5. [ ] **M6-D05 变更报备联动。** `GET/POST /api/v1/change-notices` 保存工单、资产集合、窗口、事由和审批记录；diff事件匹配同设备、同时间且已批准的报备，无有效报备生成P3工单。过期、撤销、不同设备的报备不匹配；Q22审批流程未定时不能自动判为已报备。
6. [ ] **M6-D06 失败建单。** attempt保存每次尝试结果，run保存重试后的最终结果，分别维护连续失败计数；合同“连续两次失败”到底按尝试还是最终运行计数，按Q22确认 `backup.failure_count_semantics`，目前保持null。明确的两次失败阈值和10分钟内P3建单要求先做成策略参数和测试夹具；计数口径未定时不能启用正式自动建单。已确认后仅按该口径判定、唯一关联防重复，恢复计数的重置规则同步固化，原尝试与故障历史保留。
7. [ ] **M6-D07 版本与客户视图。** 内部版提供历史、diff、受控下载、计划和手动执行；客户版仅设备、最近备份时间、是否正常。客户直调版本正文/diff/下载/执行接口必须拒绝。最近30份热版本+至少12个月归档为待Q10批准的保留实现，不擅自按30份总上限删除。
8. [ ] **M6-D08 演练。** `GET/POST /api/v1/backups/drills` 保存设备、所选历史版本、执行人、开始/结束、操作指引、结果和附件；距上次演练>90天提示。页面提供恢复参考和人工执行记录，本期不添加配置自动下发回滚按钮。
9. [ ] **M6-D09 验证。** 真实设备每日/手动备份、主机指纹变更拒绝、读取失败分类、diff噪声/真实变更、无报备P3、Q22口径下连续两次失败仅建一单、3个月前版本可检索、加密明文不可见、客户穿透拒绝和演练证据完整；确认前分别验证attempt/run计数且正式建单返回CONFIG_PENDING。

状态：run=QUEUED→RUNNING→RETRY_WAIT→SUCCEEDED/FAILED；version只有持久化校验完成才AVAILABLE；diff关联独立事件，不等于审批通过。字段：计划时间必须有效，资产集合不得为空；result/error_code/attempt_count/started_at/finished_at必备，last_success_at与last_attempt_at分开。

权限：计划/读取/历史内容限获授权内部人员；客户只概况；恢复演练与下载留独立审计。异常：任务结果未知先核查对象与run日志，不能用“网络断开”假定设备未执行；对象保存失败不标备份成功；归档恢复耗时显示operation。

冻结点：Q10保留、Q20厂商命令、Q22报备审批/匹配、Q28密钥与附件、Q21设备网络；先实现模拟执行和状态面板，设备命令白名单及删除策略未定不得上线。

## 9. M7 远程会话、设备授权、录屏与可选自动化

来源：`remote.html`、`automation.html`、`audit.html`、`contract-model.js`、`contract-pages.js`；合同 M7-0—9；旧设计 D13、D14、D19、D23。本期主线是交互式远程会话；Runbook自动化M7-1—4按可选增强处理。先开发授权/申请/审批/审计模型与堡垒机接口契约，具体建连路线等Q01。

1. [ ] **M7-D01 设备授权清单。** 新增授权Tab；`GET/POST /api/v1/remote/grants` 保存工程师、设备/设备组、readonly/readwrite、有效期、临时工单和审批来源。授权到期自动失效、提前7天提醒；目标变化需要新授权。列表只显示当前操作者可管理范围。
2. [ ] **M7-D02 会话申请。** `POST /api/v1/remote/requests` 必填ticket_id、asset_id、access_level、duration、reason；验证同租户、设备可用与有效授权。默认60分钟；原型未关联工单的申请表必须补字段。readonly的免审批例外与通用“无审批不能连接”冲突由Q01确认；不能自行让所有只读请求绕过批准。
3. [ ] **M7-D03 审批。** `POST /api/v1/remote/requests/{id}/approvals` 只接decision、comment、expected_version，approver取服务端当前登录用户。readwrite两名互异且非申请人；重复审批不加计数、拒绝终止申请、等待>30分钟作废。移除原型可选择其他姓名审批的控件。
4. [ ] **M7-D04 建连复核。** connect动作再次核查工单/资产租户、设备授权、审批未过期、级别未改、目标未改、录屏可用，并原子预留单工程师最多2个并发。通过后签发短时单次票据交堡垒机；失败释放预留。浏览器永不接设备密码。
5. [ ] **M7-D05 会话生命周期。** 建连中展示实际operation，成功收到网关session_id才ACTIVE；心跳检查空闲、授权撤销、时限，结束/断线均回收并发。延时申请有记录，不能改客户端计时器延长服务端会话。所有旁路网关入口也校验审批票据绑定。
6. [ ] **M7-D06 终端复用。** 通过已批准堡垒机的Web终端/网关SDK集成；不自研SSH/Telnet协议或在业务API拼接任意shell。只读账号的写入限制由堡垒机/设备权限真正执行，不依赖前端命令文本拦截。
7. [ ] **M7-D07 录屏与命令。** readwrite强制录屏，readonly按已确认租户配置。保存录像对象hash、key_id、起止、命令时间索引；强制录屏不可用拒绝建连，中途丢失终止可写能力并记录缺口。命令日志含序号、时间、脱敏文本、结果摘要、退出码、耗时；高危命令按厂商语法识别并阻断/二次确认，不能只复用原型正则。
8. [ ] **M7-D08 审计访问与回填。** `GET /api/v1/remote/sessions/{id}` 返回获准记录；录像调阅申请/授权/下载独立审计。关闭会话回填工单时长、结果、命令数与证据引用；成功会话才作为远程处置率的候选事实，仍需判断是否升级现场。客户录像需申请本租户调阅，不能直接获得对象地址。
9. [ ] **M7-D09 Runbook增强占位。** `automation.html` 保留目录、参数Schema、风险等级、审批、执行步骤/输出设计；生产入口feature flag默认关闭。Q11书面纳入后再实现 `POST /api/v1/automation/runs`：资产核验→前检→审批→锁定→执行→观察→留证/补偿；L1输出≤256KB、L2单机预授权、L3双审批且维护窗内≤10目标/24小时冷却。每租户默认并发2；这些增强不得替代交互会话主线验收。
10. [ ] **M7-D10 失败与补偿。** 网关请求超时查询会话是否已创建；不盲目重复连接。命令中断/会话丢失先核查设备实际状态再给出补偿建议，不显示“自动回滚成功”。录像转冷失败保留原对象并告警；Q10总留存未定前禁止自动清理历史。
11. [ ] **M7-D11 验证。** 缺授权、过期、自审、同人双审、目标更换、权限升级、票据复用、第三并发、录屏故障、到期/撤权中断均穿透测试；对真实会话抽查录屏/命令完整、审计导出、工单回填；用两独立登录身份审批，不用单个管理员模拟两人。

状态：REQUESTED→APPROVED→CONNECTING→ACTIVE→ENDED；拒绝REJECTED、过期EXPIRED、撤回CANCELLED、故障FAILED；审批记录追加。字段：访问级别枚举、事由非空、关联工单/设备、服务端申请时间与过期时间、申请人不可由请求伪造；secret_ref不得进入客户响应。

冻结点：Q01路线/只读审批、Q03许可证、Q09审批岗位、Q10录像留存、Q18授权/通道费用、Q20协议与命令、Q21网络资源、Q28密钥；缺决定时可以交付申请审批模拟联调与适配测试，不能建立真实受管设备会话或宣称通过远程验收。

4. [ ] **KB-D04 列表与安全导入。** 保留全部/收藏/我的/服务台、分类/作者/标签、更新/浏览/点赞排序；成熟Markdown编辑/渲染工具做白名单清理。原型.md/.txt/单篇.json、1MB导入可作候选上限；上传内容只作资料，需核对再发布，不执行正文代码、脚本或嵌入指令。
5. [ ] **KB-D05 检索先行。** `POST /api/v1/knowledge/search` 先按权限选已发布文章再检索，返回article_id、version、段落引用和摘录。删除/撤权后立即从索引与缓存撤销；无依据明确未找到资料。服务端分页和索引能力优先复用既有存储/搜索组件，未经规模验证不引入新中间件。
6. [ ] **KB-D06 AI按第二道开关。** 知识库获准不自动表示外部AI获准。单独确认模型/部署/数据出域/费用/留存与正确性评估后，再增加有引用回答；只读检索上下文，工具执行权限隔离，不持设备凭据、不执行推荐命令。回答无法对应版本化引用时显示不足，不补造事实。
7. [ ] **KB-D07 历史与验证。** 会话按user+tenant独立保存；收藏/点赞user+article唯一。测试草稿泄漏、共享文章、跨租户索引/缓存、XSS/恶意导入、版本并发、引用撤回、空检索和历史切换；以示例文章或原型已有浏览器测试通过不能代替生产AI质量验收。

扩展冻结点：Q11范围/阶段，Q03许可，Q09权限，Q10内容和对话保留，Q18费用，Q24文案，Q28敏感信息处理。未获得结论时正式菜单可隐藏或只显示获准的设计预览，不将“AI已上线”写入交付。

配置落地顺序：

1. [ ] **SET-D15 建配置目录。** 每个config_key定义类型、单位、作用域、允许覆盖层、校验、合同来源、敏感标记、是否待确认、影响模块。系统默认→租户覆盖→工单/报告快照的优先级显式写入Schema；未知值不回退为演示默认。
2. [ ] **SET-D16 分离草稿和生效版本。** `GET /api/v1/settings/catalog`、`GET /api/v1/settings/effective`、`POST /api/v1/settings/drafts`、校验与发布动作。只返回掩码/secret_ref；不可从设置API取回明文。每条待定项有question_id与空的decision_ref。
3. [ ] **SET-D17 保存和影响预览。** 编辑提交expected_version，服务端检查类型/范围、引用资源和跨配置冲突；预览受影响租户/模板/路由，不在保存草稿时立即下发。API对缺客户结论的发布返回 `CONFIG_PENDING` 并包含Q编号，配置登记保持 `decision_status=pending`。
4. [ ] **SET-D18 发布和回读。** 需要审批的配置引用有效审批/客户确认记录；发布生成新不可变版本并发出outbox。运行服务按版本读取，异步下发逐对象回读；未同步对象保持旧版本与错误，不写“全局已生效”。
5. [ ] **SET-D19 快照与回退。** 生效时间后新工单/新报告取新版本；历史快照与在途SLA沿用旧版。回退新建版本引用旧内容，记录原因与执行结果；不删除中间版本。验证改配置后实际行为变化且历史不变。

配置保存者、审批者、发布者各为独立权限，不因拥有全局设置页面就能绕过双人审批。具体谁担任这些职责见Q09；审批/许可/外部账号材料的结论空白需要客户填写，不把“推荐”转换成“已批准”。
