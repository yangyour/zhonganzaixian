# MOP平台数据模型与接口实施约定

本文件细化上一版D17至D23，供后端、前端和适配器并行实现。字段、接口路径、事务和错误结构属于本版技术设计；合同固定规则引用M编号，客户选择集中在04。数据库物理类型、RLS策略和部署版本在Q02、Q03确认后才生成正式迁移，不以一套SQL声称同时适配MySQL和PostgreSQL。

## 一 请求如何流转

```text
Web或企业微信H5
  → API会话校验 → 成员和租户授权 → 参数及业务状态检查
  → 领域服务 → 仓储事务（事实、动作、审计、outbox）
  → 202受理与operation_id
Worker领取outbox → 再校验授权和配置版本 → 调用适配器
  → 查询外部事实 → 写回结果 → 推送通知或推进报告
前端查询operation和详情 → 显示真实生效结果
```

同步本地读写可返回200；外部系统的调用、导入、备份、报告和执行类任务返回202。API进程重启不能丢失已受理动作，所以受理前必须持久化，不能只放内存队列。

## 二 通用字段与数据归属

|字段|逻辑类型|是否为空|写入来源及约束|
|---|---|---|---|
|id|不可预测的UUID字符串|否|服务端生成；36字符映射是本版技术建议。|
|tenant_id|租户ID|租户表否|来自可信TenantContext，禁止直接采纳表单值；平台表须单独标记。|
|created_at / updated_at|UTC时刻，毫秒精度|否|服务端；JSON按RFC3339输出，展示时区按合同为Asia/Shanghai。|
|version|非负64位整数|否|创建为1；更新CAS成功后加1；客户端提交expected_version。|
|created_by / updated_by|用户或系统主体ID|否|从会话或工作负载身份获取，不允许请求体指定。|
|source / source_version|来源代码/版本|依对象定义|区分人工、CMDB、监控、客户报障、适配器和fixture。|
|trace_id|请求关联标识|否|串联API、任务、适配器和审计，不包含个人信息。|

时间差用整数毫秒，金额用定点数并带币种；禁止浮点累计结算。比例逻辑值为0至1，页面转百分数，避免API把0.995与99.5混用。未知数据为null，并带 `unknown_reason`，不是0。列表默认排序使用时间和ID两列保证稳定性；游标包含筛选摘要与权限范围，不能跨租户复用。

依据附件三“物理主键、逻辑外键与逻辑唯一性”的约束，正式方案须记录采用的约束方式。以下联合关系是必须保证的业务不变量；若物理外键未采用，应在同一事务中校验并通过并发测试证明，不可只在页面检查。

## 三 逻辑表与关键约束

### 身份 租户和资产

|表及关键字段|唯一性和关联|实现要点|
|---|---|---|
|user：id、identity_source、subject、status|身份源+subject唯一|本地密码仅自适应哈希，外部身份不保存密码。|
|tenant：id、name、status、pool_id、auth_version|租户名称全平台唯一|PROVISIONING/ACTIVE/FAILED/SUSPENDED为技术生命周期，与合同业务状态映射单独维护。|
|tenant_membership：tenant_id、user_id、role_code、scope、status|租户+用户唯一|撤权同时增加权限版本；同名用户不能替代身份ID。|
|tenant_contact：tenant_id、user_id、contact_type、channel_ref|联系人必须归属租户|报障人、决策人身份与一般viewer不同，确认工单需再次校验。|
|service_tier_history：tenant_id、tier、effective_at、config_version|同一生效区间不可冲突|档位变更追加历史；已建工单快照不重算。|
|site：tenant_id、id、name、proxy_ref|租户+站点标识唯一|站点所属租户不可通过普通编辑跨租户更换。|
|asset：tenant_id、id、name、ip、type、site_id、source、retired_at|租户+名称唯一；IP冲突按Q31|IP、站点、凭据引用校验归属；退役不删除历史事件及报告。|
|monitor_object_map：tenant_id、asset_id、pool_id、hostid、itemid|监控池+对象类型+外部ID唯一|hostid不能脱离监控池解释；先查映射再调用受限身份。|
|asset_dependency：tenant_id、parent_id、child_id、type、scope|关系唯一；两端同租户|在事务保护下检测自环和多边环路；并发插入不得绕过。|
|credential_ref：tenant_id、site_id、secret_ref、key_version|关联目标必须同租户|只存引用和脱敏元数据；真实秘密从甲方批准密钥服务读取。|

建议索引：`asset(tenant_id,retired_at,type,id)`、`tenant_membership(user_id,status,tenant_id)`、`monitor_object_map(pool_id,object_type,external_id)`。按已确认查询计划验证索引，不能把“每列建索引”当容量方案。

### 事件 工单和通知

|表及关键字段|唯一性和关联|实现要点|
|---|---|---|
|raw_event：tenant_id、pool_id、source_event_id、phase、occurred_at、received_at、payload_ref|池+源事件ID+阶段唯一|原始事实追加；occurred_at保留源时间，接收时间不能冒充发生时间。|
|incident：tenant_id、asset_id、fingerprint、monitor_state、disposition_state、rule_version|按已确认窗口归并|PROBLEM/RECOVERED与处置状态独立；待复核映射见Q29。|
|incident_event：tenant_id、incident_id、raw_event_id|绑定关系唯一|所有关系写入检查双方租户。|
|ticket：tenant_id、id、source、incident_id、external_id、state、sync_state、priority、assignee_id|有效事件绑定按规则唯一；外部编号含系统命名空间|人工报障允许无incident_id；数据库对null唯一语义单独处理。|
|ticket_sla：tenant_id、ticket_id、tier_snapshot、calendar_version、response_due_at、recover_due_at、responded_at、recovered_at|租户+工单唯一|创建时冻结；转派保持截止；重开口径保留Q27。|
|ticket_action：tenant_id、ticket_id、action、actor_id、reason、before、after、request_key|关联幂等记录|动作追加，不能把最后状态覆盖掉历史。|
|customer_confirmation：tenant_id、ticket_id、customer_id、decision、confirmed_at、evidence_hash|同一有效确认动作唯一|客户主体由会话确定，保存所见解决版本。|
|worklog：tenant_id、ticket_id、engineer_id、started_at、ended_at、category、source|关联工单和成员同租户|结束不早于开始；更正留版本；默认工时明确source。|
|notification_delivery：tenant_id、business_key、phase、channel、recipient_ref、status、delivered_at|业务键+阶段+通道+收件人唯一|同一内容重试不新建业务通知；有可信送达证据才delivered。|
|notification_attempt：tenant_id、delivery_id、attempt_no、provider_request_id、result、receipt、next_retry_at|delivery+attempt_no唯一|每次尝试追加；accepted/unknown/failed不可算送达成功。|

工单状态至少分开三列：内部业务状态、外部状态原值、同步状态。Q07未确认时不固定外部枚举映射；可以先实现动作命令及验证，fixture明确是演示。

### 任务 备份 远程和报告

|表及关键字段|约束和用途|
|---|---|
|idempotency_record：tenant_id、actor_id、route、key、payload_hash、response_ref、expires_at|作用域+key唯一；同键异内容409；过期策略按配置，运行任务的去重记录不能提前清理。|
|operation：tenant_id、id、kind、status、step、progress、error、result_ref|PENDING/RUNNING/SUCCEEDED/FAILED/CANCELLED；终态需实际结果，不由前端填写。|
|outbox：tenant_id、message_id、topic、payload、created_at、next_at|与业务意图同事务；成功提交后由Worker投递。|
|inbox：tenant_id、source、message_id、payload_hash、processed_at|来源+message_id去重；相同ID不同载荷转冲突检查。|
|job_lease：tenant_id、job_id、owner、lease_until、fencing_token|租约接管后旧Worker不能再次提交；写回校验token与版本。|
|backup_run / backup_version|保留attempt失败数和整次run最终结果两种记录；“连续两次失败”触发口径按Q22确认，未定不发布自动建单策略。版本记录object_key、hash、key_id、规范化规则版本。|
|config_diff / change_notice|关联前后版本；有效报备必须覆盖设备、窗口并已批准。|
|device_grant / remote_request / approval|工单、设备、访问级别、申请人、有效期绑定；审批人互异且不等于申请人。|
|remote_session / recording / command_log|票据一次消费；并发占用与状态原子一致；命令序列、录屏索引及原始时间可关联。|
|metric_snapshot|tenant_id、period、metric_version、payload、source_manifest_hash；冻结后不可修改。|
|report_version / report_read|snapshot_id、template_version、status、artifact_hash；首次阅读记录只写一次，发布后修订生成新版本。|
|inspection / risk_item|评分版本、输入证据、人工备注、状态及处置引用；Q23未确认不生成正式评分。|
|config_revision / decision_record|配置键、作用域、类型、value、status、生效时间、Q编号与客户证据；审批和执行各留状态。|
|audit_log|租户、主体、动作、对象、结果、trace_id、序号、前序哈希与本条哈希；只追加，至少3年。|

审计哈希链的外部链头须另存受保护位置，否则有数据库管理权限的人可能重写整条链。普通应用账号禁止改删审计。消息与日志中不写凭据、未脱敏配置正文或完整录屏内容。

## 四 数据库隔离如何实现

Q02未结论前，两种方案都只能是候选，不预选客户数据库。

1. 先完成不依赖数据库品牌的仓储接口、数据归属规则、联合对象检查和双租户fixture。
2. 若确认原生RLS方案：按租户业务表启用并强制策略；运行账号不拥有表、不具备绕过RLS能力；事务开始从可信上下文绑定租户，缺失则拒绝；连接复用与异常回滚不得泄漏上个租户上下文。
3. 若确认MySQL独立库/独立账号方案：根据可信租户映射选择受限数据源；不同账号不能访问他租户库；平台汇总走独立受审计接口。此方案须客户确认满足合同隔离目标，不称为原生RLS。
4. 按实际选择生成迁移、约束、索引和最小授权脚本；对每张新增表做租户归属检查。
5. 用实际运行账号从应用、后台任务、导出、缓存、数据库直连分别做越权测试；管理员超级账号的测试不能代表应用账号隔离。
6. 对连接池复用、并发请求、缺租户上下文、任务撤权及迁租失败做回归。通过后才能把物理隔离任务标为完成。

## 五 HTTP共同契约

核心可机读文件见 `contracts/core-api.openapi.json`。该文件只覆盖第一批租户、资产、事件、工单和任务接口；其他接口按本章清单扩展，不宣称已具备全量OpenAPI。

|项目|本版技术约定|
|---|---|
|前缀与编码|`/api/v1`，UTF-8 JSON，字段snake_case。|
|浏览器会话|设计采用同源HttpOnly安全Cookie；具体OIDC/企业微信接入方式见Q17。写请求验证CSRF token；禁止把设备密钥交给浏览器。|
|同步成功|`{"data":{...},"trace_id":"..."}`，HTTP200。|
|异步受理|`{"data":{"operation_id":"...","status":"PENDING"},"trace_id":"..."}`，HTTP202。|
|统一失败|`{"error":{"code":"...","message":"...","details":[]},"trace_id":"..."}`。|
|幂等|所有创建与业务动作带 `Idempotency-Key`；同一主体、租户、路由的同键同内容复用结果，同键异内容409。|
|乐观锁|修改对象提交expected_version；`UPDATE ... WHERE tenant_id=? AND id=? AND version=?`，未更新返回409。|
|列表|`data.items`、`data.next_cursor`、`data.has_more`；页面按M10-9提供10/15/25/50/100，本版技术默认15；M2-3规定接口单页上限按已确认配置为100或500，服务端动态限制，不把100硬编码为全平台上限。导入500行限制单独处理。|
|时间|`2026-09-30T02:00:00.000Z`等UTC时间；响应带sampled_at/generated_at/freshness时明确各自含义。|
|查询范围|服务端授权集合；传入tenant_id仅可用于有权限的切换或平台动作，不能自授数据权限。|
|下载|接口每次检查租户和对象权限；15分钟临时链接只是过期限制，下载入口仍复核授权，撤权后不能继续直取对象存储。|

本版将上一版异步示例统一包在data内。所有新页面、模拟响应和生成客户端统一采用该结构，避免前端分别兼容多个信封。

|HTTP|code示例|客户端处理|
|---|---|---|
|400|VALIDATION_ERROR|定位字段，不自动重试。|
|401|SESSION_EXPIRED|结束本地会话，重新登录。|
|403|ACTION_FORBIDDEN / CSRF_INVALID|明确无动作权限；客户备份下载按合同返回403。|
|404|OBJECT_NOT_FOUND|对象不存在或不可见，二者不区分。|
|409|VERSION_CONFLICT / IDEMPOTENCY_CONFLICT|刷新版本或检查重复请求；不得自动覆盖。|
|422|STATE_NOT_ALLOWED / CONFIG_PENDING|显示原因及待确认Q编号，保存草稿但不执行依赖动作。|
|429|RATE_LIMITED / QUOTA_EXCEEDED|显示重试时间或配额提醒，不能无限重试。|
|503|UPSTREAM_UNAVAILABLE|未受理则返回503；已耐久受理的任务仍202，并在operation中显示异常。|

异步任务的前端轮询退避和最大等待时间属于技术配置；页面等待超时只显示“仍在处理”，不能写FAILED，也不能自动再提交一笔有副作用的请求。

## 六 首批接口字段

|接口|必填输入及校验|结果及边界|
|---|---|---|
|GET /session|有效会话|返回user、当前tenant、允许的租户和capabilities；不返回敏感凭据。|

|GET /assets|cursor/page_size/type/site_id/status均白名单|返回本租户脱敏资产；不在列表带secret_ref或配置正文。|
|POST /assets/imports|file_id、column_mapping、dry_run；确认时还需preview_hash；实际内容最多500行|202；预览哈希绑定文件、列映射、租户和配额预留版本，确认时重验，变化则重新预览。|
|GET /incidents|状态、优先级、发生时间、资产等白名单|同时返回monitor_state和disposition_state，不混成一个状态。|
|POST /incidents/{id}/ack|note、expected_version|首次有效人工确认只写一次，用于MTTA；重复操作幂等。|
|GET /tickets/{id}|路径ID|按角色投影；客户看不到内部敏感载荷。|
|POST /tickets|description、source；客户报障另需category、impact_scope、contact_name、contact_phone、urgency；asset_id可不填表示不确定；可选title/attachment_ids|类别为网络不通/网速慢/WiFi问题/设备异常/其他；图片最多3张、每张≤5MB并异步上传。title可由类别与设备生成；客户“很急”不直接等于P1，最终等级由值守判断。|
|POST /tickets/{id}/accept|expected_version|主体取会话；记录首次响应，不能刷时间。|
|POST /tickets/{id}/transfer|assignee_id、reason_code、reason_detail、retain_previous_as_collaborator、expected_version|原因枚举+补充文字；保留协办选项，目标为授权成员，不改SLA；通知原/新负责人及服务经理，P1/P2另通知客户决策人。|
|POST /tickets/{id}/resolve|solution、expected_version|解决说明按合同至少20字；计数按Unicode字符，前后端一致。|
|POST /tickets/{id}/confirm|decision为resolved/unresolved、expected_version；未解决需reason|仅报障人或决策人关系成立的客户主体；客户端不能提交customer_id。|
|POST /tickets/{id}/reopen|reason、expected_version、可选附件引用|关闭后72小时边界按合同；重开相关MTTR展示差异见Q27。|
|POST /tickets/{id}/worklogs|started_at、ended_at、category、expected_version|本人填报；更正留历史；最大时长和重叠规则如无定论不沿用原型随意值。|
|GET /operations/{id}|本租户operation_id|只暴露脱敏错误与步骤；返回状态不改变任务。|

契约中字符串长度上限等技术防护值标记为设计建议，不宣称都是合同要求。客户字段如有既有表单限制，由Q31合并并更新契约。所有正式写接口禁止未知字段，尤其tenant_id、actor_id和可自行指定的完成时间。

## 八 事务和状态迁移实例

### 创建工单

1. 验证身份、租户、关联资产及附件所有权；检查报障30秒防重复等已确认规则。业务防重复与HTTP幂等是两层机制。
2. 规范化请求计算payload_hash，在同一事务写幂等记录、本地受理单、SLA快照（具备规则时）、动作、operation、outbox。
3. 若SLA关键输入未确认，相关正式建单入口返回CONFIG_PENDING；不得静默写4小时。开发fixture可产生明确标识的测试单，不进入正式报表。
4. Worker调用ITSM前检查关联ID是否已经存在；若超时不知道是否成功，先查询而不是再建一单。
5. 回调验证来源并写inbox，依据外部版本和发生时间更新同步状态。旧回调不能覆盖新状态。
6. 外部建单成功后才写external_id与已核实状态；失败保留平台受理记录和原因。Q07决定无ITSM模式，不把它做成自动降级开关。

### 客户确认与超时关单竞争

1. 两类动作使用同一工单version做CAS；谁先提交，另一个重新读状态再判断，不能双写关单凭证。
2. 客户确认校验报障人或决策人关系和所见解决版本，close_mode记customer_confirm；后台到期关单记timeout_auto。
3. 两种close_mode在月报中分列，超时关单不增加客户确认数。
4. 重开操作保留历史关闭记录和原工单；旧超时任务以版本校验失效，不能把重开的工单再关掉。

### 配置发布

1. 保存草稿版本；校验每一必需参数与关联Q结论；预览变更影响对象。
2. 经有权主体批准后设effective_at；生效事务写活动版本和outbox。
3. 消费者刷新缓存，既有工单/报告继续引用自己的快照；计算服务读取明确版本。
4. 回退也是新的配置版本，记录来源版本和原因，不能把审计历史删掉。

## 九 外部适配器统一接口

|适配器|领域层调用的方法|必须提供的可靠性能力|
|---|---|---|
|MonitoringAdapter|provisionTenant、upsertAsset、readAssetState、pullEvents、applyTemplate|池和租户绑定；受限身份；源事件ID；分页水位；配置回读。|
|CmdbAdapter|listAssets、readChanges、readRelations|分页/增量游标、源版本；冲突前后值；失联与删资产区分。|
|ItsmAdapter|create、findByCorrelation、transition、comment、attach、read|关联ID查询、状态映射、回调版本；不确定结果可人工核实。|
|NotificationAdapter|send、queryReceipt、verifyCallback|供应商请求号、发送/受理/送达时间、去重与真实回执。|
|RemoteGatewayAdapter|probeCapabilities、createSession、stop、readRecording、queryCommands|审批凭证绑定、真正只读约束、录屏故障处置和命令检索。|
|SecretProvider|getReferenceMetadata、readForWorkload、rotate|细粒度授权、租户/站点范围、到期、审计；不返回给UI。|

每类适配器提供fixture实现和真实实现，并用相同契约测试验证。参数、域名、证书、网络出口、超时、速率与重试单独配置。Webhook用户输入URL与客户专用内网接口采用不同白名单策略；防DNS重绑定、重定向到内网和凭据泄漏。
