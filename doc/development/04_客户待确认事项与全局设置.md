## 3. 全局设置登记规则

配置登记的机器可读副本见 [config-baseline.json](contracts/config-baseline.json)，当前186项（77项有合同数值、109项保持null）。本 Markdown 为登记真源；先更新本文再同步JSON。JSON状态为design_registry_not_runtime_config，禁止直接导入生产。

未确认配置读取示例：`value=null,status=PENDING_CONFIRMATION,question_id=Qxx`。若相关操作必须依赖此值，返回统一业务错误 `CONFIG_PENDING` 与 Q 编号；页面显示原因并禁用对应执行按钮。测试夹具使用独立测试命名空间，不允许 fallback 到原型演示值。

## 6. 确认后的落地步骤

1. 接收客户书面结论，核对确认人有对应业务/安全/技术权限；补足证据文件版本与日期，不在本文保存明文密钥。
2. 将该 Q 项结论填入原空格；未覆盖的子问题仍标待确认，不能整项误关。涉及变更的另附变更单。
3. 更新关联配置草稿，将每个字段从 `null/PENDING_CONFIRMATION` 变为已确认值；校验作用域、单位、范围和依赖项。Q03录入组件批准证据；Q01录入路线确认书后才允许M7排期。
4. 修改对应设计、接口、DDL/迁移（Q02解锁后）、测试样例和验收映射，生成新版本差异；保留历史规则及原值。
5. 用客户样例执行正常、缺参、跨租户、越权、失败重试、时间边界回归；失败则维持禁用，不自动回落到演示值。
6. 经项目流程发布配置；记录生效时间、操作者、版本和审计trace_id。进行工单/报告抽样，确认旧快照不被新配置改写。
