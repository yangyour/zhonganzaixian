# 成熟组件复用与技术选型

版本：V0.1 开发设计稿　编制及官方资料核验日期：2026-09-30

本文件依据合同正文及附件（原文定位见 [合同提取证据](evidence/contract_requirements.json)）、`tmp/project_docs/formal/design_content.md` 的 D02—D04、D08、D12—D14、D22—D26，以及 `zabbix-msp-prototype` 的代码和功能说明编制。它确定复用边界、接入顺序和验证任务，不表示组件已安装、已获甲方许可或已通过验收。组件的正式版本、部署形态、费用及批准记录仍须写入技术基线。

## 1. 现状与选型原则

已核对的原型使用独立 HTML、原生 JavaScript、CSS 和浏览器本地存储。`assets/js/charts.js` 是自行实现的 SVG 图表；拓扑模型自行维护节点、边、版本和本地保存；`contract-pages.js` 的备份、审批、远程会话和报告均为模拟。当前目录检索未发现生产前后端的 `package.json`、`pom.xml` 或 `build.gradle`。因此，Vue、Spring Boot、数据库、队列和堡垒机均不能描述为“现有运行组件”。

复用分三层：保留原型的页面信息结构、字段、交互和可用测试样例；由成熟组件承担表格、图表、认证、迁移、协议、文本差异和渲染；由本项目实现租户授权、状态机、业务规则、幂等、审批与审计。不能把组件具备某功能等同于本项目已满足合同。

|状态|本文件中的含义|允许推进的工作|
|---|---|---|
|拟采用|有明确首选，作为内部开发设计，不代表客户已批准|抽象接口、数据模型、样例和验证方案；依照已确认的项目流程冻结依赖|
|条件候选|仅在指定条件满足时接入|先做接口契约与兼容性核查，不建设第二套同类基础设施|
|待客户确认/许可|影响合同实现、运行环境、许可证或外部系统|占位保持空值；先完成不依赖该结论的业务边界；不得默认启用|
|已有原型可复用|已在本地找到的原型内容|迁移交互、样式变量、校验用例和样例；重新实现服务端可信控制|

统一要求：使用明确版本和锁文件，不使用 `latest`；不同时引入两个图表库、两个数据库迁移工具或两个任务队列。合同 P281 要求运行环境使用甲方已采购产品、使用开源软件须征得甲方同意、版本处于原厂支持范围；P159 要求开源集成前提交披露清单，GPL/AGPL/LGPL 等指定许可还须书面同意。因此“拟采用”允许先形成设计和验证方案，不替代该程序。第三方模板、字体、浏览器运行时及传递依赖也进入组件清单。

## 3. 前端与图表如何接入

Vue 官方提供 TypeScript 与 Vite 的建项方式；Element Plus 提供 Vue 组件及按需导入；ECharts 采用 Apache-2.0 许可。这里选择它们是为了接管通用交互和图表能力，既有原型继续作为字段及视觉参照。[Vue TypeScript](https://vuejs.org/guide/typescript/overview)、[Element Plus](https://element-plus.org/en-US/guide/quickstart)、[ECharts](https://echarts.apache.org/en/download.html)

1. 建立管理端目录，冻结包管理器、Node 运行版本、Vue/TypeScript/Element Plus/ECharts 版本及锁文件。版本未评审时留在“候选”清单，不写成上线基线。
2. 抽取原型颜色、字号、间距和导航结构；封装 `AppTable`、`AppDrawer`、`StatusTag`、`AsyncOperationPanel`、`PermissionGate`。保留组件的原生能力，封装只承载本项目共同约束。
3. 先完成资产列表纵向切片：请求 → 分页/筛选 → 空态/失败态 → 抽屉 → 提交 → 异步进度 → 回读。前端不能在 API 尚未成功时自行改为“已生效”。
4. 从 OpenAPI 派生 DTO；建立 `apiClient`，统一 trace_id、401、403/404、409、422、429 和 503 的表现。租户切换取消旧请求并清理对应缓存；响应必须与发起时的授权上下文相符。
5. 将原型 `charts.js` 的业务输入转换成 `MetricSeries`；统一包含 `sampled_at`、单位、精度、空值和数据新鲜度。ECharts 只展示结果，不能在 tooltip 中另算可用率。
6. 为未知区间保留空值/断线，避免把 `null` 转 0；图表点击传递资源、指标和时间窗口到明细。刷新间隔遵循已确认参数，离开页面停止计时器并释放图表实例。
7. PC 管理端先复刻已确认页面；企业微信 H5 的触控布局另做适配验证，不直接将 PC 表格缩小当移动端交付。
8. CI 同时运行类型检查和构建。Vue/Vite 的转译成功不代表 TypeScript 检查通过，需单独执行 `vue-tsc`。[Vue 官方说明](https://vuejs.org/guide/typescript/overview)

隔离要求：权限不足的数据由 API 拒绝返回；隐藏按钮只能优化体验。设备秘密、备份正文和录屏不得放入全局状态或浏览器持久缓存。所有依赖本地打包，不在生产页面运行时加载公共 CDN。

小型验证 FE-01：使用两个租户、四类角色、三种加载结果验证资产页；在请求尚未结束时切租户，旧响应不能覆盖当前页；含未知值的曲线不能补零；输出截图、网络响应和类型检查日志。

## 4. Spring Boot / Security 与迁移如何复用

### 4.1 身份与业务框架

复用 Spring Security 的认证与 JWT 验证机制，使用 Spring Boot 组织 API 和 Worker；不自制令牌签名或密码哈希算法。具体 Spring Boot、Spring Security 与 JDK 使用经兼容性核验的组合，不单独追逐各组件最新版本。[Spring Security JWT](https://docs.spring.io/spring-security/reference/servlet/oauth2/resource-server/jwt.html)

1. 建立 `identity`、`tenant`、`asset`、`incident`、`ticket`、`backup`、`remote`、`report`、`integration` 模块；领域服务不引用厂商 SDK 类作为业务对象。
2. 配置认证过滤链，按实际身份源校验签发者、受众、签名及有效期。OIDC 与本地账号映射到统一 `user_id`。
3. 在身份验证后查成员关系，建立可信 TenantContext；忽略或拒绝客户端任意指定的租户上下文。MSP 多租户视图来自授权集合。
4. 对每个对象动作检查角色、对象所属租户、设备授权与业务状态；将“申请人不能自审”等规则放进领域服务，不能只依赖菜单角色。
5. 会话、缓存和任务保存权限版本，执行时查询有效授权。仅验证一个尚未过期的 JWT 不能证明撤权已立即生效。
6. Cookie 会话保留 CSRF 防护；若采用 Bearer API，按真实调用方式配置 CORS/CSRF，不全局关闭安全控制来解决联调错误。
7. 审计写入动作、对象、结果、拒绝原因及 trace_id，过滤秘密；业务事务产生待发送记录时与 Outbox 同事务提交。

小型验证 BE-01：无租户上下文、伪造租户、撤权后的旧会话、已审批后换设备、申请人自审全部失败；正常授权请求仍可完成。

### 4.2 数据库迁移

Spring Boot 支持 Flyway 和 Liquibase。首选只使用 Flyway 开源仓库提供的迁移模块，商业版的高级比较/回退能力不纳入免费基线。Liquibase 5.0+ Community 已转为 FSL，不能继续统一登记为 Apache-2.0；只有客户明确已有该产品并确认许可时才考虑沿用。[Boot 数据初始化](https://docs.spring.io/spring-boot/how-to/data-initialization.html)、[Flyway 开源仓库](https://github.com/flyway/flyway)、[Liquibase 官方许可变更](https://www.liquibase.com/blog/liquibase-community-for-the-future-fsl)

1. [Q02](04_客户待确认事项与全局设置.md) 之前整理逻辑表、约束及 Repository 契约；数据库专有迁移目录保持待选择，不双写两套生产数据库。
2. 确定数据库后创建迁移专用账号与运行账号；运行账号不能执行 DDL。迁移步骤独立于普通应用多副本启动。
3. 按顺序生成 `V001__tenant_identity.sql` 等文件，已执行文件不可修改；修正通过新迁移完成。SQL 名称仅示例，实际表及序号以数据设计文件为准。
4. 同一迁移及对应仓储实现覆盖非空 tenant_id、联合唯一性、联合关系完整性、索引、数据库权限和选定隔离策略，不只创建表结构。附件三 P369 采用物理主键、逻辑外键、逻辑唯一性的约定；关系校验在事务与并发保护下落实，具体物理约束与03保持一致，不擅自把物理外键设为合同硬要求。
5. 在空库和上一版本副本各执行一次迁移；校验迁移历史、权限、存量回填、应用兼容性。禁止将 ORM 自动建表作为生产迁移机制。
6. 不假设工具提供免费自动撤销。变更前记录备份点；破坏性变更采用先兼容新旧字段、回填、切读写、最后清理的多阶段发布，并实际演练恢复。

小型验证 DB-MIG-01：迁移中断后可判断已执行状态；篡改旧脚本被校验拦截；运行账号无法改表或绕过隔离。

## 5. 数据库隔离：先完成两套边界，等 [Q02](04_客户待确认事项与全局设置.md) 选一套

PostgreSQL 提供原生行级策略；超级用户及 BYPASSRLS 角色会绕过策略，表所有者通常也绕过，需配置 FORCE ROW LEVEL SECURITY。MySQL 的 SQL SECURITY 解决视图使用哪一身份检查权限，不能凭这一特性推定共享表已经满足合同要求的数据库层 RLS。[PostgreSQL 行安全](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)、[MySQL CREATE VIEW](https://dev.mysql.com/doc/refman/8.4/en/create-view.html)

|方案|接入步骤|必须通过的验证|待客户结论|
|---|---|---|---|
|A：PostgreSQL 控制库 + RLS|租户表非空 tenant_id → 复合关系约束 → 启用/强制 RLS → 运行账号非 owner、无 BYPASSRLS → 已鉴权事务绑定租户 → 事务结束清理上下文|遗漏应用 WHERE 仍隔离；连接池交替租户不串数据；后台任务不带上下文即拒绝；读写和关联表均不可越权|控制库是否可选 PostgreSQL；合同 MySQL 支持适用层次：**________**|
|B：MySQL 租户独立库/账号|租户路由服务 → 独立凭据授权 → 租户库内仍保留 tenant_id → 迁移编排 → 独立平台汇总库/接口|A 租户数据库账号无法访问 B 库；错误路由/任务被拒绝；所有租户升级可追踪且单租户失败可恢复|是否认可独立库方案满足 M2-5；运维/资源成本：**________**|

本项目选择事务级租户上下文时，上下文仅由已鉴权服务设置；运行身份仍是受信任的服务边界，不能把可自行改会话变量的任意数据库客户端视为受 RLS 完整约束。参数化 SQL、无动态执行入口和数据库账号隔离须同时落实。

可先做：`TenantContext`、对象联合定位、Repository 接口、租户用例、数据库验证脚本设计。应暂缓：生产方言、分库基础设施、跨库汇总 SQL、HA 复制拓扑。不能以“先上共享 MySQL，以后补 RLS”越过 [Q02](04_客户待确认事项与全局设置.md)。

## 6. Zabbix：复用采集与模板，业务留在平台

Zabbix API 支持配置及历史数据访问，使用服务端令牌调用；模板可导出并纳入版本管理。Zabbix 7.0 及后续版本的官方许可为 AGPLv3，本项目在 [Q03](04_客户待确认事项与全局设置.md) 未取得书面批准前不将其设为正式交付基线。模板自身的来源与许可也需逐件登记。[Zabbix API](https://www.zabbix.com/documentation/7.0/en/manual/api)、[模板导入导出](https://www.zabbix.com/documentation/7.0/en/manual/xml_export_import/templates)、[官方许可](https://www.zabbix.com/license)

1. 先定义 `MonitoringAdapter`：资源登记、模板关联、配置回读、指标查询、事件查询、健康状态。编写 fixture 适配器供其他模块开发；响应明确 `source=fixture`，不能当真实采集值。
2. 收到 [Q03](04_客户待确认事项与全局设置.md) 后登记精确 server/proxy/agent 版本及数据库兼容矩阵；验证 API 版本，不在同一适配器中默认所有 7.x 方法和参数完全相同。
3. 每个资源池保存端点、健康、能力和 `credential_ref`；浏览器只能调用业务 API，不能拿到 Zabbix token 或直接访问其数据库。
4. 准备专用部署身份及租户受限身份。主机组采用设计约定的租户路径；名称前缀仅便于管理，必须验证真实组权限和 API 方法权限。
5. 建立 `tenant + asset_id + pool_id + source_host_id` 映射；指标、事件、模板操作均先由资产反查映射，禁止把用户传入的任意 hostid/itemid/eventid 原样透传。
6. 优先复用官方与已验证厂商模板；将原始包、来源、哈希、模板版本、宏范围、LLD 上限、单位和阈值分开登记。只为合同缺口增加监控项或厂商映射，不复制修改整套监控引擎。
7. 模板发布先验证导入及预计监控项，创建发布版本，灰度回读。合同要求的灰度范围和时长按设计执行；[Q06](04_客户待确认事项与全局设置.md) 尚未确认的阈值只存草稿，不发布。
8. 配置下发返回 operation，Worker 回读远端事实后更新生效状态；超时先查远端状态再决定重试，避免重复创建。
9. 原始事件耐久落库，再走归并、抑制、派单和通知；保留补偿游标及重叠扫描。平台负责工单生命周期，不能将监控恢复事件当客户确认。

复用范围不包含：六层租户隔离、合同 SLA、客户确认关单、费用口径和报告审批。原生 HA、Proxy 缓冲及协议支持均按所选版本实测，不能从“有 HA 功能”推导零数据丢失。

小型验证 MON-01：两个租户各一台测试主机，验证受限身份看不到对方对象；模板导入/回读/回退；重复与迟到恢复事件不重建工单；不支持项显示原因。未获许可时只执行 fixture 契约验证，真实集成项保持待执行。

## 7. 队列与调度：优先已有服务，先固定可靠性契约

本地尚无可确认的既有队列产品。先冻结 `TaskEnvelope` 和 Outbox，不擅自引入 Kafka、Redis Streams、RabbitMQ 多套并存。客户已有服务满足持久性、确认、死信、重放、隔离和运维要求时优先沿用；没有可用服务时，RabbitMQ 是条件首选。其 quorum queue 和 publisher confirms 有明确故障边界，仍需结合副本与磁盘确认验证。[RabbitMQ quorum queues](https://www.rabbitmq.com/docs/quorum-queues)、[发布确认](https://www.rabbitmq.com/docs/publishers)

1. 统一任务信封：`message_id`、`tenant_id`、`actor_id`、`permission_version`、`task_type`、`resource_id`、`idempotency_key`、`payload_version`、`trace_id`、`created_at`。不在消息中存明文设备凭据。
2. 业务修改与 Outbox 同事务提交。发送器确认消息已耐久接收后标记已投递；未确认保留可重试状态。
3. Worker 验证来源、租户和当前授权，用幂等唯一键与处理结果同事务落库，再确认消费。按“至少一次”设计，不能依赖产品名字宣称恰好一次。
4. 按任务类型设置超时和可重试错误；对未知远端执行结果先回读。长任务有租约和心跳，超时接管前检查是否仍在运行。
5. 控制每租户并发及积压配额，防止单租户任务占满 Worker；通知、报告和设备连接分配不同执行池。
6. 定时任务通过数据库/已选调度服务持久化下一次时间，并用租约保证唯一调度；普通 `@Scheduled` 不能直接作为多实例唯一执行保证。
7. 本地测试可用内存队列替身，但启动日志、接口和验收记录必须表明其不耐久，不能用于生产 Webhook 成功回执。

队列产品、版本、副本数、跨中心方式、保留时间、最大重试及死信操作人：**________，待技术基线/[Q04](04_客户待确认事项与全局设置.md) 结论**。

小型验证 MQ-01：在“写 Outbox 后/发送确认前/业务提交后确认消费前”分别终止执行器；恢复后意图不丢失且业务不重复。结论应附消息、业务记录、确认时序和实测恢复时间。

## 8. 远程会话：完整堡垒机优先，协议组件不是全部交付

### 8.1 选择顺序

第一顺位为甲方已采购且接口可用的堡垒机。若无可用服务，优先对 JumpServer 做能力验证。官方文档包含资产/账号约束、命令过滤、审批和会话审计，但社区版与企业版组件不同，不能把文档中的全部能力视为免费可用。JumpServer 主仓库采用 GPLv3，实际打包组件逐一核对许可证。[JumpServer 仓库与许可](https://github.com/jumpserver/jumpserver)、[命令控制](https://docs.jumpserver.org/zh/v4/manual/admin/console/access_control/acls/)、[会话记录](https://docs.jumpserver.org/zh/v4/manual/admin/audit/session_audit/session_record/)

Apache Guacamole 采用 Apache-2.0，提供浏览器远程连接和记录/回放能力，可用于经批准的协议路线。其协议录屏能力不能直接证明具备本合同的命令语义拦截、完整索引和双人审批；选择该路线需要单独评估补齐成本。[Guacamole 许可](https://guacamole.apache.org/open-source/)、[SSH 与记录配置](https://guacamole.apache.org/doc/gug/configuring-guacamole.html)、[回放接口](https://guacamole.apache.org/doc/guacamole-common-js/Guacamole.SessionRecording.html)

### 8.2 接入顺序

1. 在 [Q01](04_客户待确认事项与全局设置.md) 决定前只完成申请表、状态机、审批约束、会话列表和 `RemoteGatewayAdapter` 的设计契约、fixture 评审及验证方案；依 M7-0 不进入 M7 模块实施排期。原型“连接”显示明确演示/未配置状态，不能模拟真实“已连接”。
2. 形成能力表：SSH/RDP 等实际协议、设备型号、只读限制、双审批、短时票据、并发控制、强制结束、命令检索、录像获取/完整性/失效处理、授权撤回。逐项填写产品版别、接口和实测证据。
3. 建立平台租户/资产/人员与堡垒机组织/资产/账号映射；没有明确归属的资源隔离待处理，禁止按资产名称模糊关联。
4. 平台收到连接请求后，复核租户成员、资产授权、有效工单及权限版本；readwrite 还须校验两名审批人不同且非申请人、审批有效期。readonly 按 [Q01](04_客户待确认事项与全局设置.md) 确认的例外规则判断，不能复用无条件要求双审批的校验器。通过后原子占用并发名额。
5. 服务端申请一次性短时会话票据；目标资产与权限级别取自批准记录，客户端不能改写。设备账号由堡垒机/受控凭据服务获取。
6. readonly 优先通过设备低权限账号和厂商命令权限落实，不能靠网页隐藏输入框或少量前端正则。readwrite 也需高危命令控制。
7. 建连前确认强制记录能力可用；readwrite 必须录屏，readonly 按租户确认配置决定。运行中监测录屏失败，按合同设计中止不能可靠留证的写会话。结束后核对会话 ID、命令索引及适用的录像对象、哈希与时间线。
8. 录像与命令查询走本平台鉴权，保留调阅审计；不得把堡垒机高权限查询账号或长期录像 URL 交给浏览器。
9. 联调强制结束、授权撤回、网络断开、设备提示符变化及录像失败。没有经过验证的设备/协议不进入交付支持清单。

“只读诊断免审批”与通用验收“无审批不能连接”的关系、产品路线、版别、接口与采购：**________，待 [Q01](04_客户待确认事项与全局设置.md)/[Q03](04_客户待确认事项与全局设置.md)**。批准前不启动真实设备远程接入。

小型验证 REM-01：两租户、两设备、申请人与两名不同审批人；验证自审、过期申请、替换目标、撤权、第三会话超限、断录像、只读输入绕过和强制结束。若产品无法支撑核心控制，应提交缺口与替代路线，而不是通过原型文案掩盖。

## 9. 网络拓扑：复用图引擎，保留现有数据与编辑规则

Cytoscape.js 核心及官方扩展采用 MIT，适合本项目节点、边、位置、选择和布局的通用能力。G6 同为 MIT 的图引擎，具有丰富图交互；只有 Cytoscape 验证未满足具体需要、或客户已有 G6 开发资产时才替换，首期不同时维护两套。[Cytoscape.js](https://js.cytoscape.org/)、[G6 能力](https://g6.antv.antgroup.com/en/manual/introduction/)、[G6 许可](https://github.com/antvis/g6)

1. 保留原型 `network-topology-model.js` 的节点/链路业务字段，拆分领域数据和视图位置；只建立领域模型到图引擎的转换层，不以库的全量内部 JSON 作为永久数据契约。
2. `tenant_id + topology_id + revision` 管理文档；节点引用资产时必须联合校验租户；链路两端必须属于同一张图。
3. 初次加载采用已保存坐标，布局按钮才显式重排；拖动不直接发多次写请求，先形成草稿，保存时带 expected_revision。
4. 将原型“删节点同时清理边、不删资产”“VLAN 合法范围”“端口关系去重”“无监测显示未知”迁移为服务端校验和前端提示。
5. 保存遇 409 展示冲突并保留草稿；不使用 `localStorage` 覆盖服务端事实。自动发现并非本版首期范围，示意连线不能标为真实发现。
6. 状态批量按资产/监测映射刷新，图形布局不随每次状态刷新重置。全部租户视图仍展示拓扑列表，不合并不同客户的资产。
7. 图导出先由服务端授权生成数据或受控导出内容；节点 HTML、URL 和图标使用白名单，避免从节点备注执行脚本或加载任意远程地址。

小型验证 TOPO-01：原型代表图迁移后位置/字段不丢失；同租户两个窗口冲突可见；越租户资产引用失败；未知链路不显示编造的流量。节点/边压力规模由 [Q13](04_客户待确认事项与全局设置.md) 确认，开发自测规模记录为测试数据，不冒充合同规模。

## 10. 备份、规范化与差异：只复用一个读取链路

优先复用客户已有的配置备份接口，次选经验证的堡垒机配置读取能力。无可用接口时，将 Netmiko 封装在独立受限采集器中，避免在主 API 进程内运行设备交互。Netmiko 本身采用 MIT，但其依赖另行核验。java-diff-utils 采用 Apache-2.0，diff2html 采用 MIT，可复用文本比较和展示能力。[Netmiko](https://github.com/ktbyers/netmiko)、[依赖许可清单](https://github.com/ktbyers/netmiko/blob/develop/license-dependencies.txt)、[java-diff-utils](https://github.com/java-diff-utils/java-diff-utils)、[diff2html](https://github.com/rtfpessoa/diff2html)

1. 首批设备输入为厂商、型号、系统版本、读取协议、只读命令、分页/提示符特征、最大配置大小和连通点；没有输入的型号显示“待适配”，不填写虚构支持列表。
2. 建立 `BackupCollector.readConfig(asset, credential_ref)`；从受控凭据服务获取秘密，验证主机密钥或经确认的设备信任策略，不能自动接受所有陌生主机。
3. 任务按租户/设备锁定，使用固定读取命令；不接受前端自由传入 shell 命令。Python 运行时只在 Netmiko 路线获选后引入，并单独记录依赖、镜像与补丁责任。
4. 原始配置加密保存，记录内容哈希、采集时间、模板版本和设备版本。规范化副本去掉已确认的动态噪声，规则必须版本化，禁止先删除所有“看起来会变化”的行。
5. 对秘密字段先进行受控比对：如需发现口令/密钥变化，用仅服务端可见的摘要或标记识别变化；向前端输出脱敏片段和“秘密字段已变化”，不得因全部替换为固定 `***` 而漏报变化。
6. 用 java-diff-utils 生成差异，diff2html 只渲染已授权且脱敏的结果。设置行数/大小/耗时上限，大文件返回摘要和受控下载，避免浏览器阻塞；含 HTML 的配置按文本处理。
7. 每日备份与每 6 小时差异检测调用同一读取/规范化服务，分别记录任务原因；连续失败计数按独立运行最终结果累计，内部两次重试不能算两次备份失败。
8. 差异关联变更报备及事件/工单，不提供默认“自动恢复配置”动作；配置回写属于另行确认的远程/自动化边界。
9. 热历史和归档生命周期依 [Q10](04_客户待确认事项与全局设置.md) 结论实现；客户角色只能查概况，正文、diff 和下载接口都拒绝。下载授权到期或撤权后重新校验。

小型验证 BKP-01：一台已确认型号的测试设备产生无变化、动态噪声、普通差异、秘密变化和两次失败；核对事件/工单、脱敏、加密对象、客户拒绝以及 3 个月历史检索。

## 11. 报告与文件：同一快照、同一模板、多种输出

Playwright Java 提供页面 PDF 输出，适合以同一 HTML 模板生成 H5 和 PDF；Playwright 库为 Apache-2.0，随制品分发的 Chromium、系统依赖和字体仍须单独登记许可。Apache POI 为 Apache-2.0，用于 `.xlsx` 导入/导出，CSV 用统一文本解析模块，不额外引入完整 BI 平台。[Playwright PDF](https://playwright.dev/java/docs/api/class-page#page-pdf)、[Playwright 许可](https://github.com/microsoft/playwright/blob/main/LICENSE)、[POI](https://poi.apache.org/)、[POI 许可](https://poi.apache.org/legal.html)

1. 以原型 `reportBody` 的布局代码为参照，按 M9-3 补齐老板版五区块、页脚、数字下钻和一页要求，不将原型简化内容直接当完整合同模板；模板只读 `ReportPayload`，不得直接查询实时资产/工单服务。
2. 汇总服务在明确时间窗口和口径版本下生成快照，保存 JSON、指标来源和哈希。未知区间、SLA 日历及补偿金额分别依赖 [Q05](04_客户待确认事项与全局设置.md)、[Q08](04_客户待确认事项与全局设置.md)、[Q26](04_客户待确认事项与全局设置.md)；只阻塞该字段的正式计算，不阻塞已确认字段、模板、草稿预览及基础统计开发。正式发布前校验该报告必需字段的确认状态。
3. 同一快照提供 H5 页面和 PDF 渲染入口；冻结模板版本、字体、语言、时区及浏览器版本。重生成创建新版本，不覆盖已发布报告。
4. 渲染 Worker 使用受限身份，仅允许读指定快照和本地静态资源；关闭任意外部 URL、文件系统和内部网络访问，任务结束清理临时目录。
5. 等待字体和图表完成后再打印；统一纸张、页边距和分页。核对中文、长名称、空表、多页表格、图表和页码；不以“文件能打开”作为通过。
6. 报告生成、审批、发布和发送分别建状态；退回只生成新草稿/新版本。下载网关每次检查当前租户和权限。
7. POI 导入先验证类型、文件大小、解压限制和 500 行业务上限，不执行文件宏或公式；列映射和资产字段按导入契约逐列处理。
8. 导出数值、日期和字符串使用明确单元格类型；不将用户内容作为公式写入。CSV 对公式触发字符进行文本安全处理；500 行导入逐行回执不能被一次异常全部吞掉。

小型验证 RPT-01：同一快照的 H5/PDF 指标和文字一致；修改源数据后旧报告保持不变；中文长表正常分页；跨租户下载失败；老板版生成耗时按合同独立测量。文件验证 FILE-01 覆盖畸形压缩包、超行、错误列和公式文本。

## 14. 进入开发与交付的门槛

按先后交付五个可审查结果：①组件清单与原型复用映射；②适配器契约及 fixture；③资产列表/鉴权/任务纵向切片；④客户结论到位后逐一替换真实适配器；⑤对应小型验证和合同专项验证证据。

任何成熟组件接入完成均需证明：业务输入输出与契约一致、双租户隔离有效、重复/异常可恢复、凭据不泄漏、升级可追踪、许可清单完整。小型验证用于排除路线错误，不替代合同 128 项逐项验收；本文没有预写“全部通过”的测试结论。
