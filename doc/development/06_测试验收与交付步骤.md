# MOP平台测试验收与交付步骤

本文件规定“怎样证明功能已完成”。合同需求ID是追踪入口，07中的TC编号为待执行用例入口；本轮只做文档和设计契约检查，不填写业务测试通过、客户认可或上线成功。

## 一 每个需求的测试记录

|记录字段|填写内容|
|---|---|
|需求与用例|M编号、TC编号、正向/权限/边界/异常/并发子用例。|
|规则基线|相关Q结论、配置版本、模板/日历/指标版本；没有结论的子用例标BLOCKED。|
|环境|应用提交号、依赖与数据库版本、服务器配置、数据规模、外部产品版本。|
|输入与步骤|完整的脱敏输入、调用顺序和时钟基准，另一人可复现。|
|预期|状态、数据、审计及可见页面分别应怎样变化。|
|实际|实际返回、存储和外部事实；不得只贴成功提示截图。|
|证据|trace_id、operation_id、日志/回执、截图/录屏、数据库查询结果及文件哈希。|
|结论|PASS / FAIL / BLOCKED / NOT_RUN；执行人、日期、缺陷号及复核人。|

需求优先级P0/P1与工单或告警P1/P2/P3/P4分开。128项的需求优先级在Q13确认前留空；不自行降级以计算通过率。

## 二 第一轮可立即执行的验证

此处指开发相应代码后可做的本地验证；本轮交付的文档检查结果另列在末尾。

1. **契约检查**：解析OpenAPI，检查请求必填字段、错误信封和路径参数；验证生成客户端与fixture响应一致。
2. **数据隔离接口检查**：建立A/B两租户，复用同名资产、不同成员；对每个对象接口替换B的ID，确保A无法读写。
3. **空值检查**：让告警阈值、SLA日历、补偿公式等为null，调用依赖动作应返回CONFIG_PENDING；只读展示说明未配置。
4. **状态机检查**：对工单、operation、报告版本执行合法/非法动作；重复动作无新增副作用，错误动作不改变version。
5. **幂等检查**：并发相同Key+相同内容只生成一个业务动作；同Key+不同内容409；旧响应不泄漏给另一主体。
6. **统计工具检查**：区间求交、裁剪、并集和跨月拆分以手算数据验证；尚无客户结论的公式不写期望数值。
7. **UI检查**：加载、空、未知、失效、无权限、待确认各状态，以及390像素宽的报障与确认操作。

物理数据库隔离、消息持久性和真实外部系统兼容性不能由内存fixture证明，必须留待对应集成测试。

## 三 关键业务场景逐步验证

### T01 租户及对象隔离

1. 在实际批准的隔离方案中建A/B两租户，各建成员、资产、事件、工单、报告、备份；记录ID。
2. 以A身份替换B的hostid、itemid、eventid，预期全部拒绝且无他租户数据。
3. 获取B报告下载地址后用A会话访问；复制缓存请求及伪造tenant_id任务，均应失败。
4. 用租户受限监控身份直接查询B对象，应失败；撤销A某成员权限，旧会话、缓存、未执行任务下一次均不得继续。
5. 检查缺租户上下文及连接池连续A→B→无上下文调用；数据库隔离与应用校验分别留证。

通过要求：合同七类越权检查全部拦截；包括导出和后台任务。涉及Q02/Q09/Q17，任一未满足则不能宣称隔离完成。

### T02 资产与500行导入

1. 准备500行数据，含重复名称、冲突IP、未知类型、超配额、跨租户站点和缺必填项。
2. 先预览，检查错误列、错误原因、预留配额与待导入数量，不写入错误行。
3. 确认导入，期间同时执行第二批导入，验证配额原子控制和重复数据处理。
4. 检查每行状态及operation进度；文件被替换后不得沿用旧预览确认。
5. 对成功设备走五步接入，制造连通失败、模板不支持、首值未到三种情况，页面不得标正常。

通过要求：按合同验证500行导入≤60秒，基准环境和外部调用范围由Q13固定；Q31尚未定义的冲突处理不可自选静默覆盖。

### T03 事件接收与补偿

1. 产生问题、恢复、重复问题、重复恢复及恢复先到的数据集，保存源时间和ID。
2. 中断Webhook投递，再制造故障；恢复后从水位补拉，包含15分钟重叠范围及超过重叠窗口的缺口。
3. 验证原始事件完整、归并关系可追溯，同一业务事件不重复建单或重复通知。
4. 模拟上游超时、队列重复投递、Worker提交后宕机；重新处理仍只有一笔业务结果。
5. 核对维护、依赖抑制和静默的原因字段；未知采样不被计作正常或恢复。

通过要求：源时间不被received_at替代；遗漏与重复可追踪；依赖Q06/Q14/Q29的策略逐项解锁测试。

### T04 工单完整闭环

1. 客户报障，确认界面区分平台受理与外部ITSM建单状态；外部建单超时后回读，不重复创建。
2. 工程师接单、转派、填写工时；记录转派前后响应及恢复截止时间完全相同。
3. 提交19字和20字处置说明，分别验证拒绝与受理；进入待客户确认。
4. 工程师、其他无关客户、报障人、决策人分别调用确认接口；只允许符合关系的客户主体。
5. 分别走确认、未解决、超时关单；核对close_mode及客户确认计数。
6. 关闭后72小时内、边界及边界外重开；按精确合同规则和Q27结论验证，保留原单历史。
7. 同时执行客户确认与超时任务；只能成功一次，重开的工单不得被旧任务关掉。

通过要求：状态、外部回读、SLA快照、动作与审计一致；Q07未完成时只认可本地动作测试，不能认定ITSM集成通过。

### T05 SLA与报告指标

1. 建版本化日历，选择23:50、非工作日、补班、跨月、跨年、档位变更等边界，至少20例。
2. 对每例手工画出有效服务区间，计算响应/恢复截止时间，再与程序比较。
3. 加入重叠故障、重复维护、故障与维护重叠、未知区间和零样本，核对并集不重复扣减。
4. 对相同数据验证首页、SLA列表、月报和经营看板同源；检查明细分母、样本量及未恢复数。
5. 修改租户新档位和日历，历史工单和已发布报告保持原快照；修订报告生成新版本。
6. 未确认“次日”、未知区间或补偿时，页面不得输出正式达标/应付金额。

通过要求：公式与Q05/Q08/Q26/Q27书面结论一致；不能用程序自算结果再当测试期望值。

### T06 通知和企业微信

1. 在指定测试接收人上验证六类合同通道；完成签名、防重放、超时、失败重试和死信。
2. 注入accepted无送达回执、delivered、failed、unknown四种结果，送达率只计delivered。
3. 同一事件同时触发严重级矩阵和业务优先级矩阵，按Q14确认规则去重，P1不被静音。
4. 重放企业微信报障/确认回调；服务端只产生一次动作，userid不能通过请求参数冒充。
5. H5会话到期后访问工单或报告必须重新验证；下载撤权后失效。

通过要求：事件至渠道受理P95≤30秒（M10-8）、受理至送达P95≤30秒（M8-3，100条样本）与电话30秒内发起分别记录；无可信回执的供应商不伪填送达耗时。生产接收人、费用及供应商依Q18确认。

### T07 备份与配置差异

1. 用批准的设备与只读命令执行计划备份、手动备份、并发备份，检查目标锁和主机指纹。
2. 分别制造单次运行的多次重试失败、多个运行最终失败，核对attempt和run记录各自准确；按Q22确认的“连续两次失败”口径检查10分钟内P3建单。结论未出前只测记录和策略接口，触发判定用例为BLOCKED。
3. 对相同配置、动态噪声行和实际配置变更生成diff；规范化规则带版本，原始加密副本可核验。
4. 分别测试有效报备、未批准报备、设备不符、时间不覆盖，只有有效报备满足关联条件。
5. 验证至少三个月前备份可查，客户无法读取正文、diff或下载；保留清理规则按Q10执行。

通过要求：读取不改变设备配置；合同不含自动回滚，不因成熟组件有该按钮便开放。到期清理保留证据，未知策略不得提前删数据。

### T08 远程会话

仅Q01路线确认、Q03适用许可批准及测试设备授权就绪后执行。

1. 验证只读例外与通用审批要求的已确认口径。读写申请缺审批、自审、重复同人审批、超时审批全部拒绝。
2. 在批准后更换设备、工单或访问级别，必须重新申请；旧票据重放和绕过平台直连均失败。
3. 同工程师同时发起三笔会话，最多两笔占用成功；模拟进程退出后额度可回收但旧Worker不能复活。
4. 尝试设备写命令、别名、空格变体及高危命令，验证真实网关/设备控制，不能只验证浏览器正则。
5. 录屏未启动时读写不建连；中途录屏故障时停止可写操作并终止，记录证据缺口。
6. 结束后核对命令条数、时长、录屏哈希、工单回填、索引与调阅审计。

通过要求：真实网关记录与平台一致；默认60分钟和单人并发2等合同规则落实，命令检索<3秒按已确认数据规模测量。

### T09 报告与经营

1. 用有完整来源的测试月份生成快照，分别输出老板版一页、完整报告H5及PDF。
2. 逐项比较数字、窗口、口径版本、明细引用；PDF与H5相同版本不能各算一次。
3. 修改事件或成本原始数据，已发布报告不变；新修订版与旧版可分别查询。
4. 报告首次阅读连续请求两次，只保留首次时间；客户只能看本租户已发布版本。
5. 月费、人力单价、FTE或分母缺失时展示未知，不填演示毛利；默认工时与真实填报工时分列。

通过要求：老板版月报生成≤10秒按M9-3及Q13环境测试，不把该指标扩大成所有报告的合同限制；体检权重、参照薪酬和年度复盘分别等待Q23/Q24/Q11。

## 四 性能及可靠性验证

下表保留合同及旧详细设计中的独立目标，不能用平均值替代分位数，也不能用一个较低可用率覆盖其他条款。所有实际结果留空至执行。

|项目|目标或待定边界|执行方法|
|---|---|---|
|业务并发|正常100、最高1000；服务P99≤2秒|Q13确认接口比例、数据和时长，预热后记录完整直方图、错误率和资源。|
|资源|峰值CPU≤60%、内存≤80%|记录每节点及聚合曲线，说明是否含外部系统。|
|监控吞吐|12,500 NVPS持续24小时；25,000持续30分钟|验证丢失、积压和延迟，不只记录发送端速率。|
|页面与操作|首屏<2秒；客户确认<5秒；命令检索<3秒|分别测真实客户端、API和外部调用，包含样本数。|
|导入与报告|500行≤60秒；老板版报告≤10秒|记录文件、设备规模、模板与渲染版本。|
|通知|事件至渠道受理P95≤30秒；受理至送达P95≤30秒；电话30秒内发起|三段分别计时；M8-3按100条样本；无真实回执不得算送达。|
|可靠性条款|99.99%、单次中断<1小时、不允许数据丢失|对象与时间边界按Q04，不擅改。|
|试点目标|控制层99.9%、RPO≤15分钟、RTO≤60分钟|Q04明确适用范围后做故障与恢复演练。|
|试运行验收|可用率≥99.5%、误报率≤5%|冻结分母、维护排除及误报判定规则；保留样本。|

容量示例输入不是客户实测规模。Q13未确认试点设备、监控项、采样频率和增长目标时，容量页面只能输出注明输入的估算。

## 五 部署与回退执行步骤

1. 核对客户批准的组件、环境清单、域名证书、端口、账号权限和秘密引用；预生产与生产隔离。
2. 生成不可变制品、依赖锁、许可清单、应用与数据库版本对照、校验哈希；保存本次配置版本。
3. 在与目标环境相符的验收环境执行首次安装与升级；记录全部命令、日志和运行用户。
4. 上线前备份业务库、对象引用、配置、模板和队列/outbox水位，抽样恢复验证备份可用。
5. 在客户确认的窗口执行必要的写入限制、迁移、API/Worker/前端发布和健康检查；迁移失败立即停止后续步骤。
6. 用指定测试租户回归接入、事件、工单、客户确认和报告；不能向真实客户发送未授权测试消息。
7. 发生回退条件时按演练方案停止写入，恢复兼容应用和数据状态、队列及配置；不可逆迁移使用已验证恢复路径。
8. 回退后核对工单、事件、附件及报告引用完整，重放未处理outbox且不重复建单；保存实际RPO/RTO。
9. 按合同正文从全部功能上线之日起进入30天试运行，维护每日记录和缺陷处理；合同允许客户按质量情况延长。附件中的起止及验收衔接差异由Q12确认，不另设文档批准作为起算日，上线不代替最终验收。

两地三中心及零数据丢失要求需在Q04/Q21落实实际资源和复制方案。单机Docker Compose、应用多副本或定时备份均不能自动证明这些要求已满足。

## 七 本轮文档检查范围

本轮检查包括：合同128项编号和来源完整性、31个原型页覆盖、Q编号引用、Markdown本地链接、核心OpenAPI引用和请求结构、未确认配置空值，以及HTML阅读版生成。检查脚本结果保存在 `evidence/document_validation.json`。

本轮不包括生产代码构建、业务用例执行、外部接口联调、数据库越权、性能或灾备测试。上述验证均按本文件执行并单独留证。
