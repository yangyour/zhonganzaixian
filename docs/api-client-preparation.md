# API客户端派发前取消与清理

2026-10-05，基于225faeb及其包含的aef0bd1。

## 修复

- `requestResult` 的随机标识、表单/JSON准备移入try/finally；异常仍释放内部控制器和外部abort监听。
- 固定初始signal，调用方后续修改options不改变清理对象或最终取消判定。
- 已取消的JSON、带时钟GET和二进制GET不调用transport；JSON序列化完再次检查上下文代数和abort，避免toJSON期间失效后仍调用transport。
- 不改变CSRF、同源cookie、禁止redirect、显式幂等键、multipart或响应真实性校验。未加入自动重试。

## 契约与限制

服务端API仍0.44.0，无路径/schema/迁移变化。已调用transport后的错误仍为status=0 NETWORK_ERROR，不能据此推断写入未发生。准备失败也保守沿用这一客户端错误分类，不伪造HTTP400或服务端trace，不回显底层错误正文；因此本切片没有为上层写模块增加“确定未发送”的新恢复授权。AbortError也不是此前未知请求未提交的证明。跨刷新持久化、服务端请求级租户版本绑定及多标签顺序不在此切片内。

## 证据

9项新隔离测试；首轮8项中7失败、1通过，证实旧行为，随后增加序列化抛错清理覆盖。最终1694 Web测试/99文件、类型与生产构建通过，125契约及生成一致性通过。测试transport全部为隔离替身，不代表真实HTTP、浏览器事件循环、PG、OSS或正式验收。原指定服务器新41项PG记录来自远端提交，niko本轮没有执行它们。128项正式验收仍NOT_RUN。
