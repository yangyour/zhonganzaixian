# 当前租户设备登记配额

本批继可信来源导入之后，将设备配额硬门禁接到 `PostgresPlatformRepository.insert`，覆盖现有手工新增与新33列导入两条真实资产登记路径。计数包括当前租户全部已登记资产，包括草稿；未把尚未实现的监控项、NVPS或开通预留计入。

只消费当前租户已审核发布并处于有效时间内的 `tenant.contract_device_quota`。未知、禁用、过期、非整数、负数或超安全整数范围返回422 `ASSET_QUOTA_CONFIGURATION_REQUIRED`；没有无限额或本地回退。0额度、已用等于额度、缩容后已用大于额度都拒绝新增，返回409 `ASSET_QUOTA_EXCEEDED`，不会删除已有资产。有效配置值由用户另行确定，本批未替客户填写。

同一受保护事务先锁运行配置键，再锁租户资产准入键，然后读取有效限额和资产数量，最后插入资产并提交回执。导入使用同一锁次序，在整批预查后逐行复核，配额写入与配置发布串行；失败回滚也自动撤销本事务创建的资产槽位。不同租户使用不同键。站点不存在仍先返回404，不把无权引用暴露为某租户的配额状态。

手工入口 `POST /api/v1/assets` 的API契约已标注配额必需及原子资产计数。既有授权、CSRF、幂等回执和资产草稿状态保持。成功请求重放不新增资产，因此不会重复占用额度；当前成员关系仍按原框架在回读前核验。

代码无需新表或迁移；复用指定测试环境既有 PostgreSQL 与运行发布历史。隔离JDBC测试覆盖锁顺序、无配置/禁用/过期/畸形值、0/已满/降低额度以及SQL失败传播。指定PG外层回滚案例扩展为：先批量导入占满2个槽位，再以手工入口被拒绝，发布3个槽位后相同失败键可重试成功；全部是全新隔离租户，结束回滚并检查无租户残留。

真实多连接竞争、真实提交后的崩溃恢复、性能和正式TC仍需独立验证。此计数机制不替代后续耐久开通预留/释放、服务档位、监控项/NVPS计量、租户保留审批和删除治理；这些工作未被标记完成。生产隔离及真实客户配额值仍待确认。
