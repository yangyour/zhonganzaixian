# 台账导出：显式发布与授权下载

2026-10-14，实际API 0.47.0，指定内网测试环境 `lan-test-20261008`，PostgreSQL17.9/V30、既有MinIO。此功能补齐M3-7的“已准备文件→对象存储核验→当前用户签名链接→实际下载”子链。原准备请求仍明确为 `PREPARE_ONLY_NO_PUBLICATION`，不会因为部署新版而自动上传历史任务或向客户发信。

已与横排菜单一起部署至[指定测试站](http://192.168.1.215:10010)，应用代码基线 `fd1e8f1`。公开入口另完成9次HTTP复核，实际下载摘要保持、原过期链接404、既有基础监控可读；API/Web之外10个服务的镜像/启动时间/重启次数不变。候选API、本机验证隧道和开发服务器已清理，服务端12服务仍运行且发布能力ready。部署、公开入口与最终组件证据分别见[部署记录](evidence/export-navigation-deployment-20261014.json)、[公开HTTP](evidence/export-navigation-public-http-20261014.json)、[最终组件](evidence/export-navigation-components-final-20261014.json)。

## 已实现

1. 独立发布状态读取及发布按钮。用户确认文件版本和SHA256后，才发布这一份不可变XLSX，不重新读取台账生成另一份文件。
2. 发布复核当前租户、创建人、实际成员/权限版本及内部角色。原准备租约未结束返回409，不抢占在途Worker；过期后显式取得新的5分钟技术租约和fence。文件、原请求、准备记录均保留。
3. 使用独立MinIO桶/受限账号和 `asset-exports/{tenant}/{job}` 前缀；单次条件PUT禁止覆盖，成功后按大小与SHA256读回原字节。并发相同对象或结果不明后，只能核查同一份原内容。
4. 发布成功、审计、幂等原收据与V20终态在一个受保护事务提交。对象存储不属于数据库事务；数据库回滚不表示对象未写入，因此503/响应未知保留原key/body，禁止新建替代文件。存储读写在有界请求内执行，未声称满足全量性能目标。
5. 已发布文件需要单独取得下载链接；900秒从数据库签发时刻计算。同key回放返回原有效期，不延长链接。HMAC绑定job、租户、用户、成员版本、发布版本和文件摘要；签名秘密仅在私有运行配置。
6. 下载要求当前有效登录与对象授权，MinIO读取前后均复核权限、有效期、发布事实及字节摘要；成功下载记审计，返回附件XLSX、`no-store`、`nosniff`，不返回存储坐标或存储凭据。
7. 页面有发布确认、独立刷新、取得链接和正常点击下载；未知结果只能用完全相同的请求恢复，并阻止自愿切换作业/路由/租户。强制授权上下文变化清除旧状态和链接。发布状态更新后同步重读准备进度，避免并列旧版本。

## 实际接口

|方法与路径（前缀/api/v1）|请求/结果|
|---|---|
|GET `/asset-export-jobs/{id}/publication`|读取本人当前租户发布记录，不读取MinIO、不直接给下载链接|
|POST `/asset-export-jobs/{id}/publication`|`expected_version`、`file_sha256`、`action=PUBLISH_PREPARED_FILE`；同步200仅在实际存储核验与事务提交后返回|
|POST `/asset-export-jobs/{id}/content-grants`|空JSON、CSRF、幂等键；返回平台相对链接、有效期、大小及摘要|
|GET `/asset-export-jobs/{id}/content?grant=…`|校验签名及当前授权，返回XLSX；跨租户/创建人统一404，过期/签名错误404|

未配置发布返回422；明确开启但配置/存储未就绪返回503。旧准备API和持久化原收据不被改写；其旧 `publication_status=NOT_IMPLEMENTED` 常量属于准备视图的兼容边界，**当前发布事实以新增publication资源为准**，不能拿旧准备收据推翻新的发布结果。实际OpenAPI见[当前契约](../contracts/local-api.openapi.json)。

## 私有运行配置与组件边界

- `MOP_EXPORT_PUBLICATION_ENABLED=true` 显式启用。缺省关闭，不自动发布历史任务。
- 使用已选 `OBJECT_STORAGE_PROVIDER=minio` / `OBJECT_STORAGE_ENABLED=true`、实际端点和区域；本批导出发布只实现MinIO，配置其他提供方不会静默回退。
- 必须单独提供 `OBJECT_STORAGE_EXPORT_BUCKET`、`OBJECT_STORAGE_EXPORT_ACCESS_KEY`、`OBJECT_STORAGE_EXPORT_SECRET_KEY`，不继承照片/导入/通用账号。
- `MOP_EXPORT_DOWNLOAD_SIGNING_KEY` 为私有Base64编码32—64字节随机签名密钥。重启时保留同一密钥才能保留尚未到期的已签链接；轮换会使旧链接失效，不自动迁移对象。
- 本次在既有MinIO新增有项目归属标签的 `mop-test-asset-exports` 桶和受限账号，只允许桶查询及导出前缀Get/Put；真实Delete、前缀外写、其他桶读取均拒绝。没有改变原照片/导入桶、已有账号权限、服务端口或基础服务生命周期。
- API的ready新增独立 `export_publication` 能力状态；显式启用但配置/存储不可用使整体未就绪。桶探测是依赖就绪，不是某个导出对象已存在或某个任务已完成的证明。
- SQL迁移为0，V1—V30字节不改。API/Worker不自动迁移。回退时恢复原API/Web版本和原私有env，保留新桶、对象、历史及审计，不删除数据。
