# 资产扩展资料：完整草稿与目标替换确认

## 已实现保护

- 记录采用版本时的完整原始表单基线，未改动不反复打断；任一实际输入改变即标识为未保存草稿，不裁剪空格或归一化日期后再比较。
- 重新基于当前版本编辑、取消编辑、更换资产、路由离开及自愿切租户/退出均核对完整快照。未知PATCH只能恢复原请求，不提供“放弃未知结果”确认。
- 对话框单次进行；确认期间原始字段、查询文字、基准、当前资料事实或权限上下文变化，使旧确认失效。读最新档案期间又出现新输入，也不清空后采用旧决定。
- 路由在beforeResolve最后阶段再次复核，后续路由守卫或其他上下文守卫改动输入会取消原离开批准。浏览器卸载对脏草稿与未知写入均提供原生保护。
- AssetsPage与真实metadata子组件联合核对：确认后再次比较原目标全文、当前详情选择、来源查询开关、编辑器实例/输入和授权范围；新一次选择使旧的待确认选择失效，包括新选择只是重新打开原资产。
- 重新打开同一资产只展开保留的草稿，不无故清空或重复确认。收起drawer也只隐藏，不销毁输入。强制会话/权限变化仍同步清掉旧范围数据，不因草稿阻止撤权。
- 父资产台账观察到更高版本时禁止用旧编辑基准提交；读取失败或取消只表示版本尚未核对，不伪称“已检测到版本更新”。

## 分层验证

新增16项编辑/确认/真实内存路由回归，旧实现16项全部失败；新增9项实际AssetsPage与metadata子组件联合回归。额外发现并复现“旧跨资产确认可覆盖后来同资产打开”的竞态，加入选择epoch后通过。

确认决定由测试控制、drawer外壳及无关工作区为桩；输入/按钮、Vue状态和内存路由守卫实际执行。它不证明浏览器模态焦点陷阱或辅助技术验收。全量前端275文件/4603测试、Node契约179项、类型检查及生产构建见证据；真实浏览器105项/12文件仍NOT_RUN，128正式TC仍NOT_RUN。

首轮联合测试的8个失败来自无关维保桩未暴露hasUnresolved，补齐桩公开契约；首轮类型检查的确认返回值mock按库的Awaited返回类型修正。全量首轮4601通过/1失败为旧静态源码断言未支持带inputSnapshot的guard注册，保留拒绝无条件放行和卸载解除断言，并补识别完整快照回调。以上失败和修复不掩盖为首轮全部成功。

本次不修改后端、SQL、客户默认值、账号或真实资产；维保/依赖工作区各自尚未补齐的草稿保护不因此改称完成。证据位于docs/evidence/asset-metadata-draft-protection-20261022/。
