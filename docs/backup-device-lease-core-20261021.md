# 备份设备协调租约：失联与过期边界

基线 main ef09a45674bb197457003b15cfb32bc0c82f175f。依据 doc/development/02 的 M6-D01 同租户/设备互斥要求及既有 BackupRunState 的未知结果门禁，先落实状态与结构恢复规则，再接持久化。不是分布式锁、设备授权或备份执行完成证明。

## 状态规则

- 明确tenant、asset、request、worker owner、观察时间和租期；没有推测租期默认值。1ms—5min为技术保护上限，非客户业务值或已发布配置。
- HELD在截止时刻之前才有协调令牌效力；到达截止时刻以及以后为RECONCILIATION_REQUIRED。不能因时间过去自动重领、续租、释放或判定SSH没有执行。
- 正常续租/释放要求当前逻辑版本、owner、fence及单调的可信时间，且尚未过期。同一观察时刻的续租不制造新心跳。
- 只有明确RELEASED后才能接受新request，fence与版本递增；旧owner/token不能继续协调。释放调用者必须先独立确认该请求不会继续在设备执行，超时不是该确认。
- 快照结构恢复核对ID、计数器、毫秒时间范围、租期、截止与释放一致性；恢复对象仍不是完整历史证明。数据库必须另外保证租户/设备存在、完整历史、CAS、请求重放唯一性和原子互斥。

所有状态的 deviceExecutionAuthorized、distributedLockVerified、expiredTakeoverAllowed 均false。这里只表达协调事实，不能用一个Java对象或fence值声称SSH进程已被远端隔离。仍需持久事务、独立授权、主机信任、真实停止/核查证据及Worker接线。

## 接续门禁

后续持久化按租户+设备串行化，保留不可变事件及原请求身份。过期且结果未知的持有记录继续阻塞；在核查适配器与证据没有接通前，不新增“强制解锁即安全”或盲目重试入口。Q22失败计数口径仍null，不创建P3工单，不选择凭据/KMS/设备命令。

本步没有SQL迁移、公开API、Spring自动装配、调度、设备调用或配置发布。计划的数据库CAS/多连接互斥尚未完成，不将纯模型标成真实锁。

测试初始路径不属于现有JUnit测试模块，已迁入server/api的测试源目录；领域模块保持无JUnit依赖。测试目录和编译失败留在本地日志，不记作已通过结果。

缺少的协调租期策略、可信数据库时钟/日志、过期执行停止核查器和物理隔离/停止协议均追加为backup-execution-dependencies.json中的null引用；模板开关仍false且不会被运行时消费，不把占位引用当作已经发布的配置。
