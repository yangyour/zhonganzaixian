# 备份运行状态恢复与规范存储载荷（2026-10-21）

本步是运行记录持久化的前置代码，不是运行仓储、数据库事务、计划 Worker 或真实备份执行。V1–V46 不变，没有新迁移、API 路由或自动装配。

## 状态恢复

BackupRunState 新增不可变 Snapshot 与 rehydrate，恢复时核验：

- 租户、设备、UTC 毫秒时间、跨端安全整数版本、最多三次尝试；空队列只能为逻辑版本 0。
- 尝试编号连续，开始不能早于入队；只有已明确 FAILED 的前一次尝试才可跟进下一次，并保留至少 10 分钟间隔。
- RUNNING 没有凭空心跳；第一次 RUNNING 仅可能为版本 1。未知观察可以多次发生，逻辑版本至少满足已知最少转换数，不声称可从最终快照还原全部事件历史。
- 持久化版本引用仍须同租户同设备，并处于该次尝试的开始和完成之间；成功引用的格式不证明实际对象已加密、存储或可访问。
- 重试等待不能溢出支持的时间范围。UNKNOWN 恢复后仍须核查，不能变回队列或因过了 10 分钟而重新执行。
- 原状态机的一初始尝试/两重试、未知不算失败、终局不可重开、Q22 未确认及 automaticTicketAllowed=false 均保持。

## 规范载荷

编码器位于 mop-persistence，保持存储层不依赖包含邮件、对象存储、PDF 等外部适配器的模块。BackupRunSnapshotCodec 使用 MOP_BACKUP_RUN_SNAPSHOT_V1 的有界二进制载荷，绑定独立 runId、tenantId、assetId 与运行快照，仅包含元数据，不包含配置正文、密码或密钥。

- 解码前限制 4096 字节并核对 SHA256；解码后核对外部传入的预期运行/租户/设备身份、完整状态结构与重新编码的逐字节一致性。
- 拒绝未知格式、截断、额外尾字节、非规范 UUID/布尔编码、越界尝试数、坏时间、坏逻辑版本和篡改摘要。
- Document 构造与返回字节防御性复制；坏载荷统一返回安全的 BACKUP_RUN_SNAPSHOT_INVALID，不输出原载荷或底层异常细节。
- 单独用 Python struct 的大端 ASCII 编码构造固定队列黄金向量，Java 编码与解码必须逐字节匹配；黄金向量 SHA256 为 3c1123f1a2715e839a69f0711ba57b32a4c55b34ccde4bc0a9e8b9159a4400f6。

SHA256 是完整性校验，不是签名、来源认证或授权。可信预期摘要/作用域必须由后续授权仓储提供；攻击者同时替换载荷和全部可信元数据不在此编码器的防御证明内。快照也不证明数据库 CAS、完整审计链、设备租约或远端停止。
