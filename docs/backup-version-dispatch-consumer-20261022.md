# 原命令版本登记消费者（2026-10-22）

## 实现边界

新增 `BackupVersionRegistrationDispatch`，连接已存在V49登记/父运行完成事务；不是轮询调度器，不生成命令，不自动Spring装配，不自动从归档状态猜测可执行计划。

- 绑定默认禁用；启用必须显式 `backup-version-dispatch:` 引用与独立当前授权回调。读取原登记、调用登记及返回结果三个边界均复核。
- 调用者必须耐久保留原scope/commandId/run版本/archive版本/lease/object证明引用/execution证明引用；消费者只接收这一个明确命令。凭据、端点、命令文本不通过引用槽位传入。
- 首先独立授权读取原登记。已有完全匹配记录只返回历史登记/运行完成证据，不重复对象验证或登记，不要求重新上传。
- 未见原登记才调用原仓储register。对象独立回读及采集完成前提核验、SQL幂等/CAS/同事务提交仍由已有仓储负责；公开构造器不能注入空授权或假写入端口。
- 登记方法返回异常或畸形回执时保持RECONCILIATION_REQUIRED，不推断回滚、不新建ID、不自动连发。后续明确调用先读同一原登记；若未提交，可再次提交同一原命令。
- 回读不匹配scope/command/run/archive/lease/证明引用/原登记人时不追加。异常读取不是“未登记”；错误输出不包含底层私密异常。
- 结果仅为数据库历史登记及运行完成记录，不证明当前对象健康、设备执行授权、保留策略或恢复验证。不释放设备租约、不PUT、不重新加密、不触发失败工单。

## 配置与仍缺代码

`version_registration_consumer_binding_reference` 保持null，执行和生产批准仍false；与已有登记授权、对象回读、采集完成证明和服务装配引用并列，不能用新引用代替这些独立前提。32个依赖引用均保持null。

仍缺耐久任务发现/队列及调度装配、真实授权/采集证据/供应商适配、失败工单、下载/保留清理/演练等。此消费者不能把整条生产备份链标为完成。

## 测试分层

- 21项消费者逻辑回归：禁用无IO、精确原命令、已有登记、未知提交/丢回执、畸形结果、权限变化、引用/版本/租户/原登记人不匹配及错误脱敏。
- 4项显式门禁的实际PostgreSQL测试：真实V1–V50隔离库、实际JCE及原归档/登记仓储；只用合成KMS、内存对象存储和采集证明。
- 默认Maven会跳过这些实库测试；实际门禁运行与默认跳过计数必须分别记录。原有归档测试基架仅复用准备逻辑，不将它的5项测试重复记为新增。
- Python依赖槽位新增1项；Node契约与全套后端回归另记。

首次隔离库尝试在初始化4版迁移前因复用旧测试门禁标识停止；临时库及凭据已清理。给本次初始化助手设置独立且精确的新门禁后，在新的隔离库重新执行，不放宽生产迁移器。V1–V50内容保持冻结，未创建或修改SQL。
