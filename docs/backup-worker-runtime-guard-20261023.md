# B01 备份后处理入口数据库权限守卫

复核发现 `BackupWorkerMain` 虽校验连接配置中的用户名，并做设备/操作授权，但仍直接构造 HikariDataSource。仅有用户名不证明实际连接未被赋予 superuser、角色创建、复制、BYPASSRLS 或迁移账号继承能力。

现改为复用主干 `RuntimeDataSources.openRestrictedTest`：配置与真实连接权限检查必须成功，才进入备份任务的数据库授权、存储/KMS就绪检查及调度器构造。保留原连接池与超时上限、签名证明、独立任务授权、停止/关闭资源和 check-only 行为。失败不回退为未检查连接池；不改角色权限、不创建凭据、不启用采集/恢复/删除。

新增 worker 测试模块的 Mockito test-scope 依赖，复用现有父级版本管理，不进入生产包。5项入口测试核对生产重载确实调用共享受限工厂、无效配置在工厂前拒绝、原有有界配置保持、权限失败不降级；另有2项原配置与3项共享数据库守卫测试，共10项通过。

独立从最新 origin/main `bb00bc90` 检出后，只加入本次工厂接线、测试和测试依赖，再执行同样10项通过，不依赖当前dot尚未上传的大契约及其他本地功能。无 API/前端/迁移变化；主干无自动部署工作流被调用，本次没有部署。

实际指定 PostgreSQL 权限复验、真实KMS/OSS、非空备份任务/签名证明仍待受控环境配置；上述mock/工厂测试不是实际联调。B01/B02剩余生命周期、恢复申请、清理及真实交付继续开放。
