# 容量估算取消、输入保护与派发前范围门禁

## 本次功能

- 主容量页新增只读估算取消，保留全部显式输入（包含合法 `0`），中止旧请求并拒绝迟到结果；取消和确认重置后返回主机数输入。错误提供“以当前输入重新估算”，不悄悄使用旧参数。
- 重置、路由离开和自愿切换上下文前确认丢弃当前内存参数；刷新/关页使用 beforeunload。弹窗等待期间输入或范围变化会使旧确认失效。强制撤权仍立即清旧范围，不以确认弹窗保留已无权的数据。
- 主页、增长推演、运行参数和保存方案面板均将 Session 顶层 account_version 纳入范围键；相同身份/版本仅更新 CSRF 不抹掉输入。
- 增长推演在首个请求、每个后续请求和最终发布结果之前检查取消/范围；回调中的取消不会继续计算下一档，不显示不完整曲线。
- 方案 GET/POST 在忙碌通知之后再检查范围；幂等键生成期间换范围不会把旧输入提交给新租户。原有未知写入/原回执语义不变，GET 不证明写入成功；已经销毁的工作区不能重新激活。
- 页面说明文字的显式前景色提高对比度，控件目标高度44px、焦点轮廓和状态通知进入源码。这里只验证指定颜色组合，不声称全站或全部主题已满足 WCAG。

## 验证与成熟验收基线

沿用 [前端验收标准](frontend-acceptance-standard.md) 的任务可完成、错误恢复、输入保护、上下文隔离、键盘焦点、状态语义、触控与证据分层门禁。新增20项，前端全量3399项/225文件通过；构建、发布工件和候选安全策略检查通过。4项本地 Vite HTTP200且检查了返回内容，已停止服务。没有 API/数据库业务写入。

DOM环境验证真实Element输入/按钮事件、确认取消、焦点返回、beforeunload及清理；这些不是浏览器键盘/视觉/axe结果。Chromium及浏览器矩阵仍因既有环境限制 NOT_RUN，未重试已被拒绝的绕行。320/390/768/1440视口、辅助技术、真实参数导入和正式容量压测均未据此改标。所有128项正式TC仍NOT_RUN。

保留两次早期类型检查失败：第一次错误地把 account_version 写在 user 下，按既有 Session 契约修正到顶层，并修改合成测试而非扩充接口；第二次为Element确认框类型交叉声明，测试按其函数返回类型断言，生产逻辑未放宽。最终构建标识见证据。
