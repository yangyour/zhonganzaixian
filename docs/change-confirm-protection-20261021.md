# 变更草稿与审批的异步确认保护

## 修复范围

遵循[前端功能与交互验收标准](frontend-acceptance-standard.md)的安全恢复、输入保护与身份范围门禁：

- 新建、按版本编辑、关闭、离开及归档/恢复确认均绑定原始草稿快照。弹窗期间继续修改摘要、时间、目标、查询或工单引用，旧确认即失效；工单UUID规范化不能掩盖原文改动。
- 归档/恢复第二次确认后重新核对原草稿、范围、在途候选读取与审批未知状态，不清空新输入或发送过时命令。
- 组合页面离开先核对草稿，再核对审批。任一弹窗期间另一个面板的新输入也使离开失败；前后两次确认都未变的输入仍可正常离开，不自动保存或发送。
- 审批面板的说明、固定草稿修订与审批基线都有快照保护。候选修订在弹窗期间变化不能悄悄重新固定；页面卸载后的旧确认无效。
- 父级草稿写入未知时，审批重新选择按钮及调用都受阻，确认过程中出现未知状态也不清空原说明。既有审批命令确认继续核对原说明、版本、目标和当前权限。
- 资产候选读取发出GET前再次检查范围/撤权/取消，防止同步状态变化后仍派发旧查询。既有原页重试、独立取消和状态焦点继续保留。

不新增API、权限、审批自动化或数据库迁移；内部批准仍不等于运行生效、设备执行或告警抑制。
