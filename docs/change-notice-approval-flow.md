# D10 精确修订审批接线（API 0.58 / DB V38）

## 本次已实现

报备草稿的精确修订可提交、撤回、批准或驳回，审批历史只追加。审批绑定 notice ID、修订、原文摘要、操作版本、当前身份和已发布 Q09 审批策略；拒绝自审、失效成员、陈旧草稿和未配置的审批人。

审批时间由 PostgreSQL 在授权锁之后生成，和策略有效/到期判断使用同一时刻；数据库返回的时刻用于回执与回读。不能用请求时间回填批准记录。V38 已真实应用后冻结，后续 SQL 修改需 V39+。

- 接口：精确修订的 `/approval`、`/approval/history`、`/approval/actions`。
- GET 在同一只读一致事务中返回快照和 `allowed_actions`；前端不从角色推断审批权限。
- 写动作在已有平台幂等事务中重新验证身份、草稿版本和当前策略；返回的原始回执不冒充当前权限。
- 新 `change_notice.approver_policy` 只接受 1–1000 个规范、不重复的明确 reviewer UUID，默认 null；注册表 186 项，无默认审批角色。
- 原报备页面集成审批面板。未知写结果冻结原路径、修订、版本、正文和幂等键，只能重试相同请求；切换草稿、关闭窗口及其他未确认写入均有保护，不自动改变请求目标。
- 缺少审批表/权限/结构时，`/health/ready` 返回 503；正常仅声明审批结构可用，不声明业务生效。

## 真实验证

- V38 首次应用 1，重复/只读 0；89 张已有表行指纹不变，配置表仅有预期新 null/pending 键，新增一张审批事件表。
- 21 项真实 PG 测试通过：陈旧修订、自审、权限/策略撤销竞态、时间伪造防护、回执一致性、只追加记录、CHECK 定义篡改检测和会话设置恢复。
- 同一 API 制品 43 项实际 HTTP 检查通过：登录、readiness、草稿/审批提交、双人配置创建/审核/发布、批准/驳回/撤回、CSRF、幂等回放、CAS、历史分页、跨租户 404 和新修订审批重置。
- 集成后九模块 Maven verify 通过：3213 项发现、2285 项执行、928 项有意跳过，零失败/错误。独立真实 PG 结果另计，不能与单测简单相加。
