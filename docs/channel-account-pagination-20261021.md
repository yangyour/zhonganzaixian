# 通道绑定账号分页与搜索

基线：9c283c9bab762f98d4f43180febe6836d0b9395a。仅补齐现有邮件/企业微信绑定工作区，不启用真实通道。

## 可用性变更

- 平台账号选择支持上一页/下一页和服务端搜索，沿用身份 API 的50条页大小、1–10000页和100字符搜索上限；不通过一次加载全部成员绕过分页。
- 搜索始终回到第1页，UTF-8关键字和保留字符用URL编码传输；只请求启用账号及启用成员关系。下拉框自带筛选只筛本页，服务端搜索有独立明确按钮。
- 账号页使用现有严格 readUserPage 校验，额外拒绝页码不符、重复账号和停用选项。绑定提交核对所选账号确实存在于当前验证页，邮件地址仍须在允许列表。
- 切页/搜索必须先处理未保存绑定；取消保留原输入，旧范围确认不能清除新范围输入。成功读取后焦点返回搜索框，页面加载状态有 aria-busy。无匹配数据有明确提示，不当作错误或全租户零账号。
- tickets:read 控制发送记录读取，users:read 控制配置/绑定读取；前者缺失不再导致整个配置工作区不可用。撤销发送记录权限立即清除旧记录，页面明确提示无权限，不伪装成空记录。

## 验证分层

- 原27项恢复测试保留，新增16项DOM测试覆盖分页、编码搜索、分页范围重置、无效账号选项、第二页账号的实际下拉选择和绑定请求、取消/过期确认、发送记录权限独立。
- 第二页绑定测试的请求由合成409响应终止，不创建实际绑定。
- 使用本机独立PostgreSQL/API生命周期生成60个合成账号，其中账号停用和成员停用各1个；验证启用列表50+8分页、去重、空搜索、租户隔离、未授权与无效请求。17项实际HTTP检查通过；4份实际响应由生产readUserPage再验证。运行结果见 evidence/channel-account-pagination-20261021.json 及 channel-pagination-api-20261021 证据目录。
- 真实浏览器/axe、真实通道发送及供应商核验未执行；没有部署到原测试站。Java/API业务实现未改动，本轮不是完整Java回归。

## 未解决边界

绑定列表后端仍最多返回200条，历史发送列表最多100条。选择超过50个账号的问题已补，不代表200条以外的既有绑定更新链路也已完成；需增加按目标账号读取既有绑定版本，不能凭列表未出现就断言没有绑定。真实授权仍由服务器每次请求复核。
