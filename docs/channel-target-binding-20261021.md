# 通道精确绑定读取与版本保护

基线 main：aa9bcd0003607e5e58c525652f4ccf84ccedcfea。API契约从0.72.0推进到0.73.0，不变更V1–V45迁移。

## 解决的问题

概览绑定列表最多返回200条。以前页面从该列表查找选中账号，未找到就提交 expected_version=0；第201条既有绑定因此被误认为新绑定并冲突。

新增 GET /email/bindings/{userId} 与 GET /wecom/bindings/{userId}，按当前租户、当前发件通道/企业和目标账号读取完整绑定版本，独立于概览条数限制。只有目标是本租户成员且确实没有绑定时才返回 binding:null；未知或其他租户账号返回404。读取需要users:read、有效会话和即时成员权限，不调用供应商、不创建绑定、不写审计之外的业务数据。正常成功读取完全只读，非法请求由既有安全审计处理。

## 前端工作链

- 选择账号后独立读取精确绑定；加载、明确未绑定、已绑定、失败均有不同状态，失败可重试。
- 未成功读取或范围/版本校验不通过，保存按钮禁用；不回退概览列表、不把失败当作版本0。
- 精确结果显示当前绑定目的地，并提供独立“停用所选账号绑定”入口；确认明确提示放弃编辑及企业微信会话失效，取消/过期确认不提交，停用不依赖200条概览。
- 提交使用精确结果中的版本；服务器仍执行CAS，读取后发生并发修改会返回冲突，不自动覆写或重试新意图。
- 目标账号、租户、角色、模式或权限变化中止旧读取，迟到响应不能带入新范围；页面卸载释放请求。
- 读取器检查租户、目标账号、通道标识、精确字段、UUID、正安全整数版本、UTC毫秒时间、收件地址/成员格式和明确null，并返回独立副本。
- 企业微信既有成员不能通过此入口替换，界面显示原UserID与约束，成员不匹配或输入非法时禁用保存并解释原因。未声称真实成员或邮箱归属已验证。

## 验证与边界

27项实际HTTP检查与9项独立PG测试通过，4份真实响应另由生产前端读取器回放核对。最终结果见 evidence/channel-target-binding-20261021.json。后端10项新增控制器测试；独立PG类9项覆盖第201条绑定、明确未绑定、通道隔离、跨租户/未知目标、权限与旧权限版本。前端读取器与原生DOM覆盖版本7不在概览时仍按7提交、失败不能提交0、重试、取消/迟到、目标变更、成员不匹配及原有分页保护。

初次构建命令使用错误工作目录未执行成功，后续纠正到仓库根；控制器新增测试有两处Mockito matcher嵌套错误，修正测试后完整构建通过。首次PG回归的合成corp标识不符合既有数据库格式约束，同时将合成verified_at改为稳定时间以避免时钟取整边界，保留首次失败记录，未修改或放宽任何数据库约束。

真实浏览器与axe继续NOT_RUN；实际SMTP/企业微信认证、发送、绑定变更和客户环境部署未执行。绑定概览仍限定200条，发送概览100条；此次只解决选择目标的准确读取/版本提交，不把概览当全量报表。合同128项仍NOT_RUN。
