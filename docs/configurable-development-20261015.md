# 待确认项配置化与开发接续

用户2026-10-15要求待确认项全部配置化、先开发完整。现有185项登记覆盖Q01—Q31，其中108项待确认；阻塞点是登记/内部审批未接运行发布来源，而不是缺少一个保存JSON的入口。

实施顺序：配置目录与值校验 → 明确的运行发布/失效/回滚与历史 → 配置管理页面 → 业务读取有效值与创建时快照 → 指定测试环境验证。每项实际完成后追加证据并独立提交。未知业务值不补默认，外部凭据保存秘密引用，合同固定约束不开放修改。配置化不会把采购、客户签署或第三方设备权限假称为已完成。

运行配置首先使用当前授权租户隔离；设计登记上的“平台/设备/服务”等标签不自动授予跨租户写权限。发布记录与原提案分离：内部提案APPROVED保持原含义，发布记录明确测试运行作用及版本，不冒充客户证据核验。计划生效、到期、禁用和回滚均保留不可变发布历史。

## 已验证：API0.50与运行配置中心

目录覆盖185个键、31个Q编号，108个待确认项的登记值仍null；固定合同约束只读。配置值按登记类型、已知数值范围/枚举/时间及无损数值/深度/秘密字段限制校验；定义摘要规范排序并绑定实际校验结构。可配置对象仍允许保留未知字段，具体业务执行需要其消费方校验完整性，不能仅因值已发布就声称外部动作已完成。

新增接口：GET `/runtime-configurations/catalog`，GET `/{key}`，GET `/{key}/history?before_version=`，只读POST `/{key}/validate`，POST `/{key}/releases`（以上相对`/api/v1/runtime-configurations`，目录路径除外）。发布必须明确原批准提案/版本、当前发布版本、当前定义摘要、立即/计划生效、到期和理由；原提案审核通过不直接发布。回滚复制历史值生成新版本，不删除或改写过去记录。配置定义变更后旧值不继续按新定义运行，要求重新校验发布。

前端入口 `/runtime-configurations` 支持配置键/说明/Q编号筛选、固定约束、已批准提案选择与校验、发布/回滚/禁用、有效值独立回读和历史分页。默认不选择提案，写结果未知保留原body及幂等键、阻止换键/离页，旧有效值立即清除；重试确认原回执后再独立读当前值。原配置登记页可直接带key进入运行中心，移除总是失败的“发布检查”和错误的全局“未启用”结论；旧登记诊断接口保留兼容并标deprecated，不再作为运行事实来源。

已验证：2157项前端回归；Java全量报告2756项，其中1874项实际执行、882项按环境条件跳过，失败/错误0；另6项指定PG验证独立记录。134项契约及生成一致性通过；候选真实API40次HTTP含CSRF、角色拒绝、额外租户字段拒绝、定义版本/CAS/幂等冲突、发布/回滚/禁用及响应Schema检查。浏览器实际完成提案保存、创建者提交、另一复核员批准、校验、发布回读、服务端已提交但HTTP回执丢失后的原幂等请求恢复；恢复得到同一个发布ID。手机390px无整页溢出。
