# 待确认项配置化与开发接续

用户2026-10-15要求待确认项全部配置化、先开发完整。现有185项登记覆盖Q01—Q31，其中108项待确认；阻塞点是登记/内部审批未接运行发布来源，而不是缺少一个保存JSON的入口。

实施顺序：配置目录与值校验 → 明确的运行发布/失效/回滚与历史 → 配置管理页面 → 业务读取有效值与创建时快照 → 指定测试环境验证。每项实际完成后追加证据并独立提交。未知业务值不补默认，外部凭据保存秘密引用，合同固定约束不开放修改。配置化不会把采购、客户签署或第三方设备权限假称为已完成。

运行配置首先使用当前授权租户隔离；设计登记上的“平台/设备/服务”等标签不自动授予跨租户写权限。发布记录与原提案分离：内部提案APPROVED保持原含义，发布记录明确测试运行作用及版本，不冒充客户证据核验。计划生效、到期、禁用和回滚均保留不可变发布历史。

## 已验证：监控页面实际消费运行配置（API0.51）

`GET /api/v1/network-monitoring/refresh-policy` 仅允许当前用户的assets:read，固定读取 `monitor.page_refresh_sec`；不开放任意配置键、发布人或完整提案给普通查看者。无发布时使用已有合同30秒默认；发布值采用1—3600秒技术支持范围。明确禁用、到期、定义摘要变化或值无效时暂停数据自动刷新；真实依赖失败返回503，不以默认值代替失败。

基础监控、总览及资产详情监控组件实际采用此周期，另每30秒只读核对策略，禁用后也能发现重新启用；过期/过久未核对的策略不继续触发自动读取。权限拒绝清除旧监控内容并重新核对会话。同值会话刷新不重置原发布请求或重复启动读取，已新增实际页面setup回归。
