# 联系人与导入请求的发送前范围复核

## 问题与修复

既有客户端工作区在读取/写入结束后检查范围，已能拒绝迟到响应；但通知页面“正在读取/提交”的同步回调可能立即重置账号或权限，之后仍继续调用旧请求。创建幂等key的回调也可能改变范围，若仅在send入口取当前范围，会把旧输入错误地带入新范围。

三个工作区现补充发送前门禁：

- 联系人列表/详情/历史及单条写入、联系人导入作业读取/提交，都在状态通知之后、真正调用API之前复核epoch、卸载状态和abort信号。
- 新命令在校验输入前捕获原epoch；生成key后再次核对epoch/权限/在途状态/旧命令，不借用新账号范围发送旧输入。旧范围key生成异常也不能污染新范围错误状态。
- 只读格式预览在进入请求时固定原文，通知后先复核generation/取消/卸载，再解析固定原文与POST。同步编辑或范围替换不会让旧操作自动提交新输入。
- 原未知命令重试同样经过发送前复核。强制会话范围失效仍清空旧私有状态；正常范围内的未知结果仍只用原key/body重试，不被普通GET确认。

这是客户端防错和范围一致性门禁，不能替代服务端身份验证、当前成员权限和租户隔离。不改变接口、服务端授权、导入原子性、联系人规则或真实通知发送。

## 回归方法与边界

先增加24项回归并在未修复代码运行：18项失败、6项通过，确实复现通知重入、key范围切换及预览新输入误发送。修复后24项及既有58项工作区回归全部通过，再补2项未知命令重试范围失效测试。新增共26项，覆盖reset/换身份/dispose、读取/写入、key生成错误、预览编辑以及原命令重试；全部使用合成API替身，不触达真实联系人或供应商。
