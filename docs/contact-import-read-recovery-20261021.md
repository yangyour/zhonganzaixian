# 联系人导入作业与格式预览的读取恢复

## 恢复行为

- 我的导入作业列表失败/取消后保存原成对时间/ID游标；详情保存原作业ID。显式重试只恢复原读取，不退回第一页、不重发导入命令。
- 取消正在跟踪的作业GET同时停止前端计时器。手动重试不自动恢复每2秒刷新；需要再次明确选择自动刷新。停止读取不是取消/撤销服务器已受理的作业，也不证明Worker已停止。
- 只读格式预览虽然使用POST，但不会写联系人或受理作业。两处预览入口均可独立取消、保留原始JSON，并按相同解析内容重试本次诊断。修改原文即作废旧结果、重试目标和取消提示。
- 本地JSON解析失败时未发送请求，不显示虚假的“原请求重试”；实际请求失败或响应不合格才进入读取恢复。
- 原导入受理未知时，格式重试受锁定约束；作业GET恢复不改变原key/body、原202回执或未知受理状态。写入在途没有“取消读取”绕过入口。
- 新批次、范围重置、卸载与无效新ID作废旧恢复目标。作用域标识使用本地计数器，不把整段JSON复制为组件作用域字符串。

沿用[前端验收标准](frontend-acceptance-standard.md)的独立取消、可执行错误恢复、焦点及未知状态门禁，不新增后端API、权限或真实导入操作。
