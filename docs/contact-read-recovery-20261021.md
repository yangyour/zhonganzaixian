# 联系人列表、详情和历史的读取恢复

## 用户路径

按照[前端验收标准](frontend-acceptance-standard.md)补齐读取失败和取消后的恢复，而非要求刷新页面丢掉编辑输入：

- 列表查询失败/取消后可重试原姓名条件、记录视图及成对时间/ID游标；历史恢复使用原联系人ID和before_version，详情使用原ID。不会偷偷退回第一页或跟随新筛选。
- 新筛选文本与已提交条件分别显示；未应用筛选给出说明，原页重试不覆盖新筛选输入，且不会为不同条件启用下一页。
- 独立取消仅中止当前读取，取消后焦点进入状态说明。迟到结果作废，未保存联系人字段、原写入key/body、已确认收据不变。
- 写入在途不能被“取消读取”取消；未知写入不能被普通回读或原读取重试确认为成功，也不能凭读取解锁为新命令。
- 新编辑准备、写入、范围重置、卸载和无效新查询作废旧恢复目标；新编辑准备同时清掉过时取消提示。
- 加载提示不再把详情/历史读取误称为列表加载。列表未取得时显示数量未知，不把失败/取消当作零联系人；真正空列表与尚未取得列表分开。

仅增加前端恢复操作，不改API、业务上限、授权或联系人内容，不发送通知。
