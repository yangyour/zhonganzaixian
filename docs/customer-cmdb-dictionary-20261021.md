# 客户 CMDB 字典接入（2026-10-21）

## 本次完成

从用户指定的原始 XLSX 确定性提取 14 个工作表，生成 9 个 L1、16 个 L2、95 个不重复属性、枚举、关系类型、生命周期及来源规则。每个结构条目携带工作表和原行号，原文件不改写。生成结果同时用于 contracts/customer-cmdb-dictionary-v1.json 与适配层只读资源，两个副本必须完全一致。

- 工具 tools/build_customer_cmdb_dictionary.py --check 校验原始 Git blob、确定性生成内容与副本一致性；--write 仅更新生成 JSON，不执行 Excel 公式、宏、外链或网络请求。
- CustomerCmdbDictionary 在加载时核对整个资源 SHA256；返回不可变类型目录和独立文档副本。
- 分类校验拒绝未知主类型、“其他”兜底、未知子类型及父子错配；进入服务前必须明确子类型。类型合法不等于接入已通过。
- collectionMethod 只识别源枚举代码或明确显示名，不把 SSH 擅自当作采集方式，不自行大小写折叠或去空格改写。
- 所有结果保留 assetCreated=false、collectionStarted=false、productionApproved=false。

## 保留的源文档差异

以下是本轮已识别差异，不宣称已审完全部业务规则：

1. 实际有 16 个 L2，但表尾与属性枚举声明为 15。全部 16 项保留，不删 fw_adc。
2. fw_adc 明确没有单独的监控清单类型。分类可识别，监控映射仍为待确认；不会借其文字说明伪造已发布模板或监控授权。
3. 导入样例使用 SSH，而采集方式枚举只有 agent_active、agent_passive、snmpv3、http、sender。配置备份协议和采集方式不能直接混用。
4. 新字典 note 为可选，既有 AssetImportSchema 将 NOTE 标为合同必填。本次只记录冲突，不静默改写合同固定规则。

resolution 均保留 null。源文件输入不等于运行配置发布、合同变更、生产批准或第三方执行凭据。
