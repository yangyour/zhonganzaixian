# 客户拓扑与紧凑资源导航

## 用户入口

资源与监控 → 客户拓扑。使用页面右上已有客户/租户选择器切换已授权客户；只有一个授权客户时显示当前客户名称。不能通过 URL 或请求头扩大租户范围。

原入口“资产管理 → 设备详情 → 依赖拓扑”仍有编辑能力，按钮现明确为“编辑依赖关系”，旁边新增“客户拓扑”跳转，自动聚焦此设备。拓扑页可回到当前设备详情、资产列表或设备监控。旧资产、监控、事件 URL 不变。

本次前后端授权只覆盖此区域，其他前端仍由用户主导。基线为 main 625e6d2，已先同步上游资产页、列表导航和筛选组件，未回滚用户修改。

## 导航与工作区

保持既有顶栏、侧栏、配色及工作区样式，只在左侧用短小分组组织：

- 资产与拓扑：设备资产、客户拓扑。
- 监控与接入：设备监控、服务与设备接入。
- 告警与诊断：告警事件、阈值诊断、采样诊断。

运营总览保留。分组在权限过滤后生成，没有授权项就不出现；折叠侧栏隐藏分组文字，手机菜单共用同一组件。移除原“几项功能”计数，不增加统计卡片、欢迎区或解释大面板。

拓扑页直接进入操作栏和关系工作区。空客户只显示一行空态与真实管理入口，不绘制空白大画布。最多 24 个本页节点使用虚线有向关系图，超过时明确使用可滚动列表，避免拥挤图；图/表可切换。本页设备名称/IP 查找、清除查找、上下页、当前设备关联筛选及设备详情跳转可用，普通链接保留新标签打开行为。

## 数据含义与接口

API 0.83.0 新增 GET /api/v1/customer-topology，权限 assets:read。来源是已有 PostgreSQL 登记依赖草稿，不是 LLDP/CDP/SNMP 自动发现或已核验物理链路。

- scope=CURRENT_TENANT，lifecycle_status=DRAFT。
- physical_topology_verified=false、monitoring_applied=false 永远明确保留。
- 固定每页 50 条关系；返回本页两端节点，以及可选聚焦设备。完整登记图沿用原 10,000 条边上限；每次节点授权最多 101 个，不读取整个客户资产台账。
- 参数仅 offset、graph_version、asset_id。非第一页必须带 graph_version；登记图版本变化返回 409/TOPOLOGY_VERSION_CHANGED，可重新读取第一页。拒绝额外/重复参数、非法 UUID、负数、超限及不规范数值。
- 节点均通过当前客户 authorizedAsset 回读；不存在/跨客户统一 404，不返回部分成功图。最终重新检查成员权限版本，撤权/切范围不返回旧结果。
- total_edges 是当前设备筛选范围下的登记关系总数；本页节点不是客户全部资产。资产标签来自各自授权读取，不声称所有元数据为单一事务快照。
- 原编辑接口与 CAS/幂等/审计逻辑不变；没有迁移，没有物理链路推断、扫描、监控规则发布或启用。

前端对租户、图版本、分页数量、节点集合、边引用、重复关系和未生效标记严格校验；刷新失败清除旧图。取消、退出、撤权、账号版本变化、客户切换均清空数据并取消在途请求，迟到结果不能覆盖新范围。切换客户时清除上一客户的设备聚焦参数，避免对另一客户沿用旧设备筛选。
