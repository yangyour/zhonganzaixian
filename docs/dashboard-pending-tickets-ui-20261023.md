# UI01：首页待办汇总与跨状态列表接线

本批把已存在的 `GET /api/v1/dashboard/pending-tickets` 接入首页，修复“后端已有真实汇总、首页仍全部未知且列表只查OPEN状态”的缺口。无新API、SQL迁移或部署，沿用现有桌面布局。

- 卡片和最近五条共用同一次授权汇总，完整0显示0，非零显示实际数量；存在未配置登记时总数未知，同时保留已确认数量及缺失数量。
- 同时校验V33/V42状态模型、角色范围、权限版本、数量守恒、精确时间/ID顺序、重复及行数完整性；不静默截断、不合并终态、不从一页反推总量。
- 刷新、取消、失败、重试、切租户/账号/权限时同步清除卡片与列表；迟到结果不得恢复旧范围。只使用固定GET，不允许客户端覆盖租户或数量。
- V33入口进入已有处理页，V42明确进入登记详情，不假称已有完整V42编辑器。客户范围只显示本人报障。

**UI01整体仍为IN_PROGRESS。** 当前V1没有SLA超时/剩余及已超时计数，界面明确未知；报告线正在补兼容增强。卡片的“工单登记”入口包含所有登记，尚不是跨两模型的完整待办过滤页，后续仍需补齐M1-1下钻筛选。不能因此宣称M1-1或M1-6整项验收完成。

验证：82项定向读取器/工作区/面板/整页联动回归通过；完整前端302文件、5013项通过，类型检查、构建、发布清单与策略通过。没有用模拟数据替代真实API：本地候选15217复用指定LAN现有API，对DEMO客户/管理/工程师三范围在1440/1024检查6组实际页面；客户完整待办3，管理/工程师已确认3但另有2条未配置登记，总数正确显示未知。实际账号只读检查得到完整0并显示0；没有业务写入。

浏览器还验证一次读取故障→旧计数/行清空→真实GET重试恢复、实际工单详情跳转；两个桌面宽度的待办卡片/列表axe均0违规，0脚本错误/整页横向溢出。最初测试定位器点击Element Plus内部输入被选中标签遮挡，改用组件的键盘操作；REPL超时后通过明确IPv4回环的拥有者浏览器恢复。这些保留为测试工具记录，不算应用缺陷。
