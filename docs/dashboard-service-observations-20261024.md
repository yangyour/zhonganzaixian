# 首页服务健康与故障时间线

对应 UI02 / M1-3、M1-4。本批将两个首页占位替换为真实 PostgreSQL 读取入口和可刷新、取消、展开明细的面板；不表示已配置客户服务、已接入正向健康采样、已部署或正式验收。

## 调用与来源

- `GET /api/v1/dashboard/service-observations`：只读、禁止查询参数、`Cache-Control: no-store`。服务端会话决定租户和账号，数据库时钟决定上海时区本月至今及滚动24小时窗口。
- 仅 msp/padmin，独立要求 `dashboard:read`、`assets:read`、`tickets:read`、`sla_scenarios:read`。读取前和返回前复核权限、账号版本与会话；前端租户、账号版本、权限版本、角色或能力变更立即清空并中止旧请求。
- 在重复读事务内读取现有资产、监控故障、已核验 schema2 恢复 t2 和已确认 SLA 排除维护。原 SQL、迁移和业务数据不改；超过预算报错，不能截断统计。
- 已恢复但缺少可信恢复证据的区间保持未知。恢复事实或没有故障都不能推定后续持续健康。
- 当前版本 `positive_health_coverage_loaded=false`，没有正向健康来源适配器；可用时长固定为0，不输出 AVAILABLE 区间。月可用率只有满足既有90%已知覆盖规则时才可能非null，目标未确认则为null。正向覆盖缺口没有被隐去。

## 显式配置

参考 `config/service-observations.env.example`：

- `MOP_SERVICE_OBSERVATIONS_ENABLED=false` 默认关闭。
- `MOP_SERVICE_DEFINITIONS` 为租户 UUID 到服务数组的 JSON 映射。每个服务明确给出 UUID、名称、资产UUID列表、故障组合方式、维护组合方式、目标（未确认填null）。不存在隐式资产分组、默认目标或默认客户批准。
- 故障方式：任一资产不可用 / 全部资产不可用。维护方式：任一资产已批准 / 全部资产已批准。调用方必须明确选择，不静默采用建议策略。
- 配置解析拒绝额外字段、重复JSON键、非法UUID/名称、重复服务或资产、越界目标。配置内容不写入错误日志。
- 最多100服务、每服务100资产、共1000资产、每类10000来源行、单条SQL10秒及整体30秒预算。服务定义不冒充客户签字。未启用返回503，映射缺失返回503，跨租户/缺失资产404。

## 页面行为

保留首页原面板位置，不重设计导航。健康列表显示全部配置服务，目标/可用率/未知时长、故障组合和资产入口可展开。时间线按服务UUID排序展示前8个，明确提示更多服务仍在健康列表；明细覆盖完整24小时，无缺口、重叠或错误严重级别。已批准维护优先，未知单独灰纹显示，颜色不是唯一信息来源。

刷新清空旧快照，重复点击不重复派发；停止等待后可重读；失败、无权限、未读取与数据未知分别显示。权限切换及卸载后的迟到结果不能回填。
