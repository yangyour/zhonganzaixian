# 首页真实工单工作流面板

基线main：2c6e32f8e2cc882240d0b6557b4dfec494cd1ce6。复用既有GET /ticket-workflows接口，不改API0.73.0或迁移文件。

## 功能

- 首页增加“工单处理状态”面板，默认仅筛选OPEN/待接单，允许明确选择既有六态OPEN、ACCEPTED、IN_PROGRESS、RESOLVED、CLOSED、CANCELLED。
- 每次最多5条，按登记时间及ID倒序；支持下一页、上一页、刷新回第一页、失败重试原分页及取消读取。更换状态立即清旧状态历史，失败或取消也不能拿旧状态游标继续翻页。
- 通过登记号/标题/状态/优先级/登记时间查看真实流程，并以ticket_id跳转到现有工单处理详情。不是只展示不可点击的静态卡片。
- 客户角色只显示本人报障关联流程，内部角色显示当前租户授权流程。身份、模式、角色、权限等变化中止请求清数据，迟到响应不回填。
- 读取器复用工作流DTO校验，再验证激活版本>0、请求状态一致、严格UTC、倒序、重复ID、限额和游标元数据。失败不保留旧表格，也不显示“0条成功”。
- 表格有caption、scope和可聚焦横向滚动区；状态反馈可播报；分页完成焦点移至状态，取消返回刷新按钮；控件至少44px，窄屏可换行。

## 业务边界

这是MOP既有六态工作流，不把另一个七态生命周期、尚未激活报障或外部ITSM记录拼成同一权威列表。首页待办总量KPI仍未确认，不能用本页数量或报障登记数替代。所有面板业务请求都是GET，不自动接单/派单/闭单，不发送通知，不宣称SLA或真实外部送达已验证。

## 证据

本地独立PG/API生命周期：以合成客户身份准备13条报障、12条激活流程，7条OPEN（本人6条、另一合成客户1条），其余五态各1条；未激活登记不进入列表。24项真实HTTP检查覆盖六态、分页、客户隐藏内部字段、空租户、匿名/错误筛选/错主体及错筛选游标。成功GET的105表指纹不变，拒绝只允许审计变化；全部临时服务、数据库及凭据已清理。

首次准备数据使用内部身份报障，被既有业务规则正确拒绝；改为另一个合成客户身份后重跑，未放宽权限检查。首轮DOM链接断言等待不足，改为等待路由完成；功能中还修正了失败切换状态时可能沿用旧状态历史的问题。保留失败与通过证据，不冒充首跑全通过。

11份实际HTTP响应由生产前端读取器回放。完整前端/契约/构建计数见evidence/dashboard-workflows-20261021.json。另新增6项Playwright脚本，覆盖四视口、键盘详情跳转、取消和权限撤销；目前总32项可发现，但真实浏览器及axe仍NOT_RUN。QA入口仅开发模式，生产构建检查排除合成入口/标记。

没有操作真实客户工单或部署到客户原测试站；合成夹具中的流转不算业务交付。128项正式TC仍NOT_RUN，统一指标聚合、正式生命周期启用和外部补偿链路继续独立推进。
