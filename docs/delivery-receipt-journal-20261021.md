# 通知回执逐条追加日志与恢复

基线 main d8cd95d057bf5222eb5e66b23ae27bacd4bf6105。衔接既有DeliveryReceiptState及规范快照，提供数据库仓库可使用的有界追加记录格式；本批没有表、仓库装配、Worker、供应商调用或自动发送。

## 存储形状

- 根为既有规范格式的QUEUED快照，绑定租户、投递ID、资源池、事件、渠道、接收对象不透明ID、阶段和纳秒入队时间；恢复不能用任意后续快照代替根。
- 每条记录只保存本次命令及一次状态迁移：格式名、递增版本、前条SHA256、原预期版本、命令UUID、操作者UUID、权限版本、受限追踪ID和Started/DeadLettered/ReceiptRecorded事实。回执记录还绑定完整租户/投递/请求/回执UUID、原状态、发生与观察时间。
- ASCII字段采用长度前缀，UUID为两个64位大端值，Instant为秒及纳秒；恢复后重新编码比对原字节，拒绝非规范modified UTF、无效纳秒、尾随/截断数据、未知标签等。
- 根与每条记录均有完整性摘要，后继包含前条摘要。恢复要求调用方提供完整预期范围、版本与最终摘要，检查缺条/重复/乱序/断链，逐条通过原领域状态机。最终指针仍需可信数据库事务维护；摘要不是签名，不能防止拥有全量改写能力者重写整条链。
- 单条最大1024字节，最多12000条，沿用领域1000次尝试/10000回执边界。这是技术容量上限，不是客户重试预算或短信额度。逐条存储不重复整个历史快照，长链记录大小不随历史长度增长。

## 幂等与权限边界

同一命令ID仅在预期版本、操作者、权限版本、追踪和迁移事实完全一致时允许重放。返回当前最新日志及原命令生效版本，不返回早先UNKNOWN快照，不赋予再次发送权限。同ID改载荷冲突；使用新命令ID重复同回执不制造虚假版本，要求上层关联原命令，不自动猜测映射。

UNKNOWN仍不能直接开启另一尝试；FAILED需显式死信处置后才能以新请求开始；已知旧尝试的迟到DELIVERED仍优先且逻辑送达数仅1。所有输入/输出字节做防御复制，历史集合不可变。恢复没有授权副作用，databasePersisted/providerReceiptVerified/automaticSendEnabled固定false。

操作者UUID、权限版本和追踪字段是待验证的记录数据，不是授权凭证。后续仓库必须独立检查授权/撤权、接收对象与供应商回执关联、事务并发和持久化头指针，不能凭本类恢复成功启动发送。
