# V50通知回执日志持久化与原命令恢复

基线 main 1f33e950b1daeda3e6801cc8222dd64b20bb3f49。本批在既有逐条日志格式上实现显式构造的PostgreSQL仓库，不创建运行时Bean、HTTP入口、Worker或通道发送，也不修改V1—V49。

## 持久化与并发

V50新增一张mop_delivery_receipt_journal。版本0保存原QUEUED根，其后每版本仅保存一条规范命令；原投递去重元组为租户、资源池、事件、渠道、不透明接收对象ID和阶段。租户内命令ID唯一，队列根和后续事件共用唯一约束，不能把同一命令搬到另一投递。

根行作为同一投递的事务锁；追加前持有FOR UPDATE，读取持有FOR SHARE。数据库触发器要求不可变根范围、连续版本和前条摘要匹配。运行角色仅获SELECT/INSERT及root_version一列的UPDATE权限以取得行锁，任何实际UPDATE仍由不可变触发器拒绝，无DELETE/TRUNCATE权限。根/事件为同表自关联，不存在有事件无根的中间提交。

仓库读取完整有界历史，核验所有范围、命令指纹、顺序、原命令元数据与领域状态链；不凭SQL行存在返回成功。只有原范围、原命令和原事实相符才能重放，且返回当前最新状态与原命令生效版本，避免拿旧UNKNOWN状态当再次发送资格。未知请求不能自动开启另一尝试；新ID重复回执仍冲突，上层必须关联原命令。

入队与追加均在自有事务内先授权、操作后再授权，失败回滚；状态来源/完整性不符安全报错，不输出数据库异常、参数或凭据。客户端丢失提交回包时不能宣称成功，原命令重试用于核验已提交记录，不生成新请求。并发首次建根如果遇唯一冲突返回409，由调用方按完全相同原命令重新核对，不创建第二条根。

记录的发生/观察时间保持纳秒，数据库recorded_at为事务记录时间，不据其排序推断业务观察先后。它不是供应商发生时间，也不声称并发事务记录时间严格递增；业务顺序由连续日志版本和领域时间约束确定。

## 必需授权与外部依赖

Authorizer和CommandVerifier都是构造时必需依赖，没有默认允许实现。Authorizer需核对实时身份、租户、操作及撤权，并保持相应锁；CommandVerifier负责可信原请求/回执关联和START/死信前置条件。两者只能在所给事务做本地核验，不自行提交、发网络请求或发通知。

本批隔离验证使用明确合成回调，不能当作生产授权实现。databaseRecorded仅说明库内日志；providerReceiptVerified、automaticSendEnabled仍false，接收对象ID不是联系方式，权限版本/追踪ID不是凭据。实际授权、签名回执入站、供应商关联和Worker装配仍需独立完成，既有依赖槽位保持null。

V50只接受显式测试库mop_test，通过--apply-delivery-receipt-journal在完整V49后执行，服务启动不迁移；重复apply及--check不得改变行。Python和PowerShell入口均固定V1—V50清单、哈希与功能模式，不放宽未审迁移准入。
