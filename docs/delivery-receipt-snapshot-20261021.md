# 通知回执有序历史与规范快照

## 本次交付

原模型只保留尝试和回执事实，不能恢复每次收到回执的时间及死信转换顺序。现在领域状态额外保存不可变有序转换：开始尝试、登记死信、收到回执。相同回执幂等回读不追加历史、不推进版本或观察时间。

新增持久化层 DeliveryReceiptSnapshotCodec，但没有数据库实现、Spring 接线、HTTP 接口或发送消费者。恢复时逐条调用原领域转换，而非直接反序列化任意状态。因此 UNKNOWN 不能被恢复成可重试，迟到的旧请求 DELIVERED 仍只计一次且阻止后续回放。

## 格式与边界

- 格式 MOP_DELIVERY_RECEIPT_SNAPSHOT_V1，大端；ASCII 字符串采用两字节长度及对应字节，UUID 为两个64位整数，时间为秒64位加纳秒32位。
- 头包含格式、租户、投递、资源池、事件、渠道、接收对象不透明ID、阶段、排队时间、版本和转换数量。接收对象不是手机号或邮箱。
- 标签1保存开始请求ID及观察时间；标签2保存死信观察时间；标签3保存请求ID、回执ID、声明状态、发生时间及观察时间。回执继承外层租户/投递。
- 调用者须提供完整预期范围及 SHA-256；校验全部范围、摘要、数量/版本、合法状态链及重编码后的逐字节一致性。拒绝截断、尾随数据、非规范字符串编码、重复伪造转换、非法纳秒和时间范围。
- 上限1 MiB及12000转换是资源保护，不是客户批准的保留/重试策略；覆盖既有1000尝试、10000回执及1000死信历史，不截断或自动删历史。
- 摘要不是签名、加密、回执真实性或授权证明；错误统一为503 DELIVERY_SNAPSHOT_INVALID，不回显载荷。恢复不启动发送，providerReceiptVerified 与 automaticSendEnabled 仍为 false。
