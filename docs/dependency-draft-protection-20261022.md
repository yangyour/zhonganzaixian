# 资产依赖完整草稿确认（2026-10-22）

## 行为与验收要求

落实既有前端验收规范的错误预防、可取消交互与原输入保护。依赖方向、已选设备、建议类型/范围/启用值任一变化属于未保存业务草稿；只有搜索关键词而无业务输入时，不把纯筛选误报为未保存业务。

- 新增“清空未保存输入”操作，需确认且保留搜索关键词。读取失败但原草稿仍在时，依然可以明确确认后清空，不强迫先成功联网。
- 跨资产替换、离开路由、切换租户/退出及原生离页提示保护业务草稿。收起或重新打开同资产保留输入，不重复确认。
- 原 POST 保存状态未知时，不能通过放弃草稿绕过原请求。只读用户仍可以切换查看资产，不额外要求写权限。
- 确认绑定全部原始输入（含当时关键词）、完整图、候选结果、身份范围与原命令。期间改变任何相关事实，旧批准作废，不清新输入。
- 单一确认同时阻止重复清空和保存；旧账号确认的 finally 不会解锁新账号的弹窗。
- 路由最终 beforeResolve 与上下文守卫快照防止后续守卫修改输入后继续跳转；卸载终止旧确认并移除所有监听/读请求。
- 资产页在子组件批准后再检查当前目标、完整输入、身份/权限及选择序号；较旧的跨资产确认不能覆盖后发的同资产重开。

测试控制确认返回值和drawer/表格/无关编辑器外壳，不称为真实浏览器或屏幕阅读器通过。浏览器105项/12文件仅发现、正式128项合同TC仍NOT_RUN。
