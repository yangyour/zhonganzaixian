# 设备监控 SNMP API 接入与 MIB 资料要求

记录日期：2026-10-19。适用范围：MOP 设备监控接入、厂商指标适配及相关验收。

通过 SNMP 或设备管理 API 监控设备是常规技术路线，但协议可用不代表所有指标都能采集。平台应统一接入配置和验证流程，具体指标按品牌、型号、固件及接口版本适配。SNMP 不能覆盖全部需求时，应逐项确认其他接口是否提供所需数据，不能默认“换成 API 就一定能满足”。

本说明整理本次沟通口径，并对应既有 M3 凭据托管、M4 监控与模板、Q20 厂商资料要求。它不增加合同外的承诺，不代表客户已批准具体阈值、采样周期、生产证书或设备权限。现状见[只读检查报告](device-monitoring-compliance-review-20261019.md)。

## 标准接入与厂商适配

|接入方式|可统一的配置|需按设备适配的内容|
|---|---|---|
|SNMP|设备地址、端口、协议版本、只读凭据引用、采集周期、超时及采集站点|OID、MIB 定义、索引、单位、缩放、计数器含义、型号与固件适用范围|
|API|服务地址、认证方式、凭据引用、证书校验、采集周期、超时及资源范围|接口路径与版本、认证及令牌有效期、分页、限流、字段映射、单位和对象范围|

SNMP 与 API 可以服务于同一设备的不同指标，不要求设备只能二选一。每个指标应明确当前来源和适配版本；没有验证的备用来源不自动替代失败来源，避免把不同口径的数据混为一条历史。

已有经过验证的适配器和模板时，新增兼容设备的目标是通过配置完成接入；新型号、新固件或新接口可能需要适配开发和现场验证。复用 Zabbix 等现有采集能力，不要求 MOP 自行重写 SNMP 协议栈，也不能把 Zabbix 支持 SNMP 等同于 MOP 已完成设备纳管流程。

## 华为交换机 MIB 仍然建议提供

MIB 是 SNMP 管理对象的定义资料，帮助核对指标 OID、类型、含义和适用范围，不是独立于 SNMP 的另一种采集方式。提供 MIB 不会让设备增加原本没有开放的指标。

如果已经有验证过的数字 OID 和模板，Zabbix 运行时不一定需要安装 MIB 文件。因此，缺少 MIB 文件不能机械地阻止已有可靠映射的验证；但补充厂商指标、解释取值及排查兼容问题时，仍应取得对应型号和软件版本的 MIB 包或参考说明。平台是否提供 MIB 文件上传或解析界面不是本次新增要求。

对“SNMP 不能满足”的指标，按以下顺序核对：

1. 当前模板是否已经包含该指标，是否遗漏厂商私有 OID。
2. 设备型号、固件和授权的 SNMP 访问范围是否支持该对象。
3. 实际返回值、索引、单位、缩放和采样含义是否符合要求。
4. 若确实不通过 SNMP 提供，再核对设备 API 或其他已获授权的采集方式；无来源的指标明确列为未支持或待确认，不补零、不标正常。

## 需要设备侧提供的资料

|资料|用途与处理边界|
|---|---|
|准确型号、软件或固件版本|确定模板和接口适用范围，不以品牌相同推定兼容|
|对应版本的 MIB 包、参考说明或已核实 OID 清单|核对对象定义、指标单位和索引；已有验证过的模板可复用|
|SNMP 尚不能满足的具体监控项清单|逐项比较合同需求、现有模板和设备能力，不能只写“SNMP 不够”|
|只读 SNMP 参数及授权范围|通过受控私有配置或凭据引用提供，不进入 Git、报告、日志或浏览器明文|
|所需 API 文档、版本、认证方式和只读资源范围|验证接口权限、字段含义、分页、限流及令牌有效期，不把设备登录成功当作资源读取成功|
|可信证书链和匹配访问名称|验证 HTTPS 身份；测试例外不作为生产证书已完成的证据|
|代表设备及真实样本|逐项验证首值、历史、时间含义、失败状态和恢复行为|

客户尚未填写的业务值继续保留 null。缺少现场资料仅影响依赖该资料的适配与验收，不阻止通用配置、接口、页面、校验、发布和业务接线继续开发。

## 平台应达到的接入流程

1. 绑定当前授权租户、站点、资产和采集位置，区分设备地址与管理平台地址。
2. 选择采集方式，绑定只读凭据，并选择已核验的适配器或模板版本。
3. 校验地址、认证参数、证书、资源范围、指标映射、单位和采样设置。
4. 执行受控连接测试，分别展示网络可达、认证通过、资源授权、指标首值等结果。
5. 按已有权限和审批流程发布，启用持续采集，独立验证当前值、历史和采样中断。
6. 按明确的规则版本配置告警；保存配置、启用采集、告警生效与客户生产批准分别记录。

配置写入沿用项目现有租户授权、CSRF、幂等、乐观锁及审计要求，跨租户对象统一 404。具体权限沿用合同，不向普通客户角色暴露 OID、模板、采集器或凭据等内部配置。

验收必须同时保留设备或源平台版本、适配版本、实际指标及单位、源采样时间或明确的接收时间含义、历史记录、失败及恢复结果。网络连通、登录成功、配置保存、MIB 解析通过均不能单独替代真实采集验收；源数据未知或失败时不得使用 fixture、旧值或零值冒充正常。

## 本项目的既定接入边界

- 继续复用指定测试服务器的现有组件，不新增本机数据库、缓存、队列或监控替代环境。
- 超融合已指定通过 SCP 管理接口接入，不因其权限暂不可用而擅自改为直连 HCI 或 SNMP。
- 防火墙已有 API 采集 CPU 和内存的实现与历史证据，不应再笼统描述为“厂商 API 指标全部未接入”。该实现不代表其他指标或其他设备已支持。
- 华为及信锐交换机的详细指标按各自资料和样本验证，不能把基础 ICMP/TCP 监控当作 SNMP 验收。

## 可直接使用的沟通回复

> 华为交换机的 MIB 还是建议提供，最好与设备型号、软件版本对应，方便我们核对指标和做模板适配。如果已有经过验证的 OID 或模板，也可以一起提供。
>
> 平台接入不会限定只能用 SNMP。你提到 SNMP 不能完全满足的监控项，也请列出来，我们逐项核对：SNMP 能采的继续用 SNMP，不能覆盖的再确认设备是否提供 API 或其他已授权的采集方式。MIB 主要用于核对 SNMP 指标，不代表拿到 MIB 后所有监控项就都能采到。
