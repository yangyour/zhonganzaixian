## 已完成的模块准备

- [设备清单](../deploy/lan-test/devices.json)只含明确key、中文类型、品牌、型号及单个IPv4；不接受凭据、命令、网段扫描或DNS自动发现。当前超融合保留原中文类型，不擅自新增业务数据库枚举或映射为已获批类型。
- [探测核心](../tools/device_network_probe.py)限制4个并发、TCP每端口2秒、ICMP2次/命令7秒、路由查询3秒；区分超时、拒绝、主机/网络不可达、权限拒绝和探测错误，未回应保持UNCONFIRMED。
- [远程入口](../tools/probe-lan-devices.py)复用Git忽略私有SSH资料，在认证前核对固定主机键；检查项目owner及采集容器归属/运行态，并比较探测前后容器ID/PID/启动时间。采集容器变化则丢弃本次该来源结果。两来源独立记录错误，失败不保留旧成功报告。
- 网络响应仅产生`RESPONSE_OBSERVED`；`device_identity_verified=false`、`monitoring_ready=false`、`device_health=null`。缺少只读凭据时不发SNMP请求、不尝试默认community、不将UDP发送成功当成SNMP可用；固件、sysObjectID、模板均保持null。

此工具在采集容器的**网络命名空间**中执行宿主机Python/ping。它验证网络路径，不证明Zabbix进程权限、模板、SNMP poller或实际item首值已经通过。没有新增公开API、浏览器透传、数据库迁移或Web部署；MOP HTTP契约继续0.45.0，PG V1–V30冻结不动，API/Worker不自动迁移。

## 工具输入输出与复验

本机使用已有Python 3和`tools/requirements.txt`中的Paramiko依赖；远端复用已存在的Python3、ping、ip、nsenter和Docker。不安装新数据库、监控或其他组件。凭据只从`deploy/private/lan-test-connection.json`读取，主机信任只从`lan-test-known_hosts`读取，不执行连接文件内的内容。

```text
python tools/probe-lan-devices.py --output docs/evidence/<本次独立报告名>.json
python -m unittest discover -s tools -p test_device_network_probe.py -v
```

默认输入`deploy/lan-test/devices.json`；`--manifest`可指定另一个经明确授权的清单。v1严格字段集、1–32个目标、唯一key/IP、RFC1918 IPv4；不支持网段、公共地址、凭据或额外执行选项。CLI不接受SSH密码参数。报告schema_version=1，包含环境、起止时间、规范清单与探测代码SHA256、`vantage_points.test_server`/`zabbix_network_namespace`、各设备ICMP/TCP/路由事实与未就绪原因。

|退出值|含义|不能推导的结论|
|---|---|---|
|0|两来源每个目标至少有ICMP回应或TCP开放|不表示设备身份、SNMP、指标或业务健康通过|
|2|已完成两来源探测，至少一个目标没有上述响应|不直接判定设备离线；本次防火墙导致该值|
|1|SSH/主机信任、项目归属、工具执行、报告目标不匹配或容器变化等失败|不能当成空设备清单、网络离线或成功|

TCP拒绝可能来自中间设备，单独拒绝不证明目标设备身份。错误输出仅保留类别，不回显异常正文、stderr、认证数据或完整连接串。工具不读设备配置，不运行SNMP SET、重启或压力测试。
