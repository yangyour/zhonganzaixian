用户明确要求只在 dot 自有云电脑并行开发，并启动相关本地服务测试。本批使用全新、可丢弃的数据与合成测试身份，不访问用户电脑或原指定测试服务器。

## 实际环境与结果

- 官方校验和核对后的 PostgreSQL 17.9 源码非特权编译，启用官方 Debian ICU 76.1；仅 TCP 回环，SCRAM，独立 migrator/runtime 最小权限角色。
- 每个测试会话使用新的私有临时集群与随机凭据，API 只接收 runtime 身份；结束后停止自己启动的 API/PG，删除临时集群与凭据。
- 使用当前源码 V1–V37，首次应用 37 项，重复及只读检查均 0 项；结构/ACL 检查通过。该批不包含 V38。
- 选定 PostgreSQL 持久化测试共 884 项，0 失败、0 错误、0 跳过。其中 859 项为真实 PG 集成测试，25 项为仓储/诊断/安全单元测试，不能将 884 全称为独立数据库集成用例。
- 实际打包 API 启动后的 8 项 HTTP 检查通过：live/ready 200、project_local 开启、未登录 session 401、真实密码+CSRF 登录 200、登录后会话/策略/资产查询 200。
- 前端按锁文件安装后类型检查/构建/发布规则通过；启动真实 Vite preview，首页和构建脚本返回 200。没有宣称浏览器交互验收。
- 另一个完整 Maven verify：九个模块编译打包通过，3161 项发现、2254 项执行、907 项有意跳过，零失败/错误。此运行禁用远程组件测试；不能与上述 PG 用例简单相加去重。

## 本次发现并修复

1. 最初便携 PG 未带 ICU，引发查询 collation 错误。重建 ICU 版本后重新完整运行，未把失败日志覆盖成通过。
2. 旧测试需要明确的客户报障登记前置数据；通过真实仓储事务写入三条标记为合成的测试登记，未使用内存仓储或伪造外部组件结果。
3. V37 增加了指向原始事件和隔离记录的外键，旧的两项 UNLOGGED 漂移测试在构造场景时被 PG 拒绝，未到达被测核验器。本批仅修改测试：在已有回滚事务内先把 V37 依赖子表设为 UNLOGGED，再修改被测父表；仍要求核验器拒绝漂移，最后回滚全部更改。没有删除外键、修改生产核验器或弱化断言。相关两类各 26 项及完整 884 项均通过。
4. 完整云端 Maven 的 Mockito self-attach 不可用，改用已锁定 Mockito jar 的测试 JVM 启动 agent，未改项目依赖、源代码或主机安全配置。
