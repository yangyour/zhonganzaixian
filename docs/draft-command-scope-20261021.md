# 巡检、来源、报告和审批命令生成的范围复核

## 修复范围

五个客户端工作区：巡检模板、人工执行单、来源集合、季度报告草稿、变更修订审批。

原有实现会在生成幂等key后继续进入发送函数。如果生成key的同步回调重置或替换工作区范围，旧输入可能借用新范围进入发送；旧回调抛出的异常也可能写进新范围状态。审批还可能在回调后从已经清空/替换的state再次取目标和基线。

现在：

- 生成命令前捕获原epoch，key返回后复核epoch、卸载、写权限、在途状态及已有命令。
- 原范围失效即停止，不在新身份下重建或发送旧命令。
- 原范围的异常不覆盖新范围错误状态。
- 审批在回调前冻结原目标及审批基线，之后只用冻结值并通过范围门禁，不从新状态借用目标或版本。
- 正常范围内的保存、明确拒绝及未知结果原key/body重试行为不变；现有后端授权仍是必需边界。

这是同步回调重入一致性回归，不是宣称发现可远程利用的服务器漏洞，也不替代后端认证/租户隔离。遵循[前端验收标准](frontend-acceptance-standard.md)的范围隔离及原命令恢复门禁。
