# 独立权限组合与无业务权限导航

修复两个前端接线问题：管理菜单不能仅依赖配置/审计能力显示，因为客户联系人或独立巡检/租户资源能力也应有自己的入口；缺少assets:read时不能反复重定向至同一个被拒绝资产页。

`routeAccess`集中校验已知基础类别、明确能力、单角色及角色列表限制。App管理/资源分组根据路由元数据判断是否有可访问入口，资产项也显式检查读取能力，桌面与移动菜单保留相同逐项门禁。品牌入口与路由守卫选择真实可访问页面；有资产权限时保留原资产首页，否则选择一个获准业务页。没有业务读取权限时进入`/access-unavailable`，不加载业务页或伪造授权，仍可主动退出。重新加载后如授权已恢复，守卫离开无权限说明页；未登录不能借说明页建立会话。

无权限页“重新检查”只做整页重载，再由正常GET会话获得当前权限；不自动写权限、发起账号创建或重试未知原请求。路由/菜单只是界面门禁，实际授权仍由API与事务决定。此批不声称所有已打开业务组件在任意权限变动时都完成刷新；持久角色加载及真实撤权仍待。

28项新增前端测试：9纯导航策略、9真实Vue Router/jsdom导航和10 Vue条件渲染测试。组件中的Element Plus仅slot stubs，用于核对两份菜单/退出绑定，不代表实际抽屉、CSS或真实浏览器。覆盖独立管理能力、空集合、错误类别、撤销、退出、登录/root/未知路径不循环、权限恢复和客户不得进入内部导出路线。首轮一个旧源码断言仍期待守卫内联表达式；更新为统一helper与真实角色列表导航测试。第二次新增源码读取在jsdom误用URL路径失败，改用已有resolve文件路径后再全量复验。

同时无损合入原服务器V27证据；源码与全部新blob/commit/tree已核对。原SQL和原服务未由niko修改。已登记[V27能力清单差异](identity-capability-drift.md)，不能把菜单回归当成该数据库差异已修复。API0.44.0形状不变，正式128项仍NOT_RUN。
