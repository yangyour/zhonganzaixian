# UI02 / UI03：告警趋势、事件标记与原始记录下钻

## 已实现

- 新增 `GET /api/v1/metrics/event-noise-trend`，当前授权内部角色、dashboard:read+tickets:read，在只读 REPEATABLE READ 快照内聚合既有 V37 降噪日志，返回前复核完整成员关系。
- 24小时为24个1小时桶，7天为28个6小时桶，30天为30个1天桶。这些是有界技术展示预设，不是新指定客户业务阈值。两条序列使用完全相同的 `[from,to)` 桶：RAW_INTAKE记录数，以及 RAW_INTAKE−MERGE 的指纹归并后记录数。
- RAW_INTAKE、MERGE、FLAP、DEPENDENCY、MAINTENANCE、EFFECTIVE_ALERT 六层独立计数，完整窗口总数与各桶相加一致。抑制与归并可能重叠，不将全部层简单相减。
- 24小时视图在同一数据库快照读取最近最多8条真实RAW_INTAKE事件标记，更多时明确truncated；名称/严重级别取当前事件资料，并显式标记 CURRENT_EVENT_PROJECTION，不伪造历史冻结元数据或固定“Proxy失联”样例。
- 新增 `/metrics/event-noise-trend/records`，按被选中桶的原始from/to读取完整RAW_INTAKE分页，支持原始成对游标。技术限制为近31天内最多1天跨度、默认20/最大50条；包括被归并/抑制事件的原始记录，不执行删除。
- 计数和明细同一快照；首屏少行、标记覆盖不足、桶/层计数冲突、错范围或越过游标时失败，不返回空成功。日志记录时间显式为 NOISE_LEDGER_RECORDED_AT，不冒充设备问题发生或采集时间。
- 原事件中心漏斗补 `recorded_at < observed_at` 上界，与新趋势采用相同半开窗口，不改变原成功DTO。
- 首页在原告警趋势卡内替换占位，保持固定结构和既有菜单样式。新增真实双线、数值表、各层折叠明细、事件标记、时间桶选择、原始记录分页/事件详情链接，以及取消/原页重试。
- 24h/7d/30d实际改变趋势请求。首页30秒刷新统一触发一次趋势读取，隐藏页面不轮询；无重复计时器。账号/租户/权限/窗口变化清空旧数据并取消请求；迟到结果不能恢复旧曲线。
- 同一范围临时503/网络异常可保留上次曲线，但明确标“过期”，读取时间不改写；换窗口、权限拒绝或畸形响应不能沿用。曲线和原始明细任一遇到401/403会清除另一侧旧展示。原始明细失败不保留旧内容。
- 取消操作恢复到命名读取区域的键盘焦点，且上下文已变化时不抢焦点；SVG之外有可操作数值表和桶选择器。

## 仍然未知，不核销整项

合同M1-2的降噪率分子使用“最终通知数”，不是 EFFECTIVE_ALERT，也不是供应商受理或送达率。当前缺完整可验证最终通知来源，因此 final_notification_count、noise_reduction_percent 均为null，徽标保持未知，final_notifications_verified=false。不能凭有效告警记录补出一个百分比。

读取的是已归属当前租户并写入降噪日志的记录，不等于上游全部物理信号、隔离队列或采集覆盖。零日志桶只表示该桶没有记录，collection_freshness_verified=false，不代表设备健康。各次原始记录分页单独重新授权，不是跨页冻结快照；当前事件详情也不是历史冻结元数据。

真实指定PG/OIDC/监控与桌面浏览器验证仍未执行。JDBC协议双替身、MockMvc安全过滤器、jsdom/ElementPlus和静态构建分别记录，不冒充真实联调或完整无障碍验收。最终通知源、真实采集新鲜度和其余首页服务健康/可用率/故障时间线继续待补。UI02/UI03均保持IN_PROGRESS。

## 契约与验证

新增OpenAPI模块 `tools/event-noise-trend-contract.mjs` 由最终生成器追加，既有接口不删除；离线DEMO只更新来源摘要与golden，不初始化账号/租户/业务记录。无新增组件、迁移、设备/存储操作或部署。

首次回归中，首页测试用“全部请求的最后一次”判定旧元数据窗口，新独立趋势请求使它失败；已改为分别核对两个实际来源的最后窗口，未删除窗口断言。另一项把错误提示图标SVG误认成曲线，已定位为选择器范围问题，改为检查具有图像角色的真实曲线。额外加强了标记和原始详情的文本注入测试。
