# UI03：事件读取返回前授权复核

`/events`、`/events/noise-funnel`、`/events/{id}` 原有入口检查之后，读取期间成员关系变化仍可能返回旧授权数据。本批捕获首次核验的完整 Membership，完成投影组装后、返回之前复用主干已有 DashboardReadAuthorization，重新核对会话、租户、主体及完整成员授权。初始成员的 userId/tenantId/安全整数权限版本也明确验证，不接受仓储错配。

不改变三个 GET 的成功 DTO，不新增写接口、迁移或部署。原有写操作授权/CSRF/幂等路径不绕开；本地 M01 原始恢复信号防护保留，发布此独立补丁时不把尚未远端发布的 M01 内容混入。

近期事件前端账号版本变更经验证已会因 session 对象变化触发原 watcher，原假设的“漏监听必定陈旧”未复现。因此不添加冗余前端代码，仅新增两项回归：清除已展示结果、取消旧请求并拒绝迟到结果。样式不改。

验证：在 origin/main 19b2ac3e 上先运行新增控制器用例，26项失败（24种读取中变更、稳定读取次数与初始身份错配）；应用实际后端修复后连同原事件控制器及 HTTP 契约回归复验。前端原实现 16项全部通过，新测试并未作为前端缺陷已修复的证据。最终数字见同名证据。

测试使用已明确标记的合成仓储/HTTP过滤器/jsdom，不是实际数据库、OIDC或浏览器证明。真实环境与正式验收仍 NOT_RUN，UI03 全组不核销。
