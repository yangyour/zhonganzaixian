# D08 显式工作时间窗口推进核心

`WorkingTime.advance` 只对调用方明确提供的绝对工作区间推进时长。它不创建默认工作日、不把基础档设为周一至周五9至18时、不将P3“次日”替换成24小时，也不生成客户已批准的日历。

## 输入与结果

`CalendarData` 带日历标识、版本、明确覆盖窗口、工作区间和覆盖是否完整。工作区间防御性复制、求并，必须位于覆盖窗口内；重叠或重复不能增加可用工作时长。完整覆盖中没有工作区间的部分才是明确的非工作时间。`complete`只描述数据覆盖，不验证客户资格、批准或来源真实性。

输入起点和所需时长均显式传入，返回原日历标识/版本、消耗区间及剩余时长。仅数学计算完成时返回 `CALCULATED` 和精确deadline；缺日历、缺时长、缺起点、覆盖不完整、起点在覆盖外、已知工作区间不足时返回 `UNRESOLVED` 且deadline为null。缺时长的remaining也是null，不默认0。

边界规则：工作区间左闭右开；所需时长正好耗尽时可落在区间结束点，不多推一天。显式0时长在已知覆盖内数学结果为原起点，但不能填补未知SLA参数。负时长和越出覆盖的工作区间拒绝；纳秒精度不丢失。跨夜、节假日只按明确输入的工作窗口跳过，不从星期或系统日历猜测。

## 尚未接入的边界

调用方负责把已确认Asia/Shanghai日历转换为Instant窗口，并在授权事务中取得真实有效版本、客户确认与完整覆盖事实，不能从请求体采信这些标记。运行配置解析、工单创建快照、PG持久化、SLA Worker和正式HTTP都未接入；历史工单不得因重新计算覆盖原截止。

Q08工作日历及次日口径、Q07/Q09正式动作资格、Q27重开计时仍待落实。`CALCULATED`只表示给定输入的数学结果，不是对客户承诺或验收通过。API V0.8、V1–V6及私有配置不变。

## 测试

20组独立参数化用例覆盖窗口内、午间/多段间隔、起点处于休息期/结束边界、重复/重叠、跨夜、明确假日缺口、资源不足和显式0；另6项覆盖缺值、覆盖不完整/范围外、不可变性、纳秒跨年、由调用方显式转换的上海闰日/月界及结果版本/未决状态不变量。所有时间表均标明合成测试输入，不是默认日历或真实业务配置。

复现：`mvn -B -ntp -C -pl server/api -am -Dtest=WorkingTimeTest -Dsurefire.failIfNoSpecifiedTests=false test`。真实组件、日历发布及完整SLA验收仍NOT_RUN；本轮实际结果见[验证证据](evidence/dot-working-time-20261002.json)。
