# 导出与本人偏好恢复浏览器验收规格

## 范围与标准

新增15个可执行Playwright规格，使用实际页面组件和仅开发模式可进入的合成页面。接口由测试拦截，不连接真实数据库、供应商或客户账号；合成会话和CSRF标记不属于真实凭证。该入口不是生产身份认证机制，生产构建不包含此QA入口。

依据[前端验收标准](frontend-acceptance-standard.md)的WCAG 2.2 AA目标及业务恢复门禁：

- 导出与本人偏好各320/390/768/1440四视口：原生键盘、正文不横向溢出、截图及axe WCAG 2/2.1/2.2 A/AA标签检查，共8项。
- 导出取消读取保留原输入、状态焦点、手动恢复不重开轮询；本人偏好取消后拒绝迟到版本、恢复保持编辑，共2项。
- 下载授权响应丢失后，独立刷新失败，再按原key/body恢复同一文件链接，且没有自动下载，共1项。
- 本人偏好历史续页失败后仍使用版本6边界，不退回第一页，共1项。
- 两页权限撤销移除私有内容及恢复入口，共2项。
- 本人偏好账号版本变化清理原编辑且不写入，共1项。

每个响应明确标记合成数据。GET流程不允许出现POST；只有明确测试下载授权的案例模拟POST，而且检查原key/body一致、未触发内容下载。意外API目标会使测试失败，不把未拦截的请求交给真实后端。

## 运行与证据等级

在具有允许使用的Chromium环境中执行：进入apps/web，运行 npm run test:browser -- qa/browser/export-preference-recovery.pw.ts。使用已有Playwright配置启动独立Vite；截图、失败trace及JSON报告写入既有测试工件目录。

本环境只验证TypeScript、Playwright规格发现和开发入口HTTP可达，不启动受阻浏览器，不绕过已有访问限制。新增15项及总计74项/9文件均为NOT_RUN，不是15/74项通过。axe、视觉、模态焦点、真实键盘和布局结果也全部未验证，不能声明WCAG符合。

原生DOM和全量单元证据来自各功能独立批次，不能合并成浏览器通过；128项合同TC不改标。若后续实际执行发现缺陷，必须记录失败并修复，不能降低断言或删掉失败规格来宣称通过。
