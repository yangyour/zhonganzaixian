# 导出发布与下载授权的原文件恢复保护

## 复现问题

发布/下载授权的原请求只保存动作、key和正文，回执核对却依赖当前读取面板的文件描述。授权结果未知后如果独立刷新失败，当前描述被清除，原下载授权重试即使收到合法响应也无法核验。发布重试则可能因描述缺失而漏查原文件大小、行数。

新增首批14项回归在修复前13失败、1通过，涵盖上述恢复问题，以及同步状态通知、请求标识生成期间的范围失效与卸载。随后修复并增加描述防篡改、不同文件拒绝、独立观察不替代原基准及实际Vue父子面板恢复测试。

## 修正行为

- 每次明确发布或申请下载授权时，原请求同时冻结完整文件描述；它与key、动作、正文一起深拷贝，读取面板清空或变化不会替换原基准。
- 重试核对原租户/账号/任务、摘要、大小及发布行数，下载响应还检查同源同任务路径与到期时间；错误文件仍维持原请求未知，不创建新请求。
- 原授权恢复成功可以重新展示下载链接，但不自动访问或下载。后端仍须在实际下载时重新鉴权；前端保存描述不授予访问权限。
- 请求派发前复核原代际与局部AbortController。生成key期间范围失效即停止，旧异常不写入新范围。
- 安全随机源失败或key非法，明确显示“没有发送”，不伪造已经发出的未知命令。卸载后的工作区不可通过reset复活。

新增18项回归，17工作区、1实际Vue父子/原生DOM合成测试；定向63项通过。未知授权→独立刷新失败→原key重试→显示同一文件链接的完整前端路径已验证，没有真实存储访问或下载。
