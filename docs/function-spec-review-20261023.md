历史拓扑和知识库说明包含旧站点发布、浏览器 localStorage 保存、演示数据和浏览器测试。这些是原型事实，不能直接等同当前 Vue/Java 正式系统能力。现已在两份原说明顶部补充当前入口、已实现边界和未实现事项，不改写历史记录。

说明书应将每项能力分成“原型交互”“正式代码与契约”“真实系统联调”“合同验收”。当前仍保留128项TC NOT_RUN，不能把绿色构建、页面数量或旧原型测试数转为完成率。

## 二、本轮直接修复：依赖读取授权复核

对应 M2-8、M3-9，以及 M2-D08/D11、M3-D10、TOPO-D03/D07。

旧 GET /assets/{id}/dependencies 使用无授权快照的 find 获取锚点，随后直接返回依赖仓储结果。仓储本身有读事务授权，但控制器没有返回前再检查成员/会话，因此比新监控读取路径弱。

修正：

- 锚点改为 authorizedAsset，绑定当前租户、用户、权限版本；读取前后均验证可见性。
- 返回前重读成员关系，比较完整 Membership，包括角色和有效能力集合。撤权、权限版本变化、同版本角色/能力变化或客户切换不能返回原结果。
- 校验仓储返回资产及草稿的租户/对象身份，异常来源不允许覆盖可信范围。
- 客户级拓扑也补齐成员 userId/tenantId/正权限版本检查及完整成员比较。
- 原写入接口、CAS/幂等/审计、DTO字段和API0.83版本保持；没有修改实际权限或业务数据。

## 四、复核原则

技术性能优化与更强授权复核可以直接实施，不需要补造客户业务规则。资产标签发生变化与授权被撤销不是同一问题：一致的历史快照可以合法返回，但必须准确标明读取范围，且当前授权必须有效；不应机械复制主动探测前后的资产地址一致性门禁来制造无意义冲突。

本批没有改写前端代码，完整保留上游已获授权的合同布局调整；不启用新采集、物理拓扑发现、外部通知、演示账号或部署，不修改冻结V1–V50。

本轮分批证据：evidence/dependency-read-guard-20261023/validation.json 与 evidence/topology-batch-read-20261023/validation.json。后续每个可独立验证切片单独提交，不能把本复核表当全部功能完成清单。
