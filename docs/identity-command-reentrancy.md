# 身份命令通知回调的重入隔离

2026-10-05，基于b7cccb3/API0.45。`createIdentityCommand`用于项目用户、角色、策略和本人账号写入。原实现先清空并通知，再捕获代次；同步通知若再次清空/提交，外层可能覆盖内层命令的原请求内容。原dispose也先通知再标记终止，通知中可能发出新的请求。隔离测试复现，不宣称真实浏览器或服务器曾触发。

修正将预期代次在清空通知前捕获，通知后核对代次、终止标志和idle状态；dispose在通知前进入终止状态。被替代的外层意图不能改写内层原body/key，响应丢失后重试保持同一原请求。sending通知中终止也不得调用传输。服务器端操作是否已执行仍以原请求/收据核对，客户端终止不等于服务器撤销。

新增5项纯Vitest，覆盖终止回调提交、idle回调嵌套提交、嵌套请求丢响应后的原body/key恢复、idle回调再次清空及sending回调终止。旧实现14项中3失败，新实现14项通过；全量1749项Web/105文件、类型检查、生产构建及127契约通过。实际API路径/字段/版本、SQL和权限规则未改变。证据见[回归记录](evidence/niko-identity-command-reentrancy-20261005.json)。

原命令只驻留组件内存，没有跨刷新持久化；任意第三方回调抛异常与所有管理页面权限变化后的显示清理不在本切片证明范围内。无真实账号、网络或组件操作，正式128项验收不据此改变。
