# 身份保存回执与后续回读分开确认

2026-10-05，基于796cd27/API0.45。原`useIdentityEditor`在页面load内部捕获GET错误并正常返回时，无条件显示“最新记录已回读”；GET抛异常时又会把已接受写动作的调用变成异常。挂载隔离测试已复现，不能将其写成真实服务器故障。

页面回调现在返回明确boolean：仅true可以确认最新记录，false或异常显示警告“操作已保存，但最新记录尚未确认；请重新读取，不要重复提交”。已接受的命令和原收据保留，不因为回读失败改成写失败或自动重试POST。角色、用户、身份策略三页接线；本人改密明确返回redirected，只提示重新登录，不声称已读到新账号数据。

回读期间busy阻止新写入和重复原请求重试；卸载后晚到的回读不更新完成提示。原未确认写操作仍维持uncertain及原键恢复规则，不进入保存成功后的GET回读。
