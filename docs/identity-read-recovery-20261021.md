# 角色列表、本人账号与安全设置：读取取消和恢复

基线 main d7cf8a269834e4224e19dd7e64827cda3ccfd54f。按[前端验收标准](frontend-acceptance-standard.md)完善三个固定端点读取链路，延续[完整身份输入保护](identity-input-protection-20261021.md)。

## 操作链

- 角色列表、本人账号及安全设置均提供明确GET取消和原读取重试。取消终止信号、失效原generation并忽略迟到响应；失败/取消不推断空角色、无账号或已启用策略。
- 不再使用覆盖整个页面的加载遮罩，取消按钮仍可到达；加载状态明确显示。取消聚焦恢复说明，成功读取聚焦页标题，失败聚焦命名的错误结果区域。
- 原读取恢复先检查当前范围及未保存输入，需要放弃新草稿时仍使用完整输入确认。未知写入保持原请求，不能借读取恢复清除；重试只发GET。
- 安全设置保留“策略+提供方”完整读取边界，第一步完成但第二步失败/取消不会发布半份可编辑策略；恢复重读完整原链路，权限变化则清理原范围目标。
- 账号版本/权限变化与卸载清除恢复状态，已取消读取的迟到完成不抢走取消状态焦点。

## 竞态与焦点回归

初版恢复处理器在await未保存检查前没有互斥，快速调用两次会各发一次GET。新增回归得到3失败/20通过，补独立恢复epoch与等待互斥；显式新读取仍可以按原语义替换旧读取。

另一个回归发现：放弃草稿确认期间，重试按钮因“忙”判断被卸载，取消后没有原焦点目标。现将“存在可恢复目标”和“当前允许开始恢复”分开，确认期间保留原按钮DOM，处理器仍拒绝并发；不靠可见按钮状态替代运行门禁。
