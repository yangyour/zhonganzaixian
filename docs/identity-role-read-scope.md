# 角色页面的读取范围和旧响应隔离

2026-10-05，基于0e003d1/API0.45。在Vue独立挂载中复现：缺少角色读取权限仍请求、权限变化后旧列表/表单保留、切换租户或上下文代次变化后旧响应仍显示。旧实现的5项边界检查全部失败。正常App已有按租户/权限版本重建页面的防线，本次增加页面自身防护，不声称已观测到真实跨租户泄露。

角色页现在捕获用户、角色、租户、权限版本、账号版本、能力集合、上下文代次及切换状态。任一范围变化同步清空角色列表、选中角色、未保存表单和命令显示，并取消旧GET；无roles:read或切换期间不请求。每次GET有独立AbortController与递增代次，只有当前范围与当前请求能发布结果；旧请求即使不遵守abort也被丢弃。刷新开始清空旧列表，恢复能力后须明确重新读取，不能恢复旧缓存。

手动刷新和打开/复制角色沿用未保存确认，但确认完成后再次校验范围；权限在弹窗期间变化时不能重新打开旧草稿。保存前复核读写能力、切换状态和内置保护。角色列表提供明确的只读刷新入口。

`useIdentityEditor.clear()`同时推进本地代次、清空通知和dirty状态。正在进行的旧写回执/保存后回读不能再更新新编辑上下文，也不能关闭新表单；这只是客户端展示隔离，不表示服务器写入被撤销。服务器历史请求/审计不改变。

新增9项：8项角色页Vue/Element Plus-jsdom挂载（含延迟GET、能力恢复、确认中撤权）及1项组合函数清空后回读测试。测试使用HTTP隔离替身，不代表实时服务器撤权、浏览器CSS或真正登录验收。API0.45、授权来源、SQL、业务策略未改；完整回归结果见[证据](evidence/niko-identity-role-read-scope-20261005.json)。其他页面的独立显示清理仍需各自验证，正式128项验收不据此改为DONE。
