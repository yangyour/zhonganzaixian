# 用户管理页的范围变化清理

2026-10-05，基于7afca50/API0.45。继角色页之后，为用户管理页补充不依赖App重挂载的范围防护。旧实现独立挂载的11项测试中5项失败：缺少users:read仍请求，撤权后用户与未保存口令表单仍保留，旧详情可在范围变化后重现，租户切换和上下文代次变化未清空列表。正常App已有按范围重建防线；这里是隔离复现，不记为实际线上信息泄露。

范围包括当前账号、角色、租户、权限/账号版本、能力集合、允许租户ID集合、上下文代次及切换状态。变化时同步作废列表/详情代次、终止旧读取、清空用户名/显示名/口令/外部绑定输入、角色选择、成员/绑定列表及写命令展示。读取权限恢复后只显示空状态，须主动查询，不恢复旧缓存。没有读取权限或切换期间不读取。

打开用户、查询、翻页在未保存确认返回后再次核对范围。加载详情时隐藏可写表单，当前详情失败不保留未确认可写状态。各写入口在调用前重新核验当前读取/写入能力和选中对象，成员授权额外要求角色读取能力。其他租户角色查询绑定当前账号选择、目标租户、范围与独立代次；只能用当前允许租户和已读取启用角色进行目标授权提交。服务器授权、CSRF、CAS、幂等及审计仍是最终防线。

新增8项Vue/Element Plus-jsdom测试：无读取能力、撤权清除含口令表单、旧详情晚到、切换租户、上下文变更、恢复后主动查询、确认弹窗中撤权、允许租户集合变化。实际HTTP均使用隔离替身，无账号创建、服务器写入或凭据配置。API路径/字段、0.45版本、SQL与业务策略不变。完整结果见[证据](evidence/niko-identity-user-read-scope-20261005.json)。

本切片不证明外部OIDC、真正浏览器撤权、其他管理页面或所有字段响应校验已完成；正式128项仍NOT_RUN。
