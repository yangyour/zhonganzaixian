# Impeccable 前端完善与测试部署

## 范围与设计依据

用户授权使用 Impeccable 优化现有前端并部署。独立工作区从 `eb15359` 起步，不包含原工作区尚未提交的防火墙资源采集改动。应用沿用 Vue 3、Element Plus、顶部横排模块和蓝色业务系统风格。

实际使用上游 `pbakaus/impeccable`，源码版本 `2f98774f86bc05563876643db37e6c37c322850f`；运行 `impeccable context --target apps/web/src/App.vue`，依据 polish、operate、craft-floor 执行现有页面完善。工具和依赖保存在 Git 忽略的 `.local/`，不作为应用运行依赖。未启用编辑 hook，完成后运行一次独立 detector。

真实基线来自 `lan-test-20261008` 的 10010 入口：手机资产摘要纵向重复占位、运营总览六项未知指标占据两排大卡片、通用表单/表格的间距和文字层级不一致。业务文案、数据来源、权限、未知状态与六项指标/面板顺序保留；不生成监控数据，不修改接口和数据库。

## 执行结果

- 独立 UI 改动：1935 项前端、133 项契约、16 项静态发布/策略检查通过；类型检查与生产构建通过。
- 候选浏览器：15 项操作检查、22 个页面/视口组合通过，无页面脚本异常和业务写入。覆盖 1440/1024/720/390/320px，720px 另作 200% 等效内容宽度检查；不声称原生浏览器缩放或真机验收。
- Impeccable detector 运行一次，仅报告原有 `.form-error-summary` 红色左侧边线。该边线用于表单错误定位，保留为有意的语义例外；没有将警告伪报为零。
- 首轮浏览器静态路由替换触发 Edge 私网地址空间限制，改用仅监听 127.0.0.1 的静态预览与真实测试 API 代理，未关闭浏览器安全机制。
- 部署前发现另一功能已上线 API 0.49 防火墙资源监控，原基线的监控解码器不能解析新增状态。上述 UI 检查不代表这一旧监控页面通过；部署须先合入已上线的兼容源码并重新验证，不能覆盖新功能。
- 本轮 UI 改动尚未部署；完整业务验收和生产就绪不随视觉检查改变。
