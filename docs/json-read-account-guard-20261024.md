# P01 标准JSON读取的返回前账号守卫

此前账号修订复核仅覆盖主动调用DashboardReadAuthorization的页面。其他成功JSON读取即使在请求入口通过账号检查，仍可能在控制器计算期间发生账号停用、强制改密或会话撤销后返回旧数据。

新增ProjectReadResponseAdvice，在remote_test且MOP_AUTH_MODE=project_local（默认）时安装，覆盖/api/v1/下GET和HEAD的成功2xx标准Jackson JSON或+json响应。它在转换器写出响应体前调用现有请求局部的账号复核：同一Authentication实例、会话ID、有效账号修订及强制改密门禁。匿名公共登录选项继续可用；缺失应有的入口守卫不放行项目账号私有读取。

账号变化返回401，强制改密返回403，身份存储不可核对返回503，不返回原私有数据或上游错误正文，也不失效并发建立的新会话。错误响应不再次检查，避免异常处理递归。拒绝时同时清除Servlet和Spring响应层的Content-Length、Content-Disposition、ETag、Last-Modified，并设no-store；保留安全头与会话Cookie。初次追加ETag回归测试发现只清Spring HttpHeaders不能清掉控制器已设置的Servlet头，实际定位后修复，两层同时清理，未删除相关断言。

## 范围与兼容

- 不改业务DTO或接口路由、角色配置、凭据、数据和数据库迁移，不部署。
- 保留各控制器和仓储现有租户/对象/成员能力检查。该共用守卫只扩展账号修订边界，不宣称自动解决每个接口的租户撤权或行级授权。
- 不对POST/PATCH/DELETE写回执统一追加读取检查，避免已提交写入因后置读取守卫变成结果不明；既有写操作的授权、幂等和回执检查不变。
- 不覆盖二进制下载、流式响应、预序列化字符串转换器或已经发送的字节；也不是冻结整个序列化期间账号状态的跨事务锁。对应下载/流式业务仍须自身授权和受控读取。
- 现有主动返回检查继续保留，标准JSON读取可能增加一次账号状态查询，性能需指定环境验证。非project_local的旧认证模式和local_fixture不安装此项目账号守卫，不伪造其账号修订权威。
- 登录/密码修改写流程不被新守卫拦截；要求改密时仍允许现有account/认证读取路由。

实际MVC转换器/错误处理、撤权中途变化、未安装过滤器、匿名选项、HEAD、标准响应头及Profile/认证模式测试见docs/evidence/dot-continuation-20261023/p01-json-read-guard.json。测试使用模拟身份仓储，不进行真实账号密码或权限变更；真实身份源/浏览器/性能验证仍NOT_RUN。P01/P03及正式验收不因此整体完成。
