# ② 需要客户提供或确认的部分

2026-10-23｜用于收集资料、关闭上线依赖。

**这些资料主要决定真实接入、正式启用和验收。** 下表只需补缺失或存在冲突的部分；已有资料直接沿用，不要求客户全部重新提供。

| 对应功能 | 客户需要补充或确认什么 | 未提供时影响什么 |
| --- | --- | --- |
| 生产环境 | 正式服务器及权限、域名／DNS／证书安排、数据库与租户隔离方案、组件版本及许可批准。 | 无法定稿生产部署和数据库隔离，不能正式上线。 |
| 租户与账号 | 首批租户、管理员与审批人、角色授权、服务档位、设备配额。 | 无法按真实组织开通并授权。 |
| 资产与拓扑 | 首批真实资产、关联数据权威来源、有冲突的类型／字段映射、已核实的设备依赖关系。 | 无法完成客户数据正式导入及真实拓扑核验。 |
| 设备监控 | 尚缺设备的型号／版本、只读账号、采集范围、OID／接口资料、网络放行、证书信任，以及有争议的阈值／观察窗。 | 无法完成对应设备的持续采集和告警验证。 |
| 工单与 SLA | 工单权威系统；若接外部 ITSM，需接口及账号；未明确的服务时限、工作日历、升级人员、月费与对账规则。 | 通用流程可开发，但对应正式计时、外部建单和结算不能生效。 |
| 通知渠道 | 尚缺渠道的供应商、接口／账号、接收人、回执方式、额度，以及测试发送和自动外发授权。 | 无法验证实际送达或启用自动通知。 |
| 备份与安全 | 设备备份／恢复权限、正式 OSS 与密钥服务的受限访问、未明确的保留／删除规则、恢复演练范围与窗口。 | 无法完成真实备份、解密恢复、清理及安全验收。 |
| 远程处置 | 堡垒机产品、版本／许可／接口、只读与读写审批规则、设备范围、录屏及命令控制要求。 | **路线未确认前，不进入 M7 正式开发排期，也不连接真实设备。** |
| 报告与经营 | 正式报告样式／评分与重生成规则、审核及接收人、成本／人员／费用来源、尚未明确的统计口径。 | 可做模板和计算流程，不能出具正式经营结果或客户交付报告。 |
| 正式验收 | 首发范围、验收负责人、可用率与容灾适用口径、压测资源／演练窗口、最终签收。 | 可准备和执行条件具备的测试，不能代替客户正式验收。 |

**建议先收三组：生产部署与隔离方案；设备／接口接入资料；服务档位、人员与通知规则。** M7 如纳入首发，堡垒机路线也须提前确认。

已收到的 234 项监控目录、CMDB 字典、四台设备及现有渠道资料继续复用；已明确的“监控恢复 t2 停钟”和“P2 立即通知并建单”不再重复询问。只补剩余缺项和冲突。账号密钥通过私有配置交付，文档中仅记录引用。
