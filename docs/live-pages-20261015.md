# 页面真实数据接入（2026-10-15）

用户要求将当前占位页面完善为实际页面，为上线做准备。本轮以当前菜单的实际路由、Vue 页面及 API 契约为依据；已有未提交的其他前端优化由其原任务维护，本轮逐功能提交自己的文件。

## 盘点与实施范围

当前菜单均指向实际页面，没有空路由。主要缺口是总览固定未知指标、资产详情的模拟仪表和通用空分区，以及报障页用未实现能力充当统计卡。其他页面已有真实接口或明确输入计算：身份/账号、资产/导入/导出/消息、联系人/租户、配置/审计、巡检/备份/变更草稿、工时/偏好、容量/SLA/经营对照。

草稿页面虽然可以真实保存与回读，仍不代表设备备份、通知派发、正式工单、巡检自动执行或报告发布已完成。正式告警、SLA、送达与全资产服务指标不能由基础 ICMP 或登记数量代替；这些缺口继续保留。

## 功能一：总览实际监控

- 首屏读取当前授权租户的明确绑定设备，显示绑定数、ICMP 可达、无回应与未确认数。
- 展示真实延迟、丢包和已接入的防火墙 CPU/内存；已采集资源最多前五，缺失/过期/错误不参与排名。
- 实际设备、采集项、1小时/24小时历史查询，保留缺口和原始采样表；资源时间明确为采集器接收时间。
- 30秒自动读取，后台暂停。即使暂停刷新，90秒本地过期或180秒源数据过期后也不会继续显示正常值。
- 租户、用户、权限版本、资产和卸载使旧请求失效；基础源失败清除旧数据，单独资源源失败只影响该源。
- 正式合同六指标和六面板保留在“正式运营指标与接入进度”，没有改写原 API 的未知值，也不以基础监控冒充正式服务指标。

API 沿用 0.49.0：`GET /network-monitoring`、`/{assetId}/resources`、`/{assetId}/history`、`/{assetId}/resources/history`；各路径均相对于 `/api/v1/network-monitoring`（列表路径除外）。没有新增接口、写入、迁移或组件；原租户/资产权限守卫保持。

运行方式：通过原固定主机信任 SSH 隧道访问指定测试 API；前端 `npm --prefix apps/web run dev` / `build`。私有连接与账号仍只从 Git 忽略目录读取。
