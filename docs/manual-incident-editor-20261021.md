# 手工事件登记：资产读取恢复与完整输入保护

基线 main d1467af86a51a8a12d7a43e13d556fb622f35fcb。按[前端验收标准](frontend-acceptance-standard.md)改进手工登记的实际操作链，不增加自动监控事件、正式工单或默认严重级别。

## 原读取与版本依据

- 资产查询/下一页、选择资产、核对已选资产及登记回执各自保留明确原目标。取消只中止GET并忽略迟到结果，原查询重试保留原搜索文字及游标，不重发POST。
- 选择资产同时校验原候选快照和当前登记内已观察到的最高资产版本。同版本名称冲突不能被历史最低版本信息覆盖；候选读取失败后的重试仍保留原候选，不能悄悄换核验依据。
- 已见过更高资产版本后，后续失败/取消不会丢失该最低版本要求，原读取重试和显式重新读取均不接受更低版本。同版本不同名称拒绝，不把异常回读当作最新事实。
- 刷新只更新“最新读取”依据，不自动替换已选基准。采用新版本前仍需明确确认；等待回读/确认期间标题、级别、查询、资产或账号变化，使旧确认失效。版本不匹配时提交按钮禁用，工作区也独立拒绝提交。
- 未应用的查询文字单独提示，旧候选不可选择；事件处理器也检查，不仅靠disabled。恢复已应用查询后焦点回到搜索输入，避免临时按钮消失导致键盘焦点丢失。

## 草稿、范围和原提交

原始标题、空的严重级别、搜索文字及所选资产纳入完整输入快照。重新准备、离开或切换上下文的确认不立即清空；新输入、重复确认或更换目标不能沿用旧批准。导航最后阶段再次复核，加载失败/取消/成功后清理临时守卫；跨多个上下文守卫等待也不能丢失后来输入。

账号版本和角色进入编辑器及父列表的同步清理条件。保存后的回执读取即使晚到，也不能向新的同范围编辑器或新账号范围发出旧saved通知；父列表重读完成后还会核对原范围，不能继续选择旧范围的事件ID。外租户saved回调在请求前即拒绝。

状态通知与随机key生成后重查原epoch；本地key失败明确未发送，永久销毁工作区不能重开。未知提交的原key/载荷/资产快照保持锁定，GET不能确认它；已接受回执的校验失败/取消不产生重复登记，手动原回执读取仍验证不可变登记事实。
