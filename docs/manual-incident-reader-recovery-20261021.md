# 手工事件列表与详情：原读取恢复及键盘焦点

基线 main 9b96959f4cbf62baaa46870c0ecd637d7097e99f。依据[前端验收标准](frontend-acceptance-standard.md)，补齐既有登记记录的查看链路，不扩展生产写入或自动工单语义。

## 功能与交互

- 列表失败或取消后，重试固定原页的时间/ID双游标；详情重试固定原记录ID及原不可变事实，不采用后来的输入或新范围。
- 取消只停止GET等待并忽略迟到响应。列表刷新不会卸载登记或人工恢复编辑器，不会清除未知提交；重试读取不发送POST。
- 当前页的原行、最近已核验详情、保存返回的原回执均作为详情核验依据。失败、收起详情或重新读取不抹掉最近详情依据；相同时间的等价UTC表示可以接受，不同登记事实不能伪装为刷新结果。
- 单页必须有唯一登记ID，即使重复ID使用不同且正确排序的时间，也拒绝整页。修复前新增回归真实失败，保留[原始失败输出](evidence/manual-incident-reader-recovery-20261021/duplicate-regression-before-fix.log)。
- 列表具有命名可聚焦滚动区域、caption和列标题；查看成功后聚焦详情标题，收起后返回原按钮，按钮失效则返回列表标题。刷新/续页成功后聚焦列表标题，取消使用共享状态通知与焦点机制。
- 旧行对象和读取中的重复操作在事件处理器中也拒绝，不只依赖按钮禁用。账号版本、角色、权限及租户变化清理原范围；销毁后不能重开读取器。
