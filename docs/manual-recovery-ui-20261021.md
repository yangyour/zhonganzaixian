# 人工恢复确认面板的读取恢复与说明保护

基线 main 81982839d4e8164bbaedba79924b8dbd97aa5268。遵循[前端验收标准](frontend-acceptance-standard.md)的状态完整、输入保留、安全恢复、授权范围和焦点反馈门禁，不改人工恢复的业务口径。

## 交互改进

- 当前人工恢复状态可取消读取，取消后焦点移至可读状态提示；原事件、原说明、选填时间和人工勾选保留。原读取重试仅GET同一事件，不发送或重发恢复确认。
- 初次未读取、读取失败/取消、明确版本0、已有版本1和未知原提交分开展示。已有输入在读取失败时仍可见但禁用保存，不以错误推断尚未确认，也不把当前GET中的他人/已有证据当作原POST回执。
- 切换事件或离开前对完整原始输入快照确认；等待确认期间的新输入、新目标或权限变化使旧批准失效。取消不清空输入，重复prepare不重复弹窗。无效的替换快照不会抛出未处理异常或覆盖原说明。
- 导航确认通过后追加最后阶段快照复核，后续路由守卫改变输入仍会阻止离开；目的组件加载失败、取消、成功及卸载会清理临时守卫。租户/退出守卫也检查原快照，不借用旧批准。
- 账号版本、角色、读权限和确认权限纳入同步清理条件；即使permission_version未增加而confirm能力被移除，私有输入也清除。工作区现在要求明确canWrite布尔值，读权限本身不授权确认或重放。
- 随机请求标识生成和状态通知之后复核原epoch、原事件与权限；本地生成失败明确未发送，旧错误/成功提示不进入新账号范围。已销毁工作区不能重新打开，已接受回执后的读取取消不产生第二个POST。

## 保持的业务边界

人工确认仍是SELF_REPORTED且不可变；monitor_state/disposition_state为null，monitoring_recovery_applicable、ticket_state_changed、sla_changed均false。必须由用户显式勾选人工核验，实际恢复时间留空仍null，不拿归档时间补齐。内部说明不作为监控自动恢复、工单关闭或SLA变化证据。

## 验证

新增29项：16项工作区、11项真实SFC/内存路由处理器（空渲染）、2项真实抽屉原生DOM。覆盖读取取消/迟到/原目标重试、原确认命令保留、只读上下文、派发前范围变化、确认期间的新输入/目标、账号版本和同版本撤权、跨守卫及导航加载失败、原成功提示不跨范围，以及真实textarea/时间/勾选保留和状态焦点。

确认框回复在测试中显式模拟，原生DOM聚焦不替代真实浏览器/键盘/读屏/axe。74项浏览器规格及128项正式TC仍NOT_RUN；本批不重试已有环境拒绝。Vite启动完成4项路由/模块HTTP检查后停止，不称为实际后端联调；无API/Java/DDL改动，无真实人工恢复写入。
