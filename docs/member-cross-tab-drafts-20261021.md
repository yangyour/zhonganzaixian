# 成员跨标签页保存：保留其他未提交输入

基线 main af4d737d99470db3c1d59df15e4c642e5de548e8。遵循[前端验收标准](frontend-acceptance-standard.md)中任务完整性、防数据丢失、未知提交原请求恢复及分层证据要求。

## 保存边界

成员页维护最近一次完整读取的表单基线，分别标记本次操作真正提交的字段。账号资料只提交显示名和启用状态；密码/本地登录、当前租户授权、目标租户授权、新身份绑定及已有绑定停用各自独立。

写入被接受后仍回读服务端新版本，但只清理本次已提交且未改变的输入。其他标签页相对基线的修改保持原值并继续标为未保存。解除锁定或注销会话不再顺带清空密码草稿。成功提示明确“本次操作”已保存，其他内容需要分别保存，不把整页视作保存成功。

目标租户选项及启用状态独立保留；成功提交目标授权后只更新该组基线，不错误地把别的草稿标成已保存。页面关闭、路由和租户切换仍通过共享完整快照确认。

未知提交重试继续使用原请求正文和幂等键。即使后来输入改回旧基线，只要不同于原提交值，也不当作已保存而清掉。异步写入期间输入改变仍走既有保护，暂不执行破坏输入的回读；强制会话变化彻底清理，不允许旧回读重新带回草稿。

## 失败与敏感输入

接受写入后的GET失败不改成写入失败，也不重发写入；其他草稿保持在内存且dirty门禁保留。需要原GET恢复时，若恢复会丢弃草稿，仍先要求明确放弃，取消确认不发送GET。密码只在组件/原请求短期内存，不放到可展示command正文、日志、浏览器存储或证据文件；账号变化/关闭/卸载清理。

## 分层验证

新增17项实际成员页DOM/处理器测试，覆盖各保存入口、无其他草稿时正常干净状态、原未知请求恢复、回读失败确认及强制会话变化。将这些用例在修改前源码运行：14失败/3通过，保留红灯证据；修正后全部通过。所有账号和HTTP/模态框均合成替身，无真实密码、权限或会话操作。
