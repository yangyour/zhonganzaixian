# M01 服务端恢复观察与原回执

## 接续与既有失败定位

审阅并逐项恢复 WIP `1b7211190039af081ce87a19ab8adca3c9be5280`，从当前集成工作树三方合并生成器，保留告警铃铛、首页新投影及 A05 资产接口后重新生成 OpenAPI。旧失败证据不改写。

- 原PG回执失败比较 `valueToTree(original)` 与数据库JSON解码后的 `valueToTree(replay)`。原对象的版本是Long，Map解码后小整数是Integer，Jackson的LongNode和IntNode不相等，但HTTP JSON整数值相同。新增无数据库复现明确证明这一差别、完整序列化JSON等价，以及改动实际版本必定不等；原指定PG用例改比较完整序列化后树，不删字段、不改变数值或业务断言。缺少连接资料时不宣称原PG失败已复验通过。
- 两处前端类型错误来自Element Plus confirm的声明交叉了prompt返回对象与Action字符串；实际无输入confirm返回Action。测试仅在此库边界使用精确返回类型并保留取消、撤权和POST计数断言，没有改业务校验来迁就模拟测试。

## 持久链路与边界

明确POST经过当前成员权限、CSRF、幂等、事件/策略锁、版本CAS和审计；采样证据、事件状态、关联及通知意图同事务提交。原命令GET只读查询已提交回执，未知结果不自动重采样/换键。旧普通RECOVERED标记没有绑定观察证据时不能用于SLA停钟或关单。通知意图不等于真实外发。首次持久接入/自动观察调度属于后续M02，不以本接口存在称为自动采集全接通。

本轮不执行原隔离库脚本、不创建或恢复旧测试身份，不启动组件、迁移或部署。指定PG非零观察窗并发、真实来源端到端与浏览器仍NOT_RUN/BLOCKED，保留原10项实库用例供受限配置到位后复验。正式合同TC不改为通过。
