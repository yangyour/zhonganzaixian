# M01 复发计时周期与耐久通知意图

本切片接续此前复发工单关联。相同事件从恢复转回故障，或新事件关联已有正式工单时，在原事件事务中登记新的恢复提醒周期和 `ticket.monitoring_recurred` outbox 意图。周期身份采用事件 ID 与本次故障开始的成员序号；后续重复 PROBLEM 样本、来源重投或幂等重试不会新建周期。

50/80/100% 提醒继续使用原工单冻结阈值，不重新给出完整 SLA 预算。任务键为 `recovery:{percent}:monitor:{event_id}:{problem_sequence}`；原已消费回执保持不可变。Worker 在同一工单锁下核对最近故障开始记录，较早周期和被新周期取代的原恢复任务记为 OBSOLETE；只有当前周期产生相应耐久提醒意图。响应时钟、人工复核、客户重开与关单规则保持。

事件指纹锁→工单锁→事件写入/周期任务/outbox 使用同一授权幂等事务。关联工单已 CLOSED/CANCELLED 时，即使仍处于事件5分钟归并窗，也创建新的事件登记，不把结束工单恢复成在途。窗口、跨租户404、来源重投去重、原CAS与审计均保留。

通知规划器只将复发意图转换为当前工作流快照中的工程师/协办站内意图，未分派时保留队列接收规则待定；抑制事件不生成本次复发通知。`external_dispatch=NOT_CONFIGURED` 及外发门禁保持，不运行供应商派发。前端通知区分“监控故障复发”和“客户重开”；SLA证据表展示周期标识和原始任务键，仍使用既有读取取消、错误与范围恢复流程。

已完成本地 74 项相关 Java 回归、47 项 Web 回归和类型检查。新指定环境入口 `tools/verify-monitoring-isolated.py` 通过排他 environment.lock，只建立新的 SYNTHETIC_MONITORING 租户/无登录身份，不复用实际或DEMO业务数据；运行受限账号测试后停用本次身份，保留不可变测试证据。受保护租户表摘要和迁移历史前后比较，原始日志留在忽略目录。写联调结果以进度记录为准，未运行不能算通过。

本切片本身不把原始 RECOVERED 信号或 t2 格式校验变成观察窗证明。实际样本及已发布策略驱动的恢复确认另行接续；M01 整体保持 OPEN。
