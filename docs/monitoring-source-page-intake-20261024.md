## API 与页面

`POST /api/v1/monitoring-object-mappings/{id}/page-intakes` 只接受七个字段：

```json
{
  "expected_version": 2,
  "expected_source_definition_sha256": "<当前读取的64位小写SHA256>",
  "first_event_id": "1001",
  "last_event_id": "2000",
  "from_clock": 1792800000,
  "through_clock": 1792803600,
  "page_size": 5
}
```

ID 必须为规范正 uint64 字符串，不能使用浮点数、前导零或溢出值。时间为非负 UTC Unix 秒，起止范围均包含边界；ID 和时间范围都必须明确有序。页大小是技术限制 1–10，不是客户采集频率或策略。请求要求当前 padmin 成员、原有能力、CSRF 请求头和唯一 `Idempotency-Key`；不接受查询参数、重复 JSON 字段、租户、资产、原文、规则、级别或端点覆盖。跨租户对象统一 404。

新开关 `MOP_MONITORING_MAPPING_PAGE_INTAKE_ENABLED` 默认关闭，并且要求原有 mapping、capture、problem-intake 三个开关全部为 true。还须有可用来源/私有秘密引用、明确审批策略、当前资产版本和未过期归属证明。[配置示例](../deploy/examples/monitoring/page-intake-settings.json)全部关闭，不自动加载。映射读取增加 `page_intake_enabled`；旧响应没有这个字段时页面仍按关闭处理。

资产映射详情新增“按有界窗口消费来源分页”表单。时间输入明确标记 UTC，拒绝无效日历日期；保留浏览器对整秒的规范化，不使用本地时区或舍入替换用户时间。回执显示本页收到/业务已关联数量、逐项结果、事件链接和可继续填写的下一页起始 ID。结果不明时只恢复原键与原正文；后续读取失败仍保留已提交回执，权限/身份/资产上下文变化清除内容。

## 事务与来源约束

1. 当前授权复核并锁定映射根行，检查版本、有效 HOST 映射、资产、复核人、来源定义和证明时效；从配置来源重新读取归属元数据，与批准记录逐项匹配。
2. 只调用已有只读 `event.get`，加入唯一 `hostids`，显式 ID/时间窗口、升序和页大小加一的预读限制。包括最后预读行在内，全部行必须匹配同一主机及严格协议；乱序、重复、越界或不同主机均拒绝整页。单条与分页读取共用同一规范来源信封，原纳秒及精确字节保留。
3. 外部读取后重新检查本地策略、来源定义、资产和时效。raw/隔离守卫通过后，以 `synchronous_commit=on` 和既有受限连接保存整页，不在循环中提交或更换连接。
4. 来源键冲突只耐久隔离，`pending_reason=SOURCE_KEY_CONFLICT`。原始恢复信号仅保存原始事实，原因是 `RECOVERY_OBSERVATION_REQUIRED`，不确认 t2。来源严重级别 0、未来时钟和较早信号分别保留 `SOURCE_SEVERITY_UNCLASSIFIED`、`SOURCE_CLOCK_AHEAD`、`EVENT_SIGNAL_OUT_OF_ORDER`；这些明确检查发生在业务修改前，不冒充已消费成功。
5. 其他问题信号通过现有严格信封验证及 raw ID 关联入口，沿用现有归并、抑制、建单和工作流。未被列入上述安全待处理原因的任何错误，包括第二条信封不合法或业务依赖失败，均回滚整页先前的 raw、成员、事件、工单和审计。
6. 业务效果组装后再次检查时效与配置，过期则整页回滚。成功回执与幂等记录共同提交后，HTTP 才返回 `next_event_id`；只允许最后已接收 ID 加一且仍在原上界内。原请求重放仍复核当前授权，返回原回执，不再次读取来源。换键或重叠页通过原 raw/业务去重保持既有记录。

空页明确返回零条和 null 下一页位置，不表示监控正常或完整历史。`complete_window_claimed=false`、`global_checkpoint_advanced=false`、`recovery_confirmed=false`、`dispatch_allowed=false`、`acknowledgement_only=true` 始终保持。来源读取不是上游原子快照，迟到事件、历史补读及后台水位属于后续工作。
