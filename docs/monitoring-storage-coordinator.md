# 监控来源键冲突的内部耐久隔离接线

2026-10-07，PostgresMonitoringEventStorageCoordinator 将 V29 原始仓储的冲突结果接到 V30 隔离仓储。只使用一个显式 DataSource；不增加 SQL、HTTP 接收端点、组件自动注册、来源认证或业务派发。

## 结果与事务边界

- 新来源键与内容相同的重试返回 RawResult，保留原始记录和首次接收回执，不创建隔离记录。
- 同来源键的载荷、源时间或绑定不同，保留原始记录不变，把本次输入的键、绑定 ID、源时间、接收时间和原字节按 SOURCE_KEY_CONFLICT 保存；只有隔离事务提交并正常关闭后才返回 HeldResult。
- 隔离中的 claimed_tenant_id / claimed_asset_id 是本次输入的 Binding ID，不冒充单独解析过的来源原始声明；它们不构成来源认证或租户授权。结果的 sourceAuthorized / dispatchAllowed 始终 false。
- HeldResult 不携带原始事件的 ID 或首次接收时间。该内部结果不得直接作为公开跨租户查询或存在性探测接口。

两个仓储各自提交事务。第一事务确认冲突时没有修改原始记录，其不可变性使冲突结论稳定；第二事务持久保存候选。两事务之间中断时没有成功回执，调用方必须保留原始输入并重放。不能声称每一次调用尝试都已经耐久记录，也不能据此删除上游待重试消息。

连接、提交前、提交后响应未知或关闭失败都会向调用方报错，不伪造成功、不自动盲重试。重放同一来源事实后由仓储核对实际结果；接收时间不参与内容/候选指纹，已有记录保留首次回执。每个写事务均显式使用 synchronous_commit=on。

## 验证与剩余范围

独立 PostgreSQL 17.11 测试库实际执行 14 个集成用例，另有 4 个隔离安全测试：原始/重复路径、精确字节与纳秒、跨租户输入、首次隔离回执、8 个并发异内容请求的一条原始与七条隔离，以及连接/提交/关闭不确定结果重放。66 张原有业务表的完整行摘要与 V29 前保存的基线一致；两张新事件表是本轮预期写入目标，不计入不变表集合。

首次辅助核对误用了只排除原始事件表的旧脚本，因新隔离表被纳入比较而报差异；保留原基线，明确排除两张本轮目标表后核对全部 66 张原表，未发现业务行变化。真实进程崩溃、掉电或两事务间断电恢复未执行；故障测试仅模拟连接/提交/关闭异常。
