# 监控复发与正式工单关联（2026-10-23）

本功能补齐 M5-4 中同租户、同资产、同规则的工单去重接线。新监控事件仍保留自己的事件 ID；若最近符合窗口的前序事件已关联未关闭的 WORKFLOW_V33 正式工单，则关联该工单。既有工单的状态、工程师、响应/恢复截止、档位快照和计时任务不重建。

## 输入和事务

- `POST /api/v1/events/ingest`、到期登记重试、`POST /api/v1/autoticket-attempts/{id}/manual-create` 共用逻辑。原权限、CSRF、幂等重放授权、事件/尝试 CAS、事务审计保持。
- 读取 `ticket.default_dedupe_window_sec` 最新已到生效时间的租户发布。PUBLISH/ROLLBACK 采用其正整数秒值；显式 DISABLE、到期、无效值返回 `422 CONFIG_PENDING`，整次命令回滚。没有已生效发布时读取配置登记中的合同默认 1800 秒；未来计划发布不会提前生效，禁止在停用/到期后回退默认值。
- 窗口比较两次事件的 `problem_at`，含边界，不使用重试到达时间延长或缩短窗口。按最近前序故障排序，仅选择一个已认领 WORKFLOW_V33 的候选；最新候选已 CLOSED/CANCELLED 时不再向更旧工单追溯。
- 指纹锁贯穿三条登记路径，自动重试在事件行锁之前取得指纹锁；候选工单在同一事务取得 WORKFLOW_V33 工单锁后重新读状态，与人工关单和时钟 Worker 串行。
- 关联、尝试状态和 `monitoring.autoticket.recurrence_link` 审计同事务提交。审计保留前序事件、目标工单、窗口和配置来源引用。新事件使现有工单 SLA 聚合重新看到未恢复事件，原截止不变；新事件尚未复核时沿用既有关单门禁。
- 没有正式激活的登记和 REVISION_V42 流程不参与本次复用：后者尚无同等监控恢复/关单消费，不能仅凭相同设备就跨流程绑定。已解决待客户确认的正式工单保持原状态，重开仍走现有客户动作，本次不冒充自动重开。

请求和响应字段不变；`SUCCEEDED`/`MANUAL_CREATED` 表示登记或关联成功，不保证新建独立工单。事件详情及尝试均返回同一 `ticket_id`。本功能不启动通知派发、不激活工单、不发送邮件或企微；现有通知意图保持既有流程。

本切片不重新生成已经消费的时钟任务，也不新增独立的复发通知意图；复发通知、自动重开以及对应计时任务恢复仍需后续接线。不能将工单关联成功解释为这些后续动作已经发生。
