# 独立“我的待办”入口：当前账号负责的工单

## 交付范围

新增 /my-tasks 路由和“工单与服务 → 我的待办”导航，与运营总览分开。当前只提供已接单、处理中、待客户确认三个状态下明确分派给当前账号的六态工单。待客户确认是跟进状态，不授权代客户操作。

读取复用已实现的 GET /api/v1/ticket-workflows，固定 assignee 为当前登录账号，单页5条；页面不接受URL或编辑字段覆盖负责人。逐项核对租户、负责人、工作流状态、时间、分页顺序和规范响应。只显示本页数量，不从有限分页推算全局总数、超SLA数或总体完成率。

页面提供刷新、上/下页、原页重试、取消和“查看与办理”到精确工单详情；进入详情后原有服务端授权与版本规则重新核验。读取不接单、不派单、不关闭、不发通知。

路由和导航同时要求 tickets:read、ticket_notes:write_internal，并限制 padmin/msp；页面同样检查这两项授权。routeAllowed 新增可选附加权限集合，既有单权限路由行为保持不变。此处不是新的“只能读取自己”的后端权限模型，既有内部工单API权限仍为权威；客户身份不获负责人筛选权限。

## 交互验收

- 初始/加载/成功/空结果/错误/取消/无权限分别展示。空结果仅说明当前状态本页无明确分派记录，不表示审批或其他待办为空。
- 原页重试固定筛选、签名游标和负责人；换筛选回第一页。取消及撤权中止旧请求，迟到结果不复现。
- 同步忙碌通知中撤权也会在派发前阻断GET；账号、租户、权限版本、account_version变化清理旧范围。单纯CSRF刷新不重复读取。
- 持久标签、原生键盘控件、44px目标、焦点轮廓、可聚焦表格滚动区、caption/表头和状态通知。取消回到刷新按钮，读取完成回到结果状态；不声称DOM验证等于真实浏览器可访问性验收。

## 真实服务与证据

使用全新临时 PostgreSQL 17.11、V1–V47完整迁移、合成账号/工单和当前API工件。先经真实仓储的既有授权转换生成16份合成登记（15份激活），不直接改写流程历史。未连接原服务器，没有客户设备或供应商发送。

21项HTTP检查（包括合成登录/租户选择）通过：当前账号7条已接单按5+2分页、2条处理中、1条待客户确认；实际游标重读保持相同ID/版本；详情链接目标匹配；跨状态/负责人/账号复用游标被400拒绝；客户筛选403、无关客户详情404。读取检查期间20张相关业务表指纹不变，HTTP检查没有流程写入。API、数据库、临时凭据已清理。

6份实际HTTP分页响应加入前端严格读取器回归，保留观察时间变化，未要求不同请求的整个JSON完全相同。单元/DOM、真实HTTP和浏览器三层证据不混算。

新增6项Playwright规格：320/390/768/1440回流、键盘详情、固定负责人、axe、取消焦点和撤权。可发现59项/8文件，但既有浏览器环境限制仍在，本次只发现脚本、不重试被拒绝的启动或绕行，所有真实浏览器结果仍NOT_RUN。

最初DOM链接测试只等待固定几个microtask，路由未完成就断言失败；改为等待实际路由变化后通过，不修改产品导航来迁就测试。完整测试/构建数量与源码摘要见 validation.json。
