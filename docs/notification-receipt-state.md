# 通知受理、送达与死信回放领域状态

## 已实现的范围

`DeliveryReceiptState` 是 M8-3 的纯领域切片，不是通知供应商适配、持久化作业、HTTP接口或实际发送系统。所有回执都是调用者显式输入；模型不证明供应商真实性、签名、接收人身份或终端送达。

- 每个逻辑投递绑定租户、投递ID和不可变去重键。去重键含资源池、事件、渠道、接收对象不透明ID、阶段；不保存手机号、邮箱、密钥或请求/回执原始正文
- 开始尝试只增加新请求号，尚无明确回执时为UNKNOWN；QUEUED、UNKNOWN、ACCEPTED均不计送达
- 只有显式DELIVERED回执使逻辑送达计数为1。多次回执、死信回放及较早尝试的迟到送达不会增加逻辑计数
- 已知FAILED可由上层明确登记死信；仅死信允许新尝试，必须新请求号、保留原去重键与全部历史。没有自动重试、默认次数、延时、短信额度或渠道降级
- UNKNOWN不能盲目重发，须先核实实际结果。较早尝试的迟到ACCEPTED/FAILED不改变当前尝试；任一已登记尝试的DELIVERED阻止后续回放
- 同一回执ID、相同事实重放为无写入、无版本增长的幂等返回；同ID不同事实409。租户/投递不匹配404；未知请求号、未来回执、尝试之前的回执拒绝
- 观察时间不倒退、逻辑版本比较、快照和列表不可变。保留纳秒，不将accepted或电话发起解释为接通/终端送达

DELIVERED优先保留是本切片的事实累积规则：后到的ACCEPTED/FAILED不撤销已有送达声明，但其历史仍保留。它不判断供应商矛盾回执是否真实；未来适配器必须做验签、绑定、去重、异常隔离及真实回执核查。

## 必须继续完成

Q14派发矩阵、Q18供应商/回执语义/重试预算/接收人/额度仍未确认，不启动付费发送、不创建账号。真实回执校验、供应商不透明请求号映射、真实数据库原子CAS/幂等/审计、事务outbox、Worker领取、并发回放与迟到送达竞态控制、短信月额度预留、页面8列及死信权限尚未接入。

模型中的版本比较不是数据库CAS证明。迟到送达可阻止下一次领域转换，但不能撤回已在网络上发送的另一次尝试；跨请求/供应商实际恰好一次效果尚未证明。保留去重键不等于供应商一定支持去重。

1000次尝试、10000条回执、阶段64字符是内存资源保护上限，不是客户批准的重试/保留策略。满额拒绝新记录，保留已有状态；已存在的完全一致回执仍允许幂等回读。正式持久化方案须处理长期历史与有界查询，不能据此自动删除回执。

## 验证

24项隔离纯测试，包括6种回执顺序、受理不计送达、跨租户404、版本冲突、重复ID冲突、未知禁止回放、死信新请求保留去重键、较早请求迟到送达、不可变快照、纳秒和资源边界。

该批没有真实通知、100条供应商样本、P95≤30秒、回调签名、死信页面或跨进程恢复验收；不能标M8-3 DONE。根回归与契约结果以 [本批证据](evidence/niko-notification-receipt-state-20261004.json) 为准。
