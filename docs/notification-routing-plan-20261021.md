# 通知路由决策切片（2026-10-21）

## 本步范围

依据 D11 第六节修订而非前文过期的 JPA、RabbitMQ 和固定 token 缓存示例，新增 NotificationRouter 纯领域决策。没有创建发送账号、凭据、付费通道或外部请求。

输入必须显式包含租户、资源池、事件、阶段、已解析优先级、矩阵发布引用、偏好发布引用、接收对象绑定、观察时间和查询所得去重历史。不存在从 V26 草稿到生效偏好的转换入口。发布引用只是本模型的输入证据标签，真实性、当前授权和绑定必须由后续仓储核验，不能由浏览器自行声明。

- 六类渠道采用稳定枚举顺序；每个渠道都保留独立决定与去重键。
- 未知优先级、未发布配置、缺失历史、缺失或过期绑定、未知静音策略均保持 CONFIG_PENDING。null 历史不是空历史。
- 级别与渠道偏好分别过滤；P1只绕过静音，不绕过绑定、矩阵或历史等其他门槛。显式空矩阵是只记录策略，不作为缺省补值。
- 同一资源池/事件/渠道/接收对象/阶段的已知尝试在固定5分钟内抑制；恰好5分钟结束窗口。未知结果不因超过窗口而自动重试。其他租户、资源池、事件、接收对象或阶段的历史拒绝混入。
- 聚合等待从事件时间起算，输出 notBefore；若绑定届时过期，不产生计划。重试次数、供应商接收、送达、预算和生产授权不在本模型中推断。
- 结果、集合防御性复制。绑定数量和历史数量为计算资源上限，不是客户保留政策；不会删除历史。

## 关键限制

PLANNED 仅为纯计算结果，dispatchAuthorized、dispatched、delivered 均为 false。计划不是事务锁、持久去重预留、队列、Worker或发送授权。部分渠道可计划不代表其他 CONFIG_PENDING 渠道可以被忽略。

后续必须把当前已发布矩阵、生效偏好、绑定与历史查询接入同一事务，持久保存每渠道决定；到达 notBefore 后重新检查当前授权、静音、绑定、去重和额度，避免在等待期间失效。还需补渠道配置/安全适配、供应商幂等、未知结果查询、回调认证、回执与死信页面。时间窗口到期本身不授权重新发送已有逻辑投递，仍须按 DeliveryReceiptState 和重放策略校验。

Q14/Q17/Q18 未决值仍为空，不私自替客户选择级别映射、接收人、供应商、短信额度或电话价格。V36不修改，本步无数据库迁移，无真实通知或正式验收。
