# 通知页权限清理与已读回读

基于 main f98180d，仅前端行为修正，无后端、DDL、外部派发启用或配置值补全。

## 修正的可观察问题

1. 页面上下文原来未包含角色和内部台账能力变化。即使后台拒绝后续请求，已经打开的台账仍可能留在页面。现在任一变化重置视图、清空缓存、取消在途台账请求；台账模板本身也要求当前授权，入口再次检查权限和未知写入锁。
2. 台账读取原来没有 AbortSignal，刷新失败时还保留旧记录。现在独立控制器可中止，读取前清空旧快照，错误不沿用旧成功数据。
3. 标记已读原来只局部替换消息，却未重读总未读数；旧观察时间及筛选也会不一致。现在写回执确认后使列表失效，再从第一页重新读取当前筛选。回读失败保留成功写回执，但数量保持未知，不虚构递减结果或重发写入。
4. 写入结果未知继续使用原幂等键恢复，不能切台账隐藏恢复入口；离开路由和 beforeunload 都保护未知结果。
5. 新增通知/台账返回第一页，台账可键盘横向滚动区域，按钮统一44px。

## 验证

6项新增真实 Vue/jsdom 组件测试：不升权限版本的撤权清理、角色变化迟到取消、写成功后计数回读、回读失败不展示旧数、未知写入原键恢复与卸载提示、台账失败清缓存。既有9项核心测试同时通过；写回执测试改为断言列表失效而非局部伪快照。
