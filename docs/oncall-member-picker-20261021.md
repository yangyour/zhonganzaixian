# 排班与交接的姓名候选选择

## 用户体验与范围

主班、备班和接班人员由纯UUID输入扩展为具名原生选择器，同时保留手动UUID输入。不自动选择人员，也不在读取候选后改写现有表单。

- 候选展示姓名、内部角色和UUID，同名人员可区分。主备不能相同，接班人不能是当前交班人；对应候选排除及原生自定义校验提示并阻止无效表单提交，不静默清空原值，后端仍重新验证。
- 使用原生select、input、fieldset/legend及关联label；必填、错误、说明有可访问名称/引用，错误同时进入原生表单有效性，不只变色。控件保持44px产品目标与可见焦点。
- 候选需要显式点击读取，使用既有GET /ticket-workflows/assignees。它仅覆盖当前租户活跃、有内部工单写入能力的内部人员，不是全部成员清单，也不是排班授权凭据。
- 该接口返回最多100人；超过100会返回422 ASSIGNEE_LIMIT，不是截断后返回前100人。页面明确此边界，不添加不受支持的分页参数，也不借前端扩大人员授权。
- 候选读取有独立取消、错误重试、加载及成功空状态。失败/取消清除旧选项但保留原人员UUID、排班和交接输入；仍可手动填写，保存时服务端核验。
- 候选读取期间手动UUID输入可继续使用，自动看板刷新暂停；取消焦点返回候选读取按钮。取消仅影响GET，不取消或撤销已提交排班/交接。
- 租户、账号、权限、account_version或写能力变化时清除候选并拒绝旧响应。子组件更新携带原范围标识，旧DOM事件不能在范围刚切换时重新写回旧人员。
- 运行上下文、待确认Q15、排班轮换和真实通知配置均未改变。没有新API、后台候选同步、角色创建或生产账号操作。
