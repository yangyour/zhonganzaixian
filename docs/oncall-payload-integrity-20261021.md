# 值班看板数值与记录完整性

## 修复

原读取器只检查部分外层字段、排班和策略形状，未完整检查KPI数值、队列和升级流水。新增onCallPayloadIntegrity统一校验，应用于看板读取及四类写入回执；不修改后端业务协议。

- KPI必须为合法非负安全整数，MTTA未知保留null，目标必须为正整数。不把有限队列行数推算为全局总数。
- 队列完整检查UUID、既有四种在途状态、优先级/档位、可空负责人、UTC日期时间、布尔超时状态及升级步/角色组合。倒计时允许合法负整数，进度为0到1有限数值；未知时保留null配对，不补零。
- 超时标记可能来自另一个SLA时钟，不以当前倒计时正负自行改写或拒绝该标记。
- 排班核查真实日历日期、正版本、主备身份及不同人员、备注边界与重复日期/班次；交接检查身份、非负计数及备注。
- 策略步骤必须连续、有限，等待时间和未接听阈值按既有协议范围。默认未持久化策略只能为version=0、updated_by=null；持久化策略必须正版本及合法操作者，不把默认配置称为已保存。
- 升级流水核查租户、身份、历史策略版本、等待及电话次数、下一步连续性、短信意图/摘要组合。拒绝未知DELIVERED状态，不能伪造已送达。
- 各列表拒绝重复身份和超出请求上限，不静默截断。通用协议最多100条；本工作区固定请求25条，接收端按25条核对。最多四种策略，未增加分页或改变业务上限。
- 任何载荷不合格均清除旧看板并提供只读重试，不显示错误数值、伪成功或假空队列。已保存回执仍独立处理，不能以新的GET替代未知写入核查。
