## 发现与修正

1. 旧 PostgreSQL 月报测试依赖其它测试先创建工单、交接、升级记录和服务档位。首次独立运行失败；补齐工单等后又因缺少服务档位被后端正确拒绝。现在测试自行准备所需合成数据；服务档位仅是测试夹具，费用、合同设备数、周期和可用率目标保持null，客户批准仍UNVERIFIED。未向生产添加默认值。
2. 4次真实PG执行（独立月报1次、全类3次）及27个HTTP检查均通过，但前端回放拒绝看板。捕获真实响应后确认：后端AUTO_REFRESH_SEC为30，前端与OpenAPI仍硬编码15。原模拟fixture也为15，掩盖了不一致。
3. 修正前端类型、严格读取器、定时器、页面文案、契约生成器及夹具为30秒；API契约版本0.70.0。仍拒绝旧15秒响应，不通过同时接受多个值来绕过不一致。
4. 将隔离HTTP的纯合成响应保存为 fixtures/oncall-http-synthetic-20261021.json。新增6个Web回归及1个契约回归，校验四种值班命令及月度冻结的原回执，防止只验证人工模拟成功。
5. 契约门禁发现M5-4进度说明缺少显式未完成标识，已恢复“完整TC仍NOT_RUN，非DONE”；没有修改或放宽门禁。
