# 值班看板到对应工单的办理入口

## 用户路径

倒计时队列和最近升级流水原先仅显示UUID，无法直接进入对应工单。现增加具名链接，按该行经过完整性校验的ticket_id打开既有/ticket-workflows详情路由。

- 队列进入当前工单详情；历史升级流水进入其自身对应工单，不借用第一条队列ID，不把历史升级记录当作当前状态。
- 打开详情只触发读取，不自动接单、发起升级或发送短信。详情重新读取当前状态，并按当前身份决定可办理动作。
- 保留原生链接href、键盘操作、可见焦点及44px点击目标。允许原生新标签打开，不强行改写链接行为。
- 在途读取/写入或未知提交期间不提供新的办理链接。保留旧DOM事件或旧行对象也必须通过当前权限、当前载荷身份和未锁定状态检查，不能派发旧导航。
- 普通同页路由切换沿用真实离开守卫。未保存输入可继续编辑；确认期间新改动使旧确认失效。未知提交不能靠离开页面丢弃原请求身份。

未增加新API、权限或状态机，不把六态工作流与七态生命周期混合；真实短信/呼叫、自动接单和生产执行仍未启用。

## 验证

新增9项合成DOM回归，使用真实Vue Router和memory history，不是只断言按钮文字：

1. 队列定位到确切ticket_id且无写入。
2. 历史升级记录按自己的ticket_id导航。
3. 取消离开保留原输入。
4. 批准离开不自动保存草稿。
5. 确认期间修改使旧导航批准失效。
6. 账号版本改变后的旧行不能触发navigate。
7. 同权限版本撤回能力立即移除入口并阻断旧事件。
8. 未知写入保留原请求并禁止办理跳转。
9. 真实TicketWorkflowsPage组件读取所选详情并显示其标题与接单入口，没有自动POST；API响应采用合成数据，部分Element Plus表格组件用测试替身，此项不代表真实浏览器/后端联合验收。

本地Vite启动后核对看板路由、看板组件、真实工单组件和错误组件四个HTTP响应，随后关闭。真实浏览器键盘/视觉/axe仍NOT_RUN，未绕过此前的环境拒绝，正式合同TC状态未变。
