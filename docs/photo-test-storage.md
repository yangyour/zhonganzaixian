## 准备与重入

先准备既有PostgreSQL/Keycloak项目命名空间，再执行：

```powershell
pwsh -File deploy/prepare-photo-environment.ps1
```

脚本只安装本机`.local/python-deps`的客户端依赖，复用现有SSH隧道。采用[官方MinIO Python SDK](https://github.com/minio/minio-py) 7.2.20进行S3/IAM调用，不将凭据放入命令参数、日志或公共证据。原服务器管理凭据只用于读取服务状态及创建项目桶、项目账号和项目策略；应用运行配置只获得新建的受限账号。

项目桶以`mop-project`和随机`mop-owner`标签标识。拥有者恢复资料及账号秘密只保存于被Git忽略的`deploy/private/photo-namespace.json`，环境变量引用写入同目录`runtime.json`。桶或策略已存在而本机无拥有者资料时会拒绝接管；已存在的账号有其他策略或群组时也会拒绝继续，不覆盖他人配置。

已有项目的重入校验桶标签、账号状态和完整IAM策略，服务端无语义差异的策略排序变化不造成误判。账号已附加本项目策略时不会重复发出附加写动作。失败只报告安全步骤名称，不打印SDK、SSH、JSON或响应体异常；不能据私有文件存在推定准备成功。

## 实际权限与证据

账号只允许本项目桶的ListBucket/GetBucketLocation，以及`photos/*`前缀的GetObject/PutObject。没有DeleteObject、CreateBucket、桶策略修改或管理权限。服务端允许的桶可见性如实记录为`DENIED`或`PROJECT_BUCKET_ONLY`，两者都必须保证其他项目桶不可见，不声称两者相同。

真实权限探测仅写入本项目、标为虚构组件验证的对象，验证原字节回读；删除、前缀外写入、匿名读取均应拒绝。探测对象继续保留，尚未确认清理策略时不擅自启用生命周期或删除。证据见[组件验证](evidence/photo-component-verification.json)：只记录版本、命名空间、权限行为与批准/联调边界。

用户先要求沿用客户文件策略，后明确“先支持常用的”。本轮开发方向据此选择JPEG/PNG；合同照片上限维持每张5MB、每份报障最多3张，实际实现将明确5_000_000字节上限。此开发方向不替代客户正式生产批准；病毒扫描/隔离、其他文件类型、其他单据额度和Q10保留/清理仍待确认，扫描不标为CLEAN、保留期限为null。

真实应用照片联调须另外证明API授权/CSRF/幂等、内容验证、PG耐久任务及MinIO结果、跨租户和报障人隔离、补传竞争/3张上限、授权下载与撤权、组件失败和重启恢复。组件探测成功本身不证明这些业务行为。
