## 实施范围

- 本地用户名/密码登录、当前账号、修改密码、管理员重置、启停及会话撤销；密码只保存带随机盐的自适应单向哈希，不记录明文或可离线猜测的普通请求摘要。
- 用户与当前租户成员管理；保持用户ID和既有业务/审计记录。授权范围必须明确，跨租户对象统一404，禁止凭全局角色越过当前成员关系。
- 四类合同基础角色作为业务类别；同类别可建立配置化角色并选择能力集合，能力不能越过基础类别的业务边界。菜单/按钮/API使用有效能力，数据库写入与Worker按当前成员及权限版本复核。
- 角色/成员修改CAS、幂等和审计；保护最后一个可用管理身份。用户停用、改密、重置和会话撤销使旧认证上下文失效。
- 统一认证保留OIDC适配及明确issuer/sub绑定。默认关闭外部提供方；不按邮箱/用户名自动合并账号，也不信任外部角色声明直接授予业务权限。
- 暂无邮件/短信恢复通道时由管理员重置，界面说明实际能力；不伪称已发送找回通知。

## 项目内权限使用与运维

账号登录入口为`/login`。管理导航提供“用户与成员授权”“角色与权限”“身份认证设置”，全部已登录项目账号可进入“我的账号”查看资料、修改本地密码。用户列表每页50条，支持账号/名称搜索和停用记录筛选；角色目录技术上限每租户200条（包含内置角色），创建时明确拒绝超过上限，不静默截断。

用户启停和密码操作作用于同一个全局用户ID，要求操作者具有该用户全部关联租户的管理权限，包括停用成员关系。租户成员启停、角色指派只改变选定租户；其他租户角色查询仍须具备该租户权限。角色管理权限是授权管理能力；仅有用户管理能力的委派角色不能授予超出自身基础类别和权限集合的角色，也不能重置更高权限的账号。内置角色不能修改，可复制为同类别自定义角色；停用角色或裁剪权限会推进受影响成员的权限版本。

当前会话每次请求重新检查数据库中的认证版本；改密、重置、全局启停、会话撤销、身份解绑使旧会话失效。前端导航回读最新会话权限，旧页面上下文变化会清除密码和待发命令。管理写请求使用CSRF、原请求幂等键、明确记录版本和同一事务审计；密码请求采用私有HMAC键计算幂等指纹，数据库回执中不保存明文、原密码输入或CSRF令牌。网络结果不确定时仅在当前页面内存中保留原命令并提供原键重试，离开前明确提示，不能据后续403判定原操作失败。

密码采用Spring Security Argon2id（随机16字节盐、32字节结果、19MiB内存、2次迭代、并行1）和版本化前缀，旧V27所允许的有界PBKDF2格式仅保留兼容读取。本轮技术输入上限为1024个UTF8字节；不代入客户未设置的业务最短长度、历史、锁定或强制修改规则。配置字段保持null，修改全局策略须有所有项目租户的角色管理权限。闲置策略若以后设置，仅应用于后续登录；未设置时沿用服务器原会话配置。

### 默认与可选认证配置

- 默认：`MOP_AUTH_MODE=project_local`，`MOP_OIDC_ENABLED=false`，私有`MOP_AUTH_COMMAND_KEY`为稳定随机64位十六进制值，仅位于受控环境文件。缺失时拒绝启动，不能生成临时键或退回夹具。
- 可选统一身份：设置`MOP_OIDC_ENABLED=true`及受控`MOP_OIDC_ISSUER`、`MOP_OIDC_CLIENT_ID`、`MOP_OIDC_CLIENT_SECRET`，向提供方登记`/login/oauth2/code/mop`回调。生产候选Issuer须HTTPS；现有指定测试realm和本机隧道路径是明确测试例外。签名、issuer、state、nonce、PKCE与授权码校验由Spring Security处理。
- 在用户详情的“统一身份绑定”中填写明确Issuer/Subject，外部账号才可映射到项目用户。不存在同名自动合并、邮箱匹配或外部角色自动提权；停用绑定撤销旧会话。真实外部提供方尚未按此新模式启用，不能把接口预留视为客户统一身份已联调。
- 服务器原共享Keycloak服务继续运行；默认本地登录的就绪检查不依赖它。只有显式启用OIDC时，才将提供方可用性纳入就绪检查。

### 本轮发现并处理的问题

1. 登录时服务端已轮换CSRF，但同次响应仍可能读取旧请求属性，已同步刷新请求上的令牌。
2. 原只读诊断的隔离JDBC测试未认识新增有效权限SQL，已补充明确查询替身及“padmin空权限不能回退”的反例；真实PG检查独立记录。
3. V28更新权限版本后旧导出任务会被拒绝，旧测试假定首个领取必成功；改为有界扫描已有队列，仍要求不创建额外任务。
4. 常驻联系人Worker与库级测试竞争虚构作业、追加审计，已暂停本项目三个Worker隔离回归，验收部署时恢复。保留竞争导致的首次失败结果。
5. 首页时间测试把本机时钟当成数据库时钟依据，实际环境不满足此同步假设；改为同一真实数据库前后时间窗口核对，`clock_accuracy_verified=false`保持不变，不修改服务器时钟。
6. 历史Linux私有文件权限测试在Windows上不能用POSIX模式位证明ACL，两项原断言在本机失败；本轮未降低文件保护。只将本轮相关迁移清单9项、部署守卫5项的实际通过列为证据。
