# Webhook 公网传输边界（2026-10-21）

## 本步实现

新增 PublicWebhookTransport，复用已锁定的 OkHttp JVM 5.3.2，不新增依赖。它是候选发送链中的受限传输层，不是供应商适配器、签名器、Worker、发送授权或回执验签服务。当前没有任何运行入口调用它，未向真实接收方发送。

- 只接受 HTTPS、443端口、精确小写ASCII域名白名单；拒绝IP字面量、通配域名、尾点、用户信息、查询串、fragment、非白名单目标与其他端口。
- 发送前一次DNS解析，检查全部答案；存在任何拒绝地址即拒绝整个集合。连接只使用该次已核验的不可变地址列表，保留原域名的系统TLS证书/主机名验证；不重新解析其他域名，不复用跨请求连接。
- 当前保守支持公网IPv4候选，拒绝私网、环回、链路本地、共享地址、文档/基准/多播/保留及特殊用途网段。IPv6和混合族答案暂不支持，明确拒绝，不静默改用其中一个IPv4。
- DNS等待最多5秒、并发最多2且不排队；阻塞解析不会无限占满工作线程。DNS超时不证明供应商投递失败，后续Worker仍须按已持久化的尝试阶段处理。
- 关闭代理、重定向、自动认证和连接失败重试；one-shot请求体，移除503的Retry-After自动重试触发。每次调用创建并释放独立连接池，不改JVM信任库、系统网络或全局TLS设置。
- 请求/响应体均上限64KiB，签名头只允许三种候选协议头，禁止注入Host、Cookie、Authorization或请求号；请求号由显式UUID提供，正文复制防止调用后修改。
- 不生成或保存密钥。签名算法、密钥版本和回调真实性必须由已批准供应商适配器另行完成。传输层只检查签名头形状，不能证明签名正确。
- 原始HTTP结果不转换为DELIVERED；连接后的异常保守标为TRANSPORT_OUTCOME_UNKNOWN，不授权自动重发。对象字符串和错误消息不输出目标、签名、正文或底层异常。

## 依据与限制

地址分类参考[IANA IPv4特殊用途登记](https://www.iana.org/assignments/iana-ipv4-special-registry)，实现刻意比可全局路由范围更严格；被允许仅表示通过此保守网络过滤，不证明目标可信、可达或收件人已获批准。登记变化需维护，且不能代替部署层出口限制。

Q18供应商协议/端点/凭据/回执、Q14矩阵、接收人绑定、额度、持久化尝试、通知Worker均仍是前置条件。URI白名单检查只有进入本传输构造器才执行；渠道配置保存API尚未接线，不能宣称“配置页已拒绝私网”。没有调用现有设备连接器的测试不校验证书模式。

后续需由已授权派发事务生成不可变请求，再调用适配器及此传输层；结果未知时查询原请求，不能更换请求号盲重发。DNS解析返回后若绑定、预算或配置失效，派发层还需再次阻止发送。签名候选头不是客户默认协议，不能直接把配置示例改为已启用。
