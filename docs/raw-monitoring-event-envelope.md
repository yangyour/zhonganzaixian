# 原始监控事件不可变信封

后续进展（2026-10-07）：已补[内部不可变存储与并发去重](raw-monitoring-event-storage.md)。以下保留纯信封切片的原始范围；来源认证、映射和公开接收仍待实现。

对应 M4-D05 与数据设计 raw_event / inbox 的基础部分。新增纯领域对象，明确来源池UUID、源事件ID、PROBLEM/RECOVERED来源阶段、调用方提供的租户/资产映射、源发生时间、接收时间以及原始字节。此阶段没有接收API、签名验证、映射查询、持久化、耐久队列或接收成功回执。

唯一来源键按池+源事件ID+阶段区分，问题与恢复阶段分开。内容指纹使用版本化命名空间及长度前缀UTF-8字段，包含键、租户/资产绑定、源时间的秒/纳秒和原字节SHA-256，不包含接收时间。重复投递改变接收时间不改变原事实；相同来源键而内容、源时间或绑定变化返回CONFLICT_REQUIRES_REVIEW，不覆盖原对象。不同来源键返回DIFFERENT_KEY，不按ID大小推断先后。

源时间保留纳秒精度，即使来源时钟比接收时钟快也不改写成接收时间；本类不认证时钟准确性，不决定迟到、未来时间、补偿水位或归并窗口。比较结果SAME_CONTENT只是纯内容相同，不代表数据库已经接收或处理，更不能作为Webhook成功响应依据。未来入口仍须完成签名、来源池、对象映射和当前授权检查；未知/跨租户映射应隔离，不能因能构造Binding就视为已授权。

原始payload构造时和读取时分别复制，保留原字节，不规范化JSON空白；摘要不是签名或身份认证。对象toString只给脱敏提示，不包含payload或源事件ID；访问原字节的后续调用者仍须按敏感数据规则处理，不能写日志。技术上限为1MiB原字节、源ID256个UTF-16单元；拒绝空值、首尾空白、控制字符与孤立代理字符。这些是资源限制，不是来源系统兼容或容量承诺。

本切片不包括原始记录实际追加、inbox竞争唯一约束、事件归并、五态转换、防抖、建单或通知。没有设置Q06/Q29未知规则，没有SQL/API变更。19项新纯测试覆盖来源时间、重复接收、相同键冲突、绑定变化、阶段/池隔离、原字节不可变、标识和payload资源边界、摘要确定性与脱敏；根回归结果见[证据](evidence/niko-raw-monitoring-event-envelope-20261006.json)。M4-8/M4-14及正式128项验收仍NOT_RUN。
