# 隔离 PostgreSQL 业务与 CMDB HTTP 验证（2026-10-21）

## 环境与结果

在 dot 自有临时 PostgreSQL 17.11 回环环境中，从新库显式初始化 V1–V45。使用项目自带的合成租户、工单和测试身份，不是客户数据或生产升级。运行时代码来自 afb2819eeddcc0b8410e766a37cbaf30d84fe7b5；e8cc7e6 仅补充冻结声明与首次迁移证据。API jar、45 个迁移及本轮测试源码/字节码哈希均已留证。

- attempt-3：5 个真实 PostgreSQL 测试类，14 项全部执行通过，0 跳过。
- 新增 4 项跨工单模型归属测试：双向排斥、并发创建只有一个成功、运行时不能直接抢占或删除归属记录。冲突返回 409；无双重事件历史。
- 真实 API HTTP：20 项请求检查通过（包括登录、CSRF、租户切换等准备请求，不是 20 个独立业务场景）。覆盖匿名拒绝、四个合成身份读取、伪造租户请求头不越权、查询参数拒绝、写方法拒绝、切租户和撤销成员资格。
- 成功目录读取前后业务库指纹不变；拒绝请求允许既有安全审计追加，其他业务表不变。不能把审计正常写入误报为只读接口修改资产。
- 业务事务后 schema 检查通过，执行 0 个迁移。
- API、PostgreSQL 均已停止，临时数据库和凭据已删除；邮件、企业微信及其他供应商发送关闭。

## 如实保留失败

attempt-2 的 14 项数据库测试中 13 项通过，1 项失败，HTTP 未执行。旧测试在验证跨租户资源隔离时错误复用了租户 A 的权限版本；本轮仅给合成租户 A 的 MSP 测试角色显式增加 tickets:lifecycle_write，A/B 版本因此不同，认证正确返回 401，而原测试期望 404。

修正测试为读取目标租户 B 的当前 membership.permissionVersion，保留原来的 404 隔离断言，不修改生产鉴权逻辑。随后从全新临时数据库重跑 attempt-3 全部通过。attempt-2 的失败摘要与逐用例结果保留，不能将它改写为成功；当时未提前保存旧编译测试类哈希，不声称有该证据。

V42 只扩展可授予权限上限，不自动授予既有角色。上述合成角色测试授权不代表客户授权或生产配置发布。

## 冻结与验收边界

V1–V45 字节没有改变，后续 DDL 必须 V46+。未运行正式 128 项全量验收，未验证真实客户有数据升级、生产监控、采集、外部通知或浏览器视觉交互。CMDB 仍是只读候选目录，四项客户歧义保持 null，不自动导入资产、创建客户账号或启用计费。

证据：docs/evidence/integration-pg-20261021/attempt-2 与 attempt-3。脚本是本次隔离环境的审计快照，含固定临时工具链路径，不能直接用于生产。重现需先准备同版本工具链、打包 runtime classpath、编译测试及 NikoSchemaBootstrap，并据 summary.json 的 source_snapshot 重建 snapshot.json；不得复用临时密码，也不得指向既有客户数据库。
