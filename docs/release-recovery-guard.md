# 发布和回退兼容性守卫

`tools/update-lan-test-server.py` 的发布／恢复入口现在共用回退快照守卫。它修复此前只比较“恢复前后schema相等”的不足：该比较无法阻止在发布后已发生迁移时恢复旧应用。新代码在新应用切换前、失败后自动回退前、显式restore前，要求实际Flyway历史与原事务的成功历史逐字段一致。

发布事务新增 `recovery_config_sha256`，仅在服务器原有私有事务文件中保存以下内容的SHA256：基础compose、原活动覆盖文件、项目.env与本次所用受控组件env、生成的rollback.json。比对时不输出配置内容／密码／hash集合。配置、凭据或恢复配方有变化则拒绝应用回退；读取失败也拒绝。回退不能重新激活已轮换的旧凭据。该校验是文件完整性和兼容性前置条件，不是凭据轮换执行器或密码保管服务。

手动恢复还要求非空、无重复、明确允许的应用列表；base文件位于既有项目目录内，rollback.json属于同一个事务。数据库／缓存／消息服务不能进入恢复服务集合。自动恢复时先检查再调用compose，门禁失败保持“恢复未确认”，不自动删除、降级迁移或重新创建基础服务。成功路径仍保留原有实际ready、非选中容器状态以及schema核验。

**历史事务兼容性变化：** 没有 `recovery_config_sha256` 的旧事务不再由新版工具自动restore，返回“legacy recovery requires review”。需要核对旧制品、当时schema、凭据和现状后走明确审阅的恢复方案；不要现场补造摘要来绕过门禁，也不要把此次新增检查等同于已有历史回退事务已可执行。若schema已变更，单纯恢复应用文件不一定兼容，必须另行评审。

对外调用仍为原 `update`／`restore`，没有新增部署权限或自动调度。程序内 `guarded_switch` 新增必填 `recovery_guard` 回调，调用者必须提供实际快照检查。构建、推送和本次单元测试均不执行该工具的CLI部署入口。

2026-10-23验证：`py -3.11 -m unittest discover -s tools -p test_lan_update.py -v`，30项通过（新增10项）。覆盖迁移后拒绝恢复、凭据变化、旧事务缺证、读取异常脱敏、外部路径／空服务／重复服务、切换前失败、失败部署后发生schema变化、手动入口检查顺序与锁释放；保留原成功恢复、部分启动失败、所有权和外发保护测试。仅合成对象／纯单元，没有读取私有资料、SSH、数据库、安装／停止组件或实际部署／回退；正式容灾恢复TC仍为NOT_RUN。
