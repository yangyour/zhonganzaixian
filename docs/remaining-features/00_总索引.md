## 代码核查结论（commit cca471d · 2026-10-17）

### 总体状态

- 合同 128 项正式测试用例全部 `NOT_RUN`；`production_ready=false`，当前代码只具备测试环境运行能力。
- 迁移 V1–V32 已字节冻结。新迁移按**合入顺序**从 V33 起编号，各子页写的 V33–V40 只是占位，不能当作已分配的版本号。
- 配置基线 `contracts/config-baseline.json` 共 185 个配置键，对应客户待确认事项 Q01–Q31。按 `AGENTS.md`：未确认的值一律保持 null，流程照常实现，配置发布后才生效，不得在代码里硬编码。
- 原子页通用性偏差：仓库包名为 `cn.mop.*`，**没有 JPA、没有 `@Scheduled`、没有 RabbitMQ 业务客户端**；后台任务是独立 Worker 进程 + PostgreSQL 租约；`mop_outbox` 只服务报障受理链，不能当通用消息队列。
- 其他关键更正：工单表 `mop_ticket` 的 V4 CHECK 约束冻结（D07）；AF 防火墙地址为 192.169.11.1（D05）；下载链接有效期 900 秒，不是 7 天（D12 / D14）；数据库层没有 RLS，合同 M2-5 要求 RLS，由 Q02 决定（D14）。

## 公共约定

> [!WARNING]
> 本节已按仓库实际约定（`AGENTS.md`、`doc/development/03_数据模型与接口实施约定.md`、`contracts/local-api.openapi.json` v0.52.0）重写；原「`{code, message, traceId}`」「`?cursor=&limit=`」「`X-Tenant-Id`」「`e2e/` 目录」等写法与仓库不符，已废弃。

### 技术栈与代码位置

- 后端：Spring Boot 3.5.16 / Java 17，Maven 多模块 `server/*`（`domain`、`persistence`、`adapters`、`api`、`worker`、`import-parser`、`asset-export`、`export-preparation-worker`），包名 `cn.mop.*`；照片 / 联系人 / 资产导入 Worker 都在 `server/worker`（`cn.mop.worker`、`cn.mop.contactworker`、`cn.mop.importworker`），按独立进程部署。
- 持久化用 JDBC 仓储，**不用 JPA**；后台任务是独立 Worker 进程 + PostgreSQL 租约（`lease_owner` / `lease_until` / `fencing_token`），**不用 `@Scheduled`**；仓库没有 RabbitMQ 业务客户端。
- 前端：`apps/web`，Vue 3.5 + Element Plus 2.14；页面 `src/pages/*Page.vue`，接口 `src/api/client.ts`，页面状态 `src/utils/*Workspace.ts`；当前未引入 ECharts，引入新组件需评审。
- 外部组件优先复用已选成熟组件（Zabbix 7.0、PostgreSQL、MinIO / OSS 等），新增组件须过 Q03 基线。

### 数据库迁移

- 目录：`server/persistence/src/main/resources/db/migration/`，文件名 `V{n}__{描述}.sql`。
- V1–V32 已字节冻结，禁止修改；新迁移从 V33 起**按合入顺序**取号，子页中的 V33–V40 仅为占位。
- 迁移由独立 CLI `TestSchemaMigration`（`deploy/migrate-test-schema.ps1`，账号 `mop_test_migrator`）执行，API / Worker 启动不自动迁移；运行账号 `mop_test_runtime` 需显式授权；新增表需同步 SchemaVerifier 与冻结清单。

### API 规范

- 成功响应 `{ "data": …, "trace_id": … }`；错误响应 `{ "error": { "code", "message", "details" }, "trace_id" }`。

- 租户来自会话（`POST /api/v1/session/tenant` 切换），**不用 `X-Tenant-Id` 请求头**；跨租户访问统一返回 404。
- 分页为 keyset：`page_size` + `before_created_at` + `before_id`（各接口允许的 `page_size` 以契约为准）。
- 写操作携带 `X-CSRF-TOKEN`、`Idempotency-Key`，更新类带 `expected_version`；耗时操作返回 202 + operation，前端轮询 operation。
- 功能可见性由 `CapabilityCatalog` 能力门控；新接口先改契约 `contracts/local-api.openapi.json` 再实现。

### 配置化

- 合同固定值、客户待确认值都登记为配置键（`contracts/config-baseline.json`）；待确认项为 null 时流程照常实现，计算结果返回「待配置」，不得写默认值。
- 运行配置通过 V32 发布机制生效；内部审批不等于生效（B06）。

### 分支与提交

- 仓库现用分支命名 `codex/<topic>-<yyyymmdd>`；按功能逐项提交，提交信息说明合同条款与验证证据。

### 测试规范

- 服务端：JUnit 5（`mvn -B -ntp test`）；前端：`apps/web/tests/*.test.ts`（vitest，`npm test`）与 `npm run build`；契约：根目录 `npm test`。
- 浏览器验证：`tools/verify-*-browser.mjs`（Playwright）；仓库没有 `e2e/` 目录。
- 外部组件联调必须在指定测试环境进行，不得以 fixture 或本地替代组件冒充；验收证据按同一制品记录到 128 项 TC。
