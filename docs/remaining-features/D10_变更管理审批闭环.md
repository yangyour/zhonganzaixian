```java
@Transactional
public void approve(UUID noticeId, UUID approver, UUID tenantId) {
    ChangeNotice notice = repo.findByIdAndTenantId(noticeId, tenantId).orElseThrow();
    if (notice.getStatus() != ChangeStatus.PENDING_APPROVAL)
        throw new IllegalStateException("只有待审批状态可批准");
    notice.setStatus(ChangeStatus.APPROVED);
    notice.setApprovedBy(approver);
    notice.setApprovedAt(Instant.now());
    repo.save(notice);
    outboxService.publish("change.approved", notice.getId(), tenantId);
}
```

## 三、变更窗口验证

**文件**：`src/main/java/com/mop/change/ChangeWindowValidator.java`
```java
@Component
public class ChangeWindowValidator {

    private final ChangeWindowRepository windowRepo;

    /**
     * 检查指定时间是否在某个变更窗口内
     */
    public boolean isInWindow(UUID tenantId, Instant targetTime) {
        List<ChangeWindow> windows = windowRepo.findByTenantIdAndIsActive(tenantId, true);
        for (ChangeWindow w : windows) {
            CronExpression cron = CronExpression.parse(w.getCronExpr());
            ZoneId tz = ZoneId.of(w.getTz());
            ZonedDateTime target = targetTime.atZone(tz);

            // 查找 cron 表达式在 targetTime 前最近一次触发时间
            ZonedDateTime windowStart = cron.previous(target);
            ZonedDateTime windowEnd   = windowStart.plusMinutes(w.getDurationM());

            if (!target.isBefore(windowStart) && !target.isAfter(windowEnd)) {
                return true;
            }
        }
        return false;
    }
}
```
**在执行变更时调用**：
```java
@Transactional
public void execute(UUID noticeId, UUID actorId, UUID tenantId) {
    ChangeNotice notice = repo.findByIdAndTenantId(noticeId, tenantId).orElseThrow();
    if (notice.getStatus() != ChangeStatus.APPROVED)
        throw new IllegalStateException("必须先审批才能执行");

    // 验证变更窗口
    if (!windowValidator.isInWindow(tenantId, Instant.now()))
        throw new OutsideChangeWindowException("当前时间不在变更窗口内");

    notice.setStatus(ChangeStatus.EXECUTED);
    notice.setExecutedAt(Instant.now());

    // 告警抑制：将设备标记为维护模式内， Zabbix 将忽略告警
    if (!notice.getDeviceIds().isEmpty()) {
        zabbixService.suppressAlerts(
            notice.getDeviceIds(),
            notice.getPlannedEndAt()
        );
        notice.setAlertSuppressed(true);
    }

    repo.save(notice);

    // 自动创建 P3 工单，指定进行变更操作
    Ticket p3 = ticketService.createAutoP3(
        notice, actorId, tenantId);
    notice.setAutoP3TicketId(p3.getId());
    repo.save(notice);
}
```

## 三补、自动创建 P3 工单实现

**文件**：`src/main/java/com/mop/ticket/service/TicketService.java`（新增方法）

```java
/**
 * 变更执行时自动创建 P3 工单，将变更报备关联到工单。
 */
@Transactional(propagation = Propagation.MANDATORY)
public Ticket createAutoP3(ChangeNotice notice, UUID actorId, UUID tenantId) {
    Ticket t = new Ticket();
    t.setTenantId(tenantId);
    t.setTitle("【变更工单】" + notice.getTitle());
    t.setDescription(
        "根据变更报备自动创建。\n\n" +
        "变更范围：" + notice.getScope() + "\n" +
        "计划开始：" + notice.getPlannedStartAt() + "\n" +
        "计划结束：" + notice.getPlannedEndAt()
    );
    t.setPriority(TicketPriority.P3);             // 固定 P3
    t.setStatus(TicketStatus.IN_PROGRESS);         // 直接进入处理中
    t.setAssigneeId(actorId);                      // 指派给执行人
    t.setAcceptedAt(Instant.now());
    t.setSlaDeadline(calcDeadline(t, tenantId));   // P3 SLA
    t.setSourceType(TicketSourceType.AUTO_CHANGE); // 标记来源
    t.setSourceRefId(notice.getId());              // 关联变更报备
    ticketRepo.save(t);
    eventRepo.save(TicketEvent.of(t, actorId, ACCEPTED,
        Map.of("source", "change_notice",
               "changeNoticeId", notice.getId().toString())));
    outboxService.publish("ticket.accepted", t.getId(), tenantId);
    return t;
}
```

## 四、Zabbix 告警抑制

**文件**：`src/main/java/com/mop/monitor/ZabbixMaintenanceService.java`
```java
@Service
public class ZabbixMaintenanceService {

    private final ZabbixClient zabbixClient;

    /**
     * 创建 Zabbix 维护期，抑制指定主机的告警
     */
    public void suppressAlerts(List<UUID> deviceIds, Instant until) {
        // 将 deviceId 转换为 Zabbix host ID
        List<String> zabbixHostIds = deviceIds.stream()
            .map(deviceRepo::findZabbixHostId)
            .filter(Optional::isPresent)
            .map(Optional::get)
            .toList();

        if (zabbixHostIds.isEmpty()) return;

        // Zabbix API 创建 maintenance
        zabbixClient.createMaintenance(
            "MOP-Change-" + Instant.now().getEpochSecond(),
            Instant.now(),
            until,
            zabbixHostIds
        );
    }
}
```

| 前文写法 | 应改为 |
|---|---|
| V37 `ALTER TABLE change_notices`、新建 `change_windows`（cron_expr） | 表为 `mop_change_notice_draft*`（V25 冻结）；审批状态与有效窗口新增 V33+ 迁移；变更窗口规则 `backup.change_window`（Q22，null），不要先行写死 cron 模型 |

### 合同要求但前文未覆盖

- **M6-7 / M4-17**：每 6 小时（`config.diff_interval_hours=6`）SSH 拉取 running-config 与上一版 diff，与 D17 备份**共用一条 diff 链**，不重复建设。
- 检测到变更 → 生成 **info 级事件**；该时段无对应报备单 → 升级为 **P3 工单「未报备配置变更」**；有报备单 → 仅记录事件不建单。
- 报备单字段：报备设备 / 变更内容摘要 / 计划执行时间 / 申请人 / 审批状态（现有草稿已覆盖前四项）。
- 差异行定位准确（脱敏后仍可定位行号）。

### 修订后的实施步骤

1. V33+：报备审批事实（审批人 ≠ 申请人、审批时间、结果、版本）与「生效报备」视图；审批岗位按 Q09。
2. 在 D17 备份 Worker 产出新版本后计算 diff；有差异时写入监控事件管线（D15）生成 info 事件。
3. 实现报备匹配器：设备 ∈ 报备设备集合且变更检测时间落在计划窗口内（容差读 `backup.change_window`）；配置为 null 时结果为「待配置」并保留人工处理，不自动建 P3。
4. 未匹配 → 通过 D15 自动建单规则创建 P3 工单（幂等键：设备 + 备份版本），工单时间线引用 diff。
5. 前端：报备草稿页增加提交审批 / 审批 / 驳回；设备详情展示 diff 与匹配结果。
