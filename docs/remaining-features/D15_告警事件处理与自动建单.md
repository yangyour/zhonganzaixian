## 二、处理链设计

```plain text
Zabbix 7.0.31（Action → Webhook 推送；event.get 按水位拉取兜底）
  → 接收端点（资源池级 HMAC 签名，非会话认证）
  → mop_raw_monitoring_event（已有，不可变）
  → 映射 pool_id + host → (tenant_id, asset_id)；失败 → mop_monitoring_quarantine（已有）
  → 指纹归并 (tenant, asset, rule_code)，窗口 event.merge_window_sec；灾难/严重绕过聚合等待
  → 防抖：flap_window_sec 内翻转 ≥ flap_flip_count → 静默 flap_silence_sec
  → 依赖抑制：上游（Proxy / 核心设备）PROBLEM 时抑制下游通知，事件照常记录并标记 SLA 未知
  → 维护窗口静默：SUPPRESS_NOTIFY 或 PAUSE_COLLECTION
  → mop_monitoring_event（新）处置状态机
  → 自动建单决策 → D07 工单（幂等键 tenant + incident）
  → mop_notification_intent 通知意图（D11 新建；V4 mop_outbox 与工单一对一且状态固定 CONFIG_PENDING，不作通用 outbox）
补偿：每 300 秒回看 900 秒复扫；Webhook 落库失败载荷保留 24 小时
```

## 三、数据库迁移（V33 起，按合入顺序分配版本号）

公共要求：V1–V32 字节冻结；每个迁移带 `current_database()<>'mop_test'` 守卫，只向 `mop_test_runtime` 授最小权限；配套 `XxxSchemaVerifier.java` 与 `tools/niko-test/frozen-*.json`；由 `TestSchemaMigration` 独立执行（API / Worker 启动不自动迁移）。所有业务表带 `tenant_id`，用 `(tenant_id, asset_id)` 复合外键防跨租户。

| 新表 | 关键字段 | 合同 |
|---|---|---|
| `mop_raw_event_processing` | raw_event_id、status、lease_owner、lease_until、attempts、last_error | 处理租约（V29 原表不可改） |
| `mop_monitoring_quarantine_decision` | quarantine_id、decision（BIND_ASSET / DISCARD）、bound_asset_id、decided_by、reason | M4-14 人工核验 |
| `mop_monitoring_event` | tenant_id、asset_id、rule_code、severity_rank（0–5）、fingerprint、occurrence_count、monitor_state、handling_state、suppression_reason、problem_at、recovered_at、first_ack_at、ticket_id、version | M4-8 / M4-11 / M4-14 |
| `mop_monitoring_event_member` | event_id、raw_event_id | M4-8 原始事件全部可查（×N） |
| `mop_event_noise_record` | event_id、layer（MERGE / FLAP / DEPENDENCY / MAINTENANCE）、recorded_at、detail | M1-2 降噪漏斗、M4-7 抖动记录 |
| `mop_event_source_watermark` | pool_id、last_eventid、last_clock、updated_at | M4-14 水位补偿 |
| `mop_maintenance_window` | name、scope、starts_at、ends_at、silence_mode、sla_exclusion_requested、sla_exclusion_confirmed_by / at、status、created_by、version | M4-10 |
| `mop_alert_rule`、`mop_alert_rule_tenant_override` | rule_code、severity、expression、duration_sec、recovery_hysteresis、flap_control、template_ref、enabled；覆盖人、覆盖原因 | M4-5 / M4-6 |
| `mop_controlled_macro` | macro_key（如 `CPU.UTIL.CRIT`）、默认值（取 M4-18 基线）、租户覆盖、审核状态 | M4-5 |
| `mop_autoticket_rule`、`mop_autoticket_attempt` | 等级集合、排除规则（rule_code / 资产标签 / 维护窗口）、aggregate_wait_sec、dedupe_window_sec、字段映射、路由；attempt、next_retry_at、status | M5-4 |
| `mop_monitor_template`、`mop_template_rollout` | version、checksum、layer、lld_limit、macro_count；stage（CANARY / OBSERVING / FULL / ROLLED_BACK）、observe_until、exit_metrics | M4-12 |

事件处置状态：`NEW → ACKNOWLEDGED → IN_PROGRESS → RESOLVED → CLOSED`（M4-14 五态），监控恢复后进入 `PENDING_REVIEW`（M4-11 待复核），人工确认根因后才可到 `RESOLVED`。复核转移细则由 `event.review_transition_policy`（Q29）配置。

## 四、后端实现

- **适配器**（`server/adapters/.../monitoring/`）：在现有 `ZabbixReadClient` 旁新增 `ZabbixEventPuller`（`event.get` 按 eventid 水位拉取，用于补偿）；Zabbix Action 的 Webhook 指向接收端点。
- **接收端点**：`POST /api/v1/monitoring/pools/{poolId}/events`，用资源池级 HMAC 密钥认证（现有控制器均为会话 + CSRF，不能直接复用）；落库成功才返回 202，失败载荷保留 24 小时。
- **领域纯函数**（`server/domain/.../monitoring/`）：`EventFingerprint`、`FlapDetector`、`DependencySuppressor`、`MaintenanceWindowMatcher`、`EventHandlingStateMachine`、`AutoTicketDecision`，全部不依赖时钟和数据库，便于边界测试。
- **event-worker**（新进程，参照 `contactworker` 的 PG 租约轮询；不使用 `@Scheduled`，不引入 RabbitMQ 客户端）：领取未处理原始事件 → 映射 / 隔离 → 归并 → 防抖 → 抑制 → 静默 → 写事件 → 自动建单 → 写通知意图 `mop_notification_intent`（D11）。同一指纹串行处理，避免并发合并错乱。
- **补偿 Worker**：按 `event.compensation_interval_sec` 周期，以水位回看 `event.compensation_lookback_sec` 复扫，按 `content_fingerprint` 幂等去重。
- **对外 API**（会话租户、keyset 分页、写操作需 `X-CSRF-TOKEN` + `Idempotency-Key` + `expected_version`）：
	- `GET /api/v1/events`、`GET /api/v1/events/{id}`（含原始成员、降噪记录、通知空态文案）
	- `POST /api/v1/events/{id}/acknowledge|start|resolve|close`、`POST /api/v1/events/bulk-actions`（批量确认 / 批量建单 / 加入抑制）
	- `GET /api/v1/events/noise-funnel?window=24h|7d|30d`（M1-2 漏斗）
	- `GET /api/v1/monitoring/quarantine`、`POST /api/v1/monitoring/quarantine/{id}/bind-asset|discard`
	- `GET|POST|PATCH /api/v1/maintenance-windows`、`POST /{id}/extend|end|confirm-sla-exclusion`（SLA 排除仅服务经理）
	- `GET /api/v1/alert-rules`、`POST /api/v1/alert-rules/{code}/tenant-overrides`、`POST /{code}/enable|disable`
	- `GET|PATCH /api/v1/autoticket-rules`、`POST /api/v1/autoticket-attempts/{id}/manual-create`（隔离后人工补建）
	- `GET /api/v1/monitor-templates`、`POST /{id}/rollouts`、`POST /api/v1/template-rollouts/{id}/promote|rollback`
- 同步更新 `contracts/local-api.openapi.json`（当前 0.52.0）和 `build-api-contract.mjs` 产物。
