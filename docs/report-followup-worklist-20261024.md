## 功能与实际调用

报告中心增加默认折叠的“跨报告未读跟进”。选定冻结时间起止（UTC，起含止不含），显式查询全部已发布修订、有未读接收人或超过7天未读的修订，按发布时间/文档UUID倒序分页。点击某行直接打开现有报告详情及单修订阅读看板，复用原权限与查看流程。没有新增大块统计卡、导航或全局样式。

`GET /api/v1/report-publications/followups?from=<UTC>&until=<UTC>&filter=ALL|UNREAD|FOLLOWUP_DUE&before=<UTC>&before_id=<UUID>`。from/until必填，默认筛选FOLLOWUP_DUE，游标必须成对；拒绝重复/未知参数和租户覆盖，时刻为规范UTC毫秒。响应no-store，无写方法。

要求当前有效成员同时具备dashboard:read、inspection_quarterly_reports:read/write。仓储使用独立REPEATABLE READ身份事务，不能嵌入已开启的写事务；在同一连接核验结构、权限/成员/账号、读取窗口内文档及最新状态、核对原载荷摘要、读取首次阅读记录并计算所有汇总。控制器返回前再次检查会话、账号/成员及权限。查询客户自己阅读权限不等于管理权限；所有对象读取按当前租户限定，不接收跨租户参数。

完整窗口核算后再过滤和分页，不能仅在普通报告第一页中筛选。最多扫描1000文档（包括范围内未发布草稿），50000已发布接收人人次，原载荷合计32MiB，扫描时间预算30秒、每条SQL超时10秒。超过预算422 REPORT_FOLLOWUP_SCAN_LIMIT，要求缩小范围；损坏数据503，无部分成功统计。预算是技术保护，不是客户容量/性能验收。每页20份修订，跨页重新观测，不宣称跨HTTP分页是冻结快照。

只复用已发布修订冻结的接收人和已有首次阅读规则，严格超过7×24小时才算待跟进。报告修订分别计数，同一人收到多个修订按人次统计；停用/后改策略不改写旧接收名单。未读不表示消息未送达，阅读不表示客户验收。此入口不登记阅读，不生成提醒/重发意图，不访问供应商。

前端核验窗口、租户、计数守恒、技术预算、时间、筛选、人群、顺序、游标和返回行后才显示；错误清除旧结果，重试保留原游标，取消回到重试按钮；切换范围、角色、模式、账号/成员权限或折叠时取消请求并丢弃迟到响应。表格有独立键盘滚动区域。
