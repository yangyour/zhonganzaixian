# R02 报告更正与不可变新修订

原报告退回后只能查看，不能继续更正。本次接通从季度冻结来源创建新修订的仓储、API、页面和原请求恢复；退回或已发布报告可明确选择同季度冻结来源、填写更正原因并生成新DRAFT。原文档、原HTML/PDF、审核/发布历史和阅读记录不覆盖，新修订重新生成和审核，客户来源与模板门禁保持。

仓库、独立工作区、分支和本轮HTTPS后置要求见[接续记录](gap-followthrough-20261024.md)。本功能无需新增SQL，V1–V55字节保持；本次真实验证复用指定LAN PG17.9的保留V53验证库，活动mop_test保持V50，不应用迁移、不部署、不发送消息。

## API与事务

新增 `POST /api/v1/report-publications/{id}/revisions`，严格字段为 `expected_version`、`source_id`、`expected_source_sha256`、`reason`，返回新的 `ReportPublicationSummary`。要求当前身份、报告写/来源读权限、CSRF与单个Idempotency-Key。tenant、parent/family/revision、配置策略、报告字节均由服务端确定，不接受调用方覆盖。

仓储锁定父文档、复核状态版本及当前策略，拒绝已有后续修订的父文档，防止不同命令并发分叉。此路径要求READ_COMMITTED，锁后检查可见已提交子修订；不在快照隔离下假设等待行锁后能看到新子记录。新冻结源必须是同租户、相同季度且摘要匹配。新文档、首条CREATE状态、审计及幂等回执均在同一命令事务内；原父文档不更新。

主要拒绝码：`VERSION_CONFLICT`、`REPORT_REVISION_EXISTS`、`REPORT_REVISION_PERIOD_MISMATCH`、`CONFIG_PENDING`（REGENERATION_POLICY_MISSING）、`OBJECT_NOT_FOUND`。修订达到既有100000技术边界返回`REPORT_REVISION_LIMIT`。这不是客户业务配额，也不改变既有保留/删除策略。

`MOP_REPORT_PUBLICATION_POLICY_JSON`中的既有`regeneration=NEW_REVISION`继续由受控配置提供；未配置则拒绝，不替客户填值。未核验来源和模板的incomplete_reasons从新冻结源重新生成，不能通过修订去除门禁。普通运行环境和API/Worker迁移限制保持。

## 页面行为

报告中心在退回/已发布详情提供“选择冻结来源并创建新修订”。进入既有季度来源页后明确读取一个冻结报告，再回到原报告；服务端当前版本与选择时版本不一致时禁止悄悄采用新版本。输入更正原因后才发送命令。成功转入新修订详情并聚焦标题，可回读上一修订。

写入前保存最小原请求，响应丢失/刷新后仅通过原path/body/key确认；GET或重放被拒不能冒充原写入已失败。回执核对租户、新身份、parent、DRAFT、初始状态版本、所选来源摘要及更正原因。撤权/换租户取消读取并清空旧数据；未提交原因离开时确认，确认期间的新编辑不被旧确认丢弃。新增链接符合24px最低目标大小，未更改菜单或全局样式。
