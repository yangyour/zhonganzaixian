# 运行配置目录与发布表单恢复

基于 main 2278d9c，保持 API 0.71.0 和 V1–V45 不变。此批修复前端交互与范围/版本保护，不发布任何实际配置、凭据或生产授权。

## 发现的问题

1. 运行配置 API 与当前合同基线已包含186个键，页面仍硬编码185，导致完整目录被误判为不完整。原页面测试只执行setup且不检查目录，未覆盖这个实际入口故障。
2. UTC表单使用 Date.parse 后转ISO，会把某些无效日期（例如2026-02-30）归一化成另一日期，改变用户意图。
3. 页面只保护未知提交，没有未保存输入的切换/离开提醒；提交采用最新回读版本，不能明确证明基于哪次准备。

## 修复

- 目录及登记表分别按本次编译的 config-baseline 键集合完整核对；拒绝缺项、重复和等数量替换，不把固定数字185改成另一个硬编码数字。标题由基线键数计算。此静态基线仅用于完整性核对，不填充未发布运行值。
- 解析UTC前严格验证真实日历、0001—9999年、Z及最多3位毫秒；无效输入原样保留并提示，不发送POST。合法精度规范化不改变时刻。
- 明确“准备本次发布”绑定当前配置键、发布版本和定义摘要；刷新不偷换准备版本。版本/定义变化须重新准备并核对输入。
- 未保存编辑在切换配置、重新准备、选择回滚、主动离开或切租户时确认；取消保留全部输入。beforeunload保护未保存和未知提交；成功回执已确认则不把残留展示误报成未保存。
- 回滚选择获得丢弃确认后清除之前的日期、原因与确认勾选，保留明确准备的版本。未知提交继续只能恢复同一路径/幂等键/请求体。
- 校验中抑制重复请求；切换提案/授权、重置或卸载中止校验并忽略迟到结果。旧上下文的提交回调不清除新上下文表单。
- 现有控件改为44px产品目标、清晰键盘焦点。实际DOM用例覆盖目录渲染、明确准备、原生控件输入、无效日期提示及取消切换保留原因。
