## 缺陷与修复

此前克隆器对 pg_dump 文本使用两次 `splitlines()`。它会将 SQL 字符串中的 CR、U+0085、U+2028、U+2029 等也当作分行符，再拼接成 LF。指定 PG17.9 的只读比较确认：旧 M02 保留库有 **26 个约束对象**的字面量与活动 V55 不同，包含原始监控/隔离仓储、附件、工单文本等边界约束。旧库保持原样，没有修写或删除；此前各切片的验证范围继续按原证据解释，不把它扩大为完整旧结构/生产验收。

新增 `tools/postgres_schema_text.py` 按 SQL 引号、转义字符串、嵌套注释及 dollar 引号边界扫描，不重排 SQL 或替换字面量字符。仅删除顶层配对的 pg_dump 客户端 restrict/unrestrict 行，以及已确认空 public schema 的顶层冗余创建语句。函数体里同样的文字不删除；未知客户端命令、顶层集群/数据库命令、截断文本和错误引号拒绝执行。工具仍须验证指定主机、项目及目标数据库所有权，扫描器不是通用 SQL 防火墙。

还原前后都比较表达式的字符串值与完整函数原文摘要。新建的独立 PG V55 验证库只复制 schema、55条原迁移历史和能力字典，**0条客户业务数据、0次迁移重跑**；创建时120张业务表为空。新库全部字面量/函数摘要与活动库一致，旧26项差异仍可被检测。

PostgreSQL 对还原 SQL 的重解析还会规范化布尔 AND 分组及 varchar 数组到 text 数组的转换表达式。经逐项比较、相同字面量/函数证明和真实仓储测试，V29/V30 守卫增加了各自一个**精确、固定的还原目录 SHA256**。原执行目录摘要继续接受；旧损坏目录摘要仍拒绝。列、类型、约束数量、主外键、生成列、函数体、所有者、ACL、持久性及禁止改写等其他门禁保持。没有用子串、去空白或“语义看起来相同”替代目录检查。V1–V55 SQL资源字节及原冻结记录均未修改；守卫调整和验证期间持有自己的 migration.lock。
