# UI03 搜索返回复核与监控账号上下文失效

本dot从main `de43dd5a`继续用户授权的剩余开发。核对M1-5/7/8/9/11现有实现后，优先修复实际复现的读取边界，而不重做已存在的最近7条、铃铛、固定布局或M7门禁。

## 实际缺陷与修复

全局搜索仓储在单一只读RR快照核验当前权限，但Controller之前只在进入时读取成员，数据库读取后到HTTP返回前没有复核完整成员/会话。新增8项测试分别在search返回期间撤销成员、停用、改变权限版本、角色、能力集合、租户、会话或主体；修复前8项全部失败，因为旧结果仍被返回。

现在Controller保留确切初始Membership，起始核对身份/租户匹配，并将search:read、assets:read、tickets:read三个前置要求与实际仓储对齐；返回前复用DashboardReadAuthorization，同时核对完整成员和项目账号状态。结果不向客户端部分发送，失效返回401 SESSION_EXPIRED。5项真实Spring过滤器/MVC协议用例验证no-store错误且没有data分组。不是实际PG或浏览器联调。

监控事件中心与网络监控页面使用“多个值getter”监听，之前遗漏account_version；仅账号版本改变而租户/成员权限不变时不会清理旧请求。两项新增迟到响应测试在修复前均失败：AbortSignal仍为未取消。现将账号版本加入两处上下文依赖，立即取消旧读取、清空原事件/设备/资源/历史/输入状态，只有新请求可回填；新增已渲染历史与私有查询清除检查。没有修改布局、样式、菜单或刷新策略。

最近事件子组件已有独立账号版本回归且采用getter数组对象触发方式，本轮实际检查通过，未把它误报为同一缺陷或重复改动。全局搜索组件、首页、值班看板已有对应上下文处理，继续复用。

## 兼容和仍未核销

API路径、查询参数、5/4/3/3分组上限、JSON字段和既有HTTP契约回放完全不变，因此公共契约不生成无意义差异；生成一致性继续检查。没有新增数据库结构、依赖、配置、迁移或外部调用。M7脚本搜索仍NOT_IMPLEMENTED/Q01门禁。搜索旧兼容字段notification_bell_status不承载独立铃铛实时状态，已有铃铛API/组件不能据该字段被误判为未实现；后续接口版本演进另处理，不在安全修复中破坏旧消费方。
