# SLA 诊断范围：接口、读取器与浏览器样例一致性修正

基线 main bbb1f81bfff1dda2b10f5ae5a8a8e8a583a55a6d。复核既有OpenAPI发现TicketSlaInspection最多64个clock_tasks、20个sla_references，而前一浏览器样例曾产生60个来源；此前通过的是读取器兼容检查，不是这些契约边界。保留原证据并显式更正，不把错误样例视为有效验收。

## 修正

- 不放宽或改写既有契约。浏览器样例保留60个任务用于分页，冻结来源改为最多20个；断言核对完整第20项，不再要求不应出现的来源末页按钮。
- 前端读取器显式拒绝65个任务或21个来源，返回413 SLA_INSPECTION_LIMIT；不截掉多余记录后显示成功，原工单GET恢复继续可用。
- 服务端按同样边界拒绝超限。任务SQL只取65个用于有界lookahead，发现第65项则整次读取失败；冻结来源超过20项同样失败。不改真实任务、不删历史，不把技术上限当作合同费用/配额或SLA业务策略。
- 新的域限制类与持久层调用不改变V1–V50任何SQL资源，不自动迁移或启用任务。
- 组件独立60行压力测试仅验证通用分页能力，不意味着接口允许60个来源。

## 工具链恢复及失败保留

Maven3.9.11从官方Maven Central取得并核对SHA512；完整Temurin17.0.20.1+1由官方Adoptium元数据提供并核对SHA256。仅在dot自有工作区安装，不修改用户设备、系统安全设置或任何凭据。

系统原有Java21是运行时，缺少完整编译器符号表，release17编译曾失败。恢复后的独立JDK17直接下载依赖又遇到信任链错误，未跳过TLS或导入新CA；最终由原系统Java运行Maven、使用系统既有有效证书链获取官方依赖，完整JDK17作为外部javac及测试JVM。代理只复用当前执行环境已提供的无凭据代理，每次命令重新读取其临时地址，不固定失效端口。

另保留JUnit测试初放入无JUnit依赖的domain模块导致的编译失败（移至已有测试依赖的persistence模块），以及Mockito动态附加失败导致的首次全量错误。使用其官方依赖自带的启动期javaagent运行测试，未开启系统附加权限或绕过沙箱。所有失败与最终结果分开记录。
