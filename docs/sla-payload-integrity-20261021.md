# SLA 月报完整性与派发前授权检查（2026-10-21）

本次修正客户端边界，不改变后端可用率、合同计费或赔付公式，不生成正式账单。

## 问题与修复

既有月报读取器核对了顶层身份、服务字段集合和部分未知区间标志，但未逐项验证服务数值及嵌套对象。明细读取器也未完整验证服务、解释区间和工单判定。因此错误字符串、非有限数、负时长、重复服务或不一致解释可能被当成已校验结果交给页面。

现在增加：

- 百分比必须为有限 0–100 数值或明确 null；计数、时长和金额必须符合现有整数合同，拒绝负数、字符串数字、布尔值及不安全整数，不自动纠正或补零。
- 服务 ID/名称须为有效文字，同一报告不允许重复 ID；既有 CORE_NETWORK 等稳定非 UUID 标识继续合法，不擅自改成 UUID-only。
- KPI 和延迟统计核验完整字段。零样本对应 null 延迟，有样本时延迟为非负整数，P50 不大于 P95；未恢复计数独立保留，不错误推断必须小于已恢复样本数。
- 解释区间核验种类、严格 UTC 起止、正时长和原文。用 BigInt 纳秒比较，整数秒按后端 Duration 的正区间截断语义核验，不用 Date 浮点毫秒改写原时刻。
- 明细外层与 service 内的重复区间解释必须一致；工单判定字段、状态、时间和身份去重也核验。
- 实时月度评估使用与已保存快照相同的数值类型门禁；赔付仍为 CONFIG_PENDING_Q26，compensation_amount_fen 必须为 null。历史公式版本兼容性不变。
- 月报/明细 GET、快照 POST 派发前重新核对 epoch、当前权限或取消状态。若同步状态回调或生成请求 key 的回调已撤权/重置，不再发出旧请求。

本增量不重算业务统计，不把未知变成零，不按前端结果变更合同账务。异常读取清空相应旧结果并显示错误，原月份和已确认保存事实按既有规则保留。
