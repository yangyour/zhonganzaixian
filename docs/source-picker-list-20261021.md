# 来源集合的分页执行单选择与明确修订核对

## 用户现在可以怎样操作

1. 点击“读取执行单候选”，查看当前租户未归档执行单的资产名称、执行单编号/版本、冻结模板及人工填写数量。只显示当前页15条，不自动读取、选第一项或推断总库存。
2. 点击某行“核对此修订”。候选行须仍属于当前有效页，读取固定执行单ID、修订版本并约束该行内容SHA256；核对模板、人工内容与完整来源摘要。
3. 明细核对通过后再点击“添加至集合”。读取或选择本身不保存集合，不自动加入来源，不执行扫描。重复的同一执行单修订仍禁止再次添加。

原有手动执行单ID和历史修订号入口保留，支持未出现在当前候选页中的明确历史/归档修订。选择较早修订不会自动升级到当前头版本。

## 恢复和交互

- 候选列表独立取消/原页重试，保留成对时间/ID游标。失败或取消不是空列表，空页也不表示没有历史或归档记录。
- 来源核对独立取消/原目标重试，并继续约束最初内容摘要，不因重试放宽校验。修改手动目标立即清旧证明和重试目标。
- 父页面锁定、身份范围变化、页替换后的旧行事件都不能派发旧选择。来源读取在发送前再次复核范围与取消状态，不只是事后拒绝迟到响应。
- 使用原生按钮、表格caption/列头、具名可横向滚动区域、44px目标、可见键盘焦点。候选行可通过资产名称、版本和完整ID区分，但jsdom不代表屏幕阅读器/视觉验收。

遵循[前端验收标准](frontend-acceptance-standard.md)。前端复用既有受保护API，不增加权限、生产配置或自动扫描。
