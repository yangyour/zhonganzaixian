# D04/D05/D07 UTC时间回读严格校验

## 实际缺陷与修复

审查现有前端发现三个读取入口仅依赖Date.parse或“正则+Date.parse”：报障登记operation、配置来源诊断observed_at、手工资产资料时间。JavaScript可能把2月30日/非闰年2月29日自动归一到3月，也可能接受裸数字、日期串；Date.parse还把纳秒截为毫秒，无法发现同一毫秒内updated_at早于created_at。

5项新增回归先失败（该轮101项中5失败/96通过），确认不是凭推测修改。新增公共utcInstant工具：仅0001—9999年的完整UTC/Z时间、可选1—9位小数；对整秒做ISO日历往返校验，拒绝不可能日期、24点/闰秒/非UTC偏移/日期-only/多余字符，再使用BigInt组合秒与9位小数。原字符串不截断、不重写。utcNotBefore比较精确纳秒，包含负Unix时间场景。

接入上述三个验证器；operation及资产快照还检查updated_at不早于created_at。配置诊断仅确认原observed_at格式，不把观察时间当批准、生效或监控采样；报障仍PENDING/CONFIG_PENDING，资产仍按原source/status/未采集约束。其他模块已有各自时间校验，本次未声称全面替换或所有时间入口均审计。

## 2026-10-04 台账显示、资料分页与修订时间补齐

继续检查发现三处：台账采样显示会把不可能日期归一成另一天；资料分页用毫秒比较created_at，纳秒不同却可能误用UUID决定顺序；修订updated_at与created_at也被截断到毫秒。这三处统一复用严格UTC/BigInt纳秒解析，保留服务器原字符串与成对游标，不改查询参数、写命令或后端契约。

7新增用例中6缺陷回归先红，修复后49定向与894Web、类型/构建、70契约/生成一致通过。覆盖同毫秒内正确/反向排序及下一页边界、无效采样日期、合法闰日精确采样、修订倒序1纳秒。未扩展任何业务默认值。

真实验证先在session读取阶段失败，刷新既有六个OIDC测试会话后完成7个GET：30条实际资料/2页、15条空采样保持缺失、1个原有已撤回修订完整JSON不变、425条登记前后hash一致。该次30条资料的创建时间没有微秒/纳秒尾数，精度边界只由隔离回归证明；15条实际资产均无采样，未声称验证真实监控时间。0新业务写、0新测试对象，原失败记录保留。见 [实际只读结果](evidence/niko-asset-time-client-http-20261004.json) 和 [本次汇总](evidence/niko-remaining-utc-20261004.json)。
