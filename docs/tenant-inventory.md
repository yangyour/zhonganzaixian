# 租户已登记资源只读仓储

## 范围和真实来源

M2-1 当前新增 `authorizedTenantInventory`，复用现有PG表、运行账号及连接池，不迁移、不新增租户/用户/凭据/权限。返回租户ID、名称、原created_at、登记资产行数、登记站点行数、当前活跃用户且活跃成员关系数量。

这些是本次数据库快照中的记录事实：登记资产包含草稿与已有测试数据，不能称在线/已采集/计费资产或配额占用；站点是登记表数量，不是Zabbix Proxy健康；活跃成员数不等于MFA覆盖或当前在线人数。租户活跃/接入中状态、隔离模式、资源池、三种配额及利用率、Item/NVPS、保留期、ITSM方式、网络拓扑仍无已验证来源，后续DTO必须明确null，不从演示值或旧注册设计推断。

当前只是仓储功能，无新增业务HTTP接口、导航或12列页面；列表/详情字段一致、80%黄/95%红和客户验收未执行。

## 授权及一致性

独立readonly REPEATABLE READ事务中先复核当前租户成员、活跃用户、精确权限版本及padmin角色，然后只查询该用户在每个目标租户也具有活跃padmin成员关系的记录。平台角色不会绕过目标租户授权；其他三角色403，失效/缺少成员或旧版本401。拒绝在既有写事务内调用，避免隐式退化成跨语句READ COMMITTED。

一次请求的授权和计数在同一快照；之后的撤权不会追溯撤销已经完成的读取，下一次必须重新授权。没有修改授权矩阵或创建全局浏览权限。当前仅分页列表，没有单对象详情接口，不声称新增跨租户详情404验收。

按规范小写UUID升序keyset，after_id可空；limit 1–101（为未来100页长加1探测）是技术读取上限。未知/非法游标不拼SQL，所有参数预编译绑定，SQL超时10秒。未提供平台总数/全局排名或未授权租户名字。计数使用Java long；未来JSON边界须避免JS浮点精度丢失，不能因为数量超界返回0。
