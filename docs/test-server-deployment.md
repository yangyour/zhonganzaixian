# 指定服务器验收部署

2026-10-05 用户授权将当前代码部署到指定测试服务器，以服务器 IP 和独立端口验收；发现问题及时记录、修复并回归。新版应用复用原 PostgreSQL、Keycloak、MinIO，不启动本机业务后端或新增基础组件。

## 外部登录入口

原 `remote_test` 仅接受 SSH 回环 `mop-test` / `mop-web`。新增显式 `MOP_TEST_PUBLIC_ORIGIN` 后，仅允许同一配置源的 `/realms/mop-acceptance` 与 `mop-web-acceptance`；不从浏览器 Host 选择身份源。HTTP 仅限明确 IPv4，HTTPS 可用明确域名；用户信息、路径、查询、片段和无效端口均拒绝。既有本地模式保持。

验收复用现有 Keycloak 服务，独立项目 realm/client/六个虚构身份，绑定新的平台测试用户及原两个虚构租户。原 realm、原身份 subject、原成员权限不变；原身份消失或绑定不一致时禁止按同名账号恢复权限。随机密码与 client secret 只在 Git 忽略的私有配置保存。此入口不是生产身份源批准。

新增端点策略和原身份映射共8项隔离测试通过；真实服务器 OIDC/CSRF/租户及浏览器验收待部署后独立留证。API 路径和0.44契约不变。当前1660项 Web 测试、类型与构建通过，不能据此认定真实组件已验收。

## 部署与数据库边界

项目目录限定 `/opt/mop-platform-test`，网页入口10010、API仅回环18010。预选10001已占用，保留原服务。复用已存在且按 image ID 固定的 Java17、Nginx 镜像；只创建本项目应用容器，不重启或改变共享组件。API、三个专用 Worker 均不得自动迁移；运行环境不包含迁移或 Keycloak 管理员凭据。

迁移前实读原库V22，保存本机忽略目录中的 PGDMP 副本和48张既有业务表摘要，尚未恢复演练。V23–V26已按独立CLI逐项执行各1次，重复执行各0次，最终只读检查0次。迁移后58张业务表，原48张表的行数与全行摘要全部一致；121项隔离迁移保护通过。首次迁移后快照沿用旧的单个json_build_object聚合，表数超过50后查询失败；改为同一只读快照内按名称聚合后通过，没有重做迁移或改变旧数据。见[原指定库V26证据](evidence/designated-schema-v26-20261005.json)。

本机历史进程记录中一项PID已复用，经CIM创建时间证明原进程不再存在后归档记录；没有停止该PID。首次迁移前检查正确拒绝旧启动记录。首次聚焦测试命令受PowerShell逗号及点号参数解析影响，调整为整体参数引用后8项通过；失败输出保留在忽略目录。

上线状态、验收范围、问题修复与完整合同剩余项以随后实际部署证据为准；正式128项仍未完成验收。
