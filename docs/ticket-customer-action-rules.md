# D07 客户动作的合同固定校验核心

`TicketCustomerActionRules` 是独立纯Java校验器，覆盖 M5-15/M5-17 的确定约束。当前未接入HTTP或PG工单事务，不新增接口、工单状态或客户批准记录，首次切片时实际API为V0.8；当前V0.14的其他功能不代表本校验器已接线。不能据此宣称客户确认、重开、SLA或完整工单闭环完成。

## 已实现的输入边界

- 新鲜有效成员身份缺失/撤销返回401；工单不存在或租户不匹配统一404
- 仅客户角色viewer/tadmin且为报障人或当前启用决策人，才可通过这一层关系检查；msp/padmin不能借报障人或决策人字段代客户确认
- `Relationships.complete=false`明确表示关系查询未完整完成，返回503；不能把未知联系人列表当空列表，也不能从不完整结果放行
- 解决说明至少20个Unicode码点，边界空白不计数（含不间断空格）；未解决、重开原因不可空白，无效UTF-16代理字符拒绝。校验不重写原文
- 关闭后72小时包含精确边界；超过1纳秒即拒绝。关闭时间/当前时刻缺失、未来关闭时间不被解释成可重开
- 关系集合防御性复制且不可修改；输入变化不能改变已构造关系集合

## 接入前必须完成

这些输入不是认证机制。真实调用方必须在当前租户受限事务内回查成员、权限版本、报障人和启用决策人，禁止从浏览器接受身份、关系或complete标记。正式动作仍需Q07状态/权威策略及Q09资格来源；本工具没有替代这些决定。

真实HTTP需保留CSRF、幂等、expected_version/CAS；工单状态、处置动作、审计与outbox必须原子保存。确认、超时关闭及重开竞争需验证；原SLA截止及历史关闭记录不得改写，Q27未确定口径不补值。仅通过本校验器不得直接生成已关闭、已重开、已客户确认的事实或API成功响应。

## 验证边界

11项JUnit是合成输入的隔离校验，包括客户/内部角色、对象404、撤权、关系未知、集合不可变、19/20码点、补充平面字符、Unicode空白及72小时纳秒边界。它们不读取私有配置、不启动替代组件，也不证明真实客户资格、PG并发或UI验收。

运行：`mvn -B -ntp -C -pl server/api -am -Dtest=TicketCustomerActionRulesTest -Dsurefire.failIfNoSpecifiedTests=false test`。完整Maven、契约检查及真实环境未执行项分别记录于[验证记录](verification.md)。
