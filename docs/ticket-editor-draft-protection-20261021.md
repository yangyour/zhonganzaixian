# 工单备注、客户沟通与工时的组合草稿保护

## 修复范围

内部备注和客户沟通此前主要阻止未知提交丢失，但不同工单间替换目标和离开页面没有完整保留未提交文字。两个组件现在提供原始输入快照与明确离开确认，抽屉收起仍保留原内容；未知提交始终拒绝放弃，不用“丢弃草稿”来绕过原请求恢复。

TicketsPage统一协调内部备注、客户沟通、工时三个保留编辑器。切换某一面板的工单目标前先确认其输入，等待期间目标、范围或文字变化则旧确认失效。取消确认重新打开原面板，不把文字移交到新工单，也不在内部备注与客户评论之间复制内容。

离开整个页面或主动切换账号时，按顺序确认必要编辑器，再核对所有面板的整体快照。一个面板确认后在另一个确认等待期间产生的新输入仍会阻止离开。确认本身不清空草稿，只有实际目标/上下文改变后才按原规则清理。

## 异步与范围门禁

- 自愿租户/退出守卫支持不可变基础值快照，检查开始与全部守卫完成后比较；守卫注册集合变化或快照读取失败也拒绝。旧单参数守卫继续工作。该机制不阻止强制会话失效后的安全清理。
- 页面离开确认完成时，为本次导航追加范围/输入复核，排在已经登记的后续路由守卫之后；成功、取消、目的组件加载失败及卸载都会清理临时复核器。不会保留一次确认作为未来通行证。
- 三个编辑器由父页协调时不再重复弹出各自的离开确认；单独使用仍保留自己的守卫。
- 备注/评论准备、保存及原请求恢复完成后，只有原范围和原输入仍匹配才更新/清空表单。旧保存后的列表回读结束不能清掉另一工单的新输入。
- 角色、account_version和当前权限纳入范围标识并同步清理，旧私有文字不会继续展示给新身份。
- 关闭浏览器时有当前文字或未知提交会触发浏览器既有未保存提示。读取失败不再一直显示“正在读取”；未知提交文案明确刷新不能确认原请求。
