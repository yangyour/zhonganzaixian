# D07 生命周期持久化接续

## 本批实现

- 新增 V33 候选迁移：不可变解决快照与只追加生命周期修订；V4 报障、operation 和原 outbox 不改写。
- 生命周期按租户 / 工单加事务 advisory lock，版本连续追加；数据库触发器核对状态转移、身份角色 / 报障人关系、负责人范围、解决快照绑定和关闭凭证。
- 开单规则快照及原响应 / 恢复截止在后续修订保持不变；解决文档按 SHA-256 关联。
- Java / Python / Windows 独立迁移入口新增显式 ticket-lifecycle 模式，补资源哈希和结构 / ACL 核验。API / Worker 不自动迁移。
- 新增 JDBC 仓储：当前读取、历史分页、开单、工程师动作和客户动作，复用平台受保护幂等事务；修订、解决文档及审计一起提交 / 回滚，不启动独立写事务。
- 读取带解决证据的修订时，重新严格解码文档，并核对租户、工单、版本、解决人、时间与 hash；损坏数据不作为成功结果返回。
- 写功能由 MOP_TICKET_LIFECYCLE_ENABLED 显式配置，默认关闭；仅接受精确 true / false，拼写或类型错误拒绝启动；缺少开单规则或 SLA 截止返回 CONFIG_PENDING。配置 JSON 只接受明确允许字段，不接收任意对象。
- 新增可授予的 tickets:lifecycle_write / tickets:customer_decide 能力。V33 仅扩充角色能力上限，不为已有内置或自定义角色自动加权限；现有成员仍需显式授权。新租户内置角色沿现有初始化机制生成。

## 验证

- PostgreSQL SQL 解析器通过 13 条语句，PL/pgSQL 两个函数语法检查通过。初次函数检查发现 CASE 表达式需要括号，已修复尚未应用的候选并更新候选哈希。
- 独立迁移选择、资源和仓储边界定向 Java 检查，以及身份能力目录、工单领域回归已实际执行。随后完整 Maven verify 成功：JUnit 报告 2989 项，实际执行 2092 项，环境条件跳过 897 项，失败 / 错误 0；跳过项不计通过。
- 32 项 Python 迁移 / 私有配置保护测试通过。
- 仓储边界测试只使用拒绝连接的 DataSource 替身，验证禁用时零连接、写入必须处于幂等事务、数据库失败不伪装为空列表、非法分页与自动关闭入口拒绝。这些不是 PostgreSQL 集成测试。

## 仍未完成与依赖

V33 **尚未在任何数据库执行**。文件名中的 frozen 清单是兼容现有工具的候选资源 pin，不是已执行或已验收声明；V1–V32 仍字节冻结。真实 PG 约束、权限、并发、事务回滚与迁移前后旧表指纹均 NOT_RUN，原因仍是缺少受控测试连接配置；不得将静态 SQL 解析当成执行验证。

本批尚未接入公开动作 API、前端按钮、自动关单 Worker、SLA 状态持久化或通知意图。客户动作暂收紧为当前报障人，决策联系人需真实关系绑定后再开放；返回仓储 Entry 是内部数据，不可直接作为客户 DTO 暴露工程师标识。

后续 API 服务必须从服务端核验后的规则来源构造 opening snapshot，不能接受客户请求直接传入开单 JSON、截止时间或配置批准标记。通知 / 外部 ITSM 未配置时应显示未接入，不声称已经送达或同步。正式 D07 和全部 128 项验收保持未完成。

本地首次完整验证受 Mockito 动态附加限制和工作副本缺少原仓库 SCP 配置示例影响。使用已安装测试依赖的启动 Java agent、补齐仓库原示例后重跑；未降低 TLS 或操作系统安全限制。
