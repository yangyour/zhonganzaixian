# 工单详情实时摘要与可操作入口

本批复用现有生命周期/SLA API和写入工作区，不新增业务状态、写协议或数据库结构。详情原有固定阶段、固定“优先级/SLA暂未提供”和始终禁用的转派入口，改为使用同一受控子面板的实际回读。

## 一份来源，不重复推断

`TicketLifecyclePanel` 向详情发送已校验、当前授权代次的生命周期摘要；`TicketSlaPanel` 仅发送同一生命周期版本的时钟。详情不另外请求同一接口，也不从内部备注或客户沟通推断流程完成。

- 头部显示当前生命周期状态；基本信息显示同版本优先级与服务档位、服务端时钟截止值。
- 阶段标识只依据当前状态、明确方案时间/摘要和关闭方式。超时自动关闭不会标成客户已确认，也不宣称所有历史步骤均已发生。
- 生命周期未创建不等于其他处理模型不存在，保留按同一工单ID进入既有工单处理页的入口。
- 导出只包含当前已读取范围，未读/失败保持明确；不再承诺外部ITSM启用后自动关联。登记数据自身的MOP权威来源、外部同步NOT_APPLICABLE按实际字段展示。
- 报障202受理不再被界面描述成“系统正在创建正式工单”；登记列表不再用始终为空的registration.state推定所有工单都待分派。

## 操作仍需明确确认

转派、等待厂商、恢复处理快捷入口来自既有当前状态/角色/能力动作集合。点击只选中并聚焦现有表单，仍需目标、原因、勾选确认与显式提交；不会自动写入、发送通知或暂停SLA。存在不同动作的未完成输入时，快捷入口拒绝覆盖，要求先核对/清空。

未知写结果继续使用原请求重试；详情关闭与导航原保护保留。通用“申请协助”仍缺独立业务持久链，保留明确未实现边界，不把“转派保留原协作人”假称成完整协助申请。巡检证据绑定同样未以改写冻结SQL解决。

## 授权与迟到结果

生命周期、SLA时钟、口径绑定、提醒记录和详情读者统一包含账号版本、完整能力、角色、租户、主体及上下文代次。账号变化同步清空已展示事实/确认状态并中止旧请求。仅CSRF轮换不改变授权代次。口径与提醒两个子面板的账号变化回归先各失败1项，修复后通过。

## 验证与环境边界

最终结果见 `docs/evidence/ticket-overview-live-state-20261024/validation.json`。真实Vue组件+Element Plus的DOM测试覆盖摘要、SLA、快捷准备、未确认零提交、保留已有原因、账号撤权和迟到结果。

新增三项浏览器规格，全部200项/32文件仅发现。另创建无业务网络/写入的独立合成页面并编译。当前已有云端Chromium，但从该浏览器访问回环预览返回连接拒绝；受控预览启动遇到环境初始化限制。未绕过限制，未取得真实页面检查通过；原预览进程已以退出码130停止，失败页已关闭。先前“浏览器启动不可用”更精确地收敛为本次浏览器与执行沙箱预览无法连通，不能把DOM或编译当浏览器验收。

无真实数据库写入、迁移、部署、设备操作或外部通知。本批继续独立分支提交，main集成方式仍待用户确认。
