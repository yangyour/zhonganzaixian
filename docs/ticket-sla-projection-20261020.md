# 服务端工单 SLA 历史投影（2026-10-20）

## 本步骤

`GET /api/v1/tickets/{ticketId}/sla` 在当前租户授权的只读一致性事务中读取不可变开单快照和完整生命周期历史，输出观察时刻、生命周期版本、配置摘要、响应/恢复时钟、已结束暂停区间及缺配置原因。读后再次核对当前成员权限，客户仍限本人报障，不暴露工程师或内部配置内容。

- 响应时钟只在首次接单停止，转派及待厂商不重置。
- 待客户确认暂停恢复时钟；已关闭工单以解决时刻停止，不把客户确认等待当成解决耗时。
- 重开使用原始预算。Q27 的 `sla.reopen_and_mttr_policy.clock_policy` 需明确为 `EXCLUDE_CONFIRMED_PAUSES` 或 `INCLUDE_ALL_ELAPSED_TIME`；不认识或缺失时返回 CONFIG_PENDING，不选默认。
- 基础档有效用时只计开单时冻结的工作区间；标准/进阶为连续时间。超时依据服务端计算的截止时刻，前端不自行判定。
- 冻结配置重新计算并核对快照、原始截止时间、租户和连续版本；缺历史、未来事件或快照不一致不返回替代成功。在线技术上限为10000个版本，超过时明确拒绝而不截断算成功。
- 修正超大 SLA 参数可能生成四位年份之外截止时间的问题，超界返回 DEADLINE_OUT_OF_RANGE，不产生不可读时间。

详情面板与当前生命周期版本绑定，显示服务端观察时刻、时钟状态、有效用时、预算和已超时标识；租户/权限变化立即清空并丢弃迟到数据。只有显式刷新才更新时间，不做浏览器端假计时。提醒送达、月度结算及生产批准不在本步骤中声称完成。

## 配置和遗留边界

配置示例 `deploy/examples/ticket-lifecycle-configuration.json` 新增Q27空项。Q27发布值若在开单时已存在则随快照保存，之后修改当前配置不会追溯改动历史工单。

历史开单未携带Q27时，本步骤保持重开时钟待配置；后续需要独立、可审计的口径绑定流程补充，不能偷偷修改原始开单快照。P3日期目标没有时长预算时保留预算null，不伪造百分比；下一步提醒Worker需要明确该类目标的进度口径。SLA提醒持久去重、通知意图和升级链仍待接线。
