# 内部备注与客户沟通的原读取恢复

基线 main 166c46dd2e1fa9b927e94516b52cfe1e020bc2de。按[前端验收标准](frontend-acceptance-standard.md)的状态完整、安全恢复、范围隔离和焦点反馈门禁补齐两种文字记录的读取路径。

## 实现与边界

- 读取父工单与记录列表可显式取消，二者共享中止信号；取消只停止本次读取，忽略迟到结果，不取消保存、不撤销后端操作。
- 失败和取消保存原页目标，下一页的时间与ID双游标一起保留。重试重新核验同一父工单、完整记录范围、摘要和版本，不悄悄回到第一页。显式新读取替换旧恢复目标。
- 未保存文字、表单原版本和未知写入的原key/原载荷不受只读恢复影响。未知写入仍不能提交新内容；GET成功不确认原POST，只有显式“重试提交”恢复原写入。
- 已接受的保存回执独立保留；其后列表读取取消/失败不会变成“保存失败”或再次POST。
- 采用共用读取恢复控件，取消后焦点移到具名状态提示，按钮采用44px产品目标。原文字与未知请求状态可在实际抽屉中继续核对。
- 通知回调及请求标识生成后复核原范围；reset/dispose阻断尚未派发的GET/POST，旧回执通知也不能借用新工单自动读取。局部随机源/标识错误明确表示未发送，不伪造未知提交。
- 账号版本、租户、工单、身份或权限变化仍同步清理。内部备注与公开评论保持各自可见性和存储路径，没有跨面板复制文字。
