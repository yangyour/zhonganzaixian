# 原不确定写入在重试被拒绝后继续保护

## 问题与修复范围

首次写入可能已经提交，但200响应在网络/客户端丢失。随后用原键重试若被400/403/404/409/422拒绝，只能证明这次重试未成功，不能倒推出首次请求没有提交。旧11个前端writer把这次4xx降为rejected，导致unresolved保护解除，可能允许新键重复登记或错误离开。新增回归先在全部11处复现，再修复。

覆盖设计配置草稿、配置提案/审批动作、工作日历、本人工时、手工来源登记、人工恢复、内部备注、客户评论、资产依赖、基础资料、补充维保。send区分首次明确动作与原请求retry：首次明确4xx仍是rejected；原uncertain重试任何错误继续uncertain，原body/key/path/版本不变。只有核对通过的成功原回执可解除该不确定状态；强制会话/租户失效仍清保护上下文，不以此恢复旧授权。没有自动重试、自动换键或覆盖。容量新writer已先采用同样规则，未重复修改。

## 验证

11新增回归分别覆盖400/403/404/409/422，共55分支。修前11失败/623原有通过；修后完整634Web、类型构建、55契约通过。既有“首次409明确拒绝不重试”测试保持通过。

实际WorklogWorkspace、ConfigurationRevisionWriter和ApiClient连接真实niko PG/OIDC：31HTTP，工时创建/修改和配置提案创建各丢弃一个已提交200，再用实际不具备该能力的会话重试得403，保持原不确定状态，恢复原身份后原键重放200。9次受测写尝试仍只有工时1行2版本2成功审计、配置1份DRAFT提案v1；配置登记/有效值不变。普通GET虽能看到写后记录，仍不替代原请求确认。其他9个writer是隔离回归，未冒充新增HTTP覆盖。

前两次探测在合成父登记POST被真实CSRF_INVALID403拒绝；重新采集6个获准测试身份的会话后完整通过，未绕开CSRF。失败批次未并入31计数，没有输出凭据。
