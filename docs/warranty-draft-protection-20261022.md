# 维保完整草稿确认与目标保护（2026-10-22）

## 用户可见行为

依照项目既有前端验收规范的错误预防、可取消交互、原输入保留及键盘离开保护要求，补齐已存在的维保编辑器，不新增虚假功能菜单。

- 基于当前档案准备表单时记住原始字段；实际修改才算未保存草稿，不将未修改的已载入表单视为脏数据。
- 重新准备、取消编辑、切换另一资产以及离开页面/切换租户/退出，都必须通过未保存草稿确认。原始空格及非法日期同样是需保护的输入，不用规范化后的值判断是否相同。
- 同资产重开、收起面板继续保留草稿。原 PATCH 未确认时不能通过放弃确认销毁原请求；关闭页面前的原生提示覆盖草稿与未知写入。
- 确认仅作用于弹窗发起时的完整输入、基准、当前档案和身份范围。输入或目标在等待中改变，旧批准作废；不会抹掉后来的内容。
- 重新准备的 GET 完成前也检查原表单；服务端版本低于父资产台账时不采用。已知父版本前进会暂停旧表单保存；取消读后没有当前值不被误标为已知版本变化。
- 真实路由在最终 beforeResolve 再核对快照；上下文守卫也注册快照，以免后续守卫修改输入后仍按旧批准离开。卸载、身份变化使旧确认失效，且旧 finally 不解锁新弹窗。
- 资产页在子组件批准返回后再次检查目标、父子输入、账号权限、后发选择序号和扩展资料未知保存。一个较旧的跨资产确认不能覆盖随后重新打开的原资产。

## 验证

新增 16 项编辑器/内存路由测试与 9 项真实父子组件测试。原编辑器上 16 项均失败，修复后通过。父子集成包括“另一个扩展资料编辑器在确认期间进入未知保存”，最后一刻仍应拒绝替换维保目标。

实际 Vue/Element Plus 与内存路由测试不等于浏览器验收：确认返回值和 drawer 外壳受测试控制，真实弹窗焦点陷阱、屏幕阅读器、四视口截图与 Chromium/axe 仍 NOT_RUN。静态 Vite HTTP 冒烟与全量测试、类型/构建结果在 `evidence/warranty-draft-protection-20261022/` 分层留证。

## 范围外

未改业务日期/维保核验规则、后端、SQL、真实账号或供应商。资产依赖编辑的读取恢复和完整草稿保护仍需继续补齐。正式合同 128 项 TC 仍 NOT_RUN，不以单元测试计数替代完成率。
