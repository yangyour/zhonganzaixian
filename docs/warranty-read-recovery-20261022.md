# 维保资料原读取恢复（2026-10-22）

## 范围与可用性标准

沿用 `frontend-acceptance-standard.md` 的 WCAG 2.2 AA、键盘/焦点、状态可感知及可恢复错误要求。接入既有资产详情维保面板，不新增空菜单，不宣称供应商或维保覆盖已核验。真实浏览器、屏幕阅读器与完整弹窗验收仍独立 NOT_RUN。

- GET 可取消，错误/取消后可重试原资产与原历史 `before_version`。当前档案版本前进时也不静默改为第一页；刷新首页必须明确操作。
- 读取未完成不显示为“未登记”。取消与失败清掉当前展示，但保留最高已见版本、未保存输入及未知 PATCH 的原命令。
- 单独 GET 恢复不重发 PATCH；保存准备错误不提供虚假的 GET 重试。隐藏面板仍取消读，不取消正在保存的原请求；重新打开后可恢复。
- 使用公共 44px 恢复按钮、状态播报、可聚焦错误组和当前/历史标题。异步完成仅在焦点未被用户主动移走时转移焦点。
- 账号版本、权限、角色、模式、租户或资产变化同步清理旧范围数据。通知回调和幂等键回调后再次检查归属，旧请求不能向新范围派发。
- 提交输入在调用幂等键回调之前冻结；合法旧回执与新当前档案分开保留。保存完成只清与原提交仍相同的输入，不抹掉后来填写的内容。
- 最高已见资产/资料版本与创建时间、已登记维保补充字段不允许回退或清空；相同版本仍检查事实一致性。销毁后不能通过 reset 复活。

## 验证与证据边界

新增 16 项读取器测试及 8 项实际 Vue/Element Plus DOM 测试。DOM 中 drawer 外壳受控，不能作为真实浏览器/模态焦点验收。原实现首次有效运行 13 失败、3 通过；随后加强 3 个版本保护断言，要求异常当前值在历史请求前拒绝。公共 fixtures 提取时误把函数内局部 const 标为 export，修复后才开始有效前后对比；组件立即 watch 调用未初始化的 const load 被测试发现并改为函数声明。

分层结果、源码哈希及实际 Vite HTTP 检查见 `evidence/warranty-read-recovery-20261022/`。HTTP 只证明静态入口/模块可服务，不证明浏览器执行或后端业务联调。
