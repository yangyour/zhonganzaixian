# 工单编辑、回执与读取恢复

基线main：bad1bb462ab737719686ae86ebf70f307d8b8788。仍使用既有六态工作流API0.73.0，不修改Java业务或V1–V45迁移。

## 编辑与读取

- 操作说明、显式档位/优先级、转派人/原因/协办选择接入脏数据判断。离开页面、切换工单、主动切租户/退出需确认；取消保留输入，过期确认不能丢弃新范围内容。关闭浏览器有beforeunload提示。
- 刷新状态保留未提交输入，同时重新读取历史和候选人；接单/开始处理本身不提交说明，因此不会顺手清空未发送的说明。其他已确认提交仅在原上下文仍有效时清理此次实际发送的字段；未发送字段继续保留，并有明确确认的“清空未提交输入”入口。
- 尚未确认的操作阻止自愿离开，保留原请求重试；强制权限失效仍立即清除受保护数据。
- 租户、操作者、角色、模式、权限/账号版本、读写能力和切换状态变化均清理旧列表、详情、候选、历史及编辑内容。列表/历史/候选/详情/命令分别可中止，迟到回调不污染新范围。
- 失败列表不再显示“没有记录”。错误重试保留原分页与已应用筛选；输入但尚未查询的筛选不会混入旧游标，第一页/下一页也不悄悄应用草稿筛选。
- 历史核对UTC、版本倒序、重复ID、分页边界、动作/状态及客户字段隐藏；候选人员可重试，转派不能提交仍在读取、未出现在最新候选中或等于原负责人的对象。服务端超过100候选人的既有服务队列门禁不放宽。

## 原命令回执与当前状态分开

- 回执必须属于原工单/租户、原expected_version+1及原操作对应状态；另核对显式激活档位/优先级、接单人、转派目标、解决说明、客户关单方式。
- 回执不符保持结果不确定，不能假装成功或生成新请求重试。
- 网络丢失后严格重用原POST正文和Idempotency-Key。重试期间遇到403等拒绝，不能据此断言原操作从未生效，继续保留不确定性。
- 提交回执已确认而独立GET失败时，保留确认版本并明确提示“不要重复提交”；只重读GET恢复当前状态。GET早于已确认回执版本则拒绝展示；比回执更晚的当前状态允许显示。
- 等待回读期间发生上下文切换，不向新页面返回旧操作“成功”。dispose后不能复活工作区。
- 共享读取器改为严格日历UTC、规范UUID及hash长度，不接受Date.parse归一化的无效日期。

## 验证与限制

最终独立临时PG/API执行46项HTTP检查。七种合成操作accept/start/resolve/close/reopen/reassign/cancel均验证原回执、同key重放及独立GET；最后只有OPEN加七次转换共8条历史，没有重放生成的重复流转。验证无关客户不能读取/确认目标、客户不能执行内部操作及陈旧版本拒绝；客户历史内部actor/details均隐藏。7份真实命令响应回放经过生产writer，2份真实历史经过实际页面DOM读取。
