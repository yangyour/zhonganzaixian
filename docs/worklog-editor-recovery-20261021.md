# 工单内本人工时编辑面板读取恢复

基线 main c0a3ddcca1e680ab096090f3b758cf9fe5abee7f。此处为工单抽屉中的工时新增/修改及历史面板，不是只读“本人工时”独立列表。遵循[统一前端验收标准](frontend-acceptance-standard.md)，不扩大团队工时访问权限。

## 原目标读取与编辑保护

- 列表失败或取消保留原时间/ID双游标，原页重试重新核对父工单和本人记录。详情/历史是独立的两阶段GET，保留原记录及历史版本边界。
- 详情必须匹配已知记录的创建时间、版本和更新时间；同版本所有事实一致，不因历史失败允许详情退回旧版本。新版本出现时重启最新历史并明确提示，旧历史页游标不混用。
- 在第二阶段历史请求前固定已核验的新版本，即使历史失败，后续原读取重试仍以它为最低版本。取消详情第一阶段后不会继续派发历史GET。
- 取消只针对读取，保留类型、起止时间、原始备注、编辑ID/版本和未知保存命令。恢复GET不重发POST/PATCH，不确认未知写入，也不取消后台提交。
- 共享恢复控件具名按钮和状态；取消后状态可聚焦。列表失败或取消不再一直表示正在加载，当前页无数据与未成功读取明确区分。
- 开始编辑前回读、保存后的回读和原请求恢复结束均复核原输入快照，不覆盖后来同范围输入；上下文变化仍清除私有内容与旧恢复目标。
- 状态通知/随机key回调后重查epoch，捕获路径使用原范围；已销毁工作区不能reset重开。key生成失败明确“没有发送”，不伪装未知保存。

工时仍为人工实填区间，不据此证明实际作业已发生。原跨日时段不自动拆分；默认分钟、费用、毛利及计费参数仍为null/CONFIG_PENDING，不添加生产默认值。
